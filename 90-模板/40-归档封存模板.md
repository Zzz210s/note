# 40-归档 归档封存模板

> **属于哪层:** `40-归档\` 归档层——**完结/过时内容沉底,只进不出**。
> **作用:** 完成的项目、过时的知识,从这里退休。即使以后不用也不轻易删,留作历史。
> **要点:** 项目层(10-项目)是"活的"、会随进度改动;一旦做完,整个文件夹移入 40-归档——这是给"一件事"画句号的地方。

## 搬之前:四条归档判据(与巡检 A12 逐条对应)

逐条核对 `10-项目/<项目>/!项目说明.md`,**四条同时成立**才搬:

| # | 判据(A12 第几条) | 在 `!项目说明.md` 里查什么 |
|---|------------------|---------------------------|
| 1 | 项目已完结(A12①) | frontmatter 里 `status: done` |
| 2 | 收尾无遗留(A12②) | 「出口」或「验收」小节里没有未勾选项(`- [ ]`) |
| 3 | 做过复盘(A12③) | 正文含「复盘」小节 |
| 4 | 清单已清(A12④) | 「任务清单」小节里没有未勾选项 |

- **位置只是状态的镜像,判据永远看 `status` 与勾选**:判据不读文件夹路径。不许为了"整理得干净"而提前搬家
- 缺小节按"不满足"处理:没有「出口/验收」或「任务清单」小节就无从验证收尾,巡检器不出提示(误报比漏报贵)
- 四条全满足时,巡检器在独立的 `[提示]` 小节打印 `可归档:<项目名>`,**不计入 FAIL**;搬不搬由人决定

## 怎么搬

```bash
git mv "10-项目/<项目>" "40-归档/<项目>"     # 用 git mv,保住历史
```

- 归档后**仍要在根 `00-索引.md` 留一行登记**:「计划与进度」里该项目那行勾成 `- [x]`,「项目清单」表里状态列改成 `归档`。**不要整行删掉**——A12 反向检查的硬错误就是"归档项目未在根 `00-索引.md` 登记",索引里消失的归档物等于找不回来的死文件
- 项目内的 `20-知识/` 随整包一起进档,继续当参考;封存说明写在归档文件夹根(如 `40-归档/<项目>/封存说明.md`):它是库内笔记,记得带 frontmatter(`type: note` / `status: done`),否则巡检 A6 报缺元数据

## 封存信息

- **原名:** 搬之前所在的 `10-项目/<项目>` 路径
- **起止:** 开始 → 结束日期
- **为什么封存:** 完成 / 已过时 / 被替代
- **结论:** 最后一句可带走的话

- [x] 正文含「复盘」小节
- [x] 「任务清单」小节无未勾选项

## ▼ 填充后长这样(示例:Markdown 学习结项归档)

> 项目学完,`10-项目/2026-10-掌握Markdown\` 整体移入 `40-归档\2026-10-掌握Markdown\`,并在文件夹内放一份封存说明。

```markdown
# 封存说明:2026-10-掌握Markdown

- **原名:** 10-项目/2026-10-掌握Markdown
- **起止:** 2026-10-01 → 2026-11-20
- **为什么封存:** 核心语法已掌握,能独立写文档与 README,目标达成
- **结论:** Markdown 几小时可上手;真正的坑在 GFM 扩展语法跨平台兼容
```
