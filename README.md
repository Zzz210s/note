# 0-Note · 程序员知识库总纲

> 一套纯 Markdown、工具无关、AI 友好的程序员知识管理体系。
> 整合 PARA(行动分类)+ Zettelkasten(原子写作)+ MOC(索引地图)+ Johnny.Decimal(编号定位)+ Karpathy 分层(素材/成品分离)。
> 本文件是体系的**唯一规则源**:人和 AI 都按此规则使用本库。

## 一、目录体系(编号即优先级)

```
0-Note\
├── 00-MOC\         索引层   每个专题一张"地图",笔记的入口(不放内容,只放链接)
├── 10-Projects\    项目层   有明确目标和截止的学习(如"14天刷完Hot100")
├── 20-Areas\       领域层   长期维护的知识田(01-算法/02-编程语言/03-开发工具/04-系统与部署/05-网络与服务器/06-Web/07-外语)
├── 30-Resources\   资源层   收集的资料/工具/脚本/图片,暂不体系化
├── 40-Archive\     归档层   完成的项目、过时的知识(只进不出)
├── 90-Templates\   模板层   统一笔记骨架(算法/项目/系统/语言)
└── README.md       本文件(总纲)
```

配套仓外目录(二进制素材,不进 git):
- `F:\0-Note-Data\` — Anki 牌组、xlsx/csv、处理脚本等原始素材,按 English/Español 等同名对应

### 00~90 到底什么意思(编号即优先级,也是知识生命周期)

> 目录名里的**数字前缀**两层含义:①大数字 = 越接近仓库边缘(数字小=越核心、越常动);②每层代表知识在其生命周期中的一个**阶段**。**同一个主题的笔记,会随它在生命周期里的位置变化,在不同层之间移动。** 下面用本仓库里真实存在的文件举例,这样你对号入座:

| 目录 | 含义 | 放什么 | 仓库里的**真实例子** |
|------|------|--------|--------------------|
| **00-MOC** | 索引层 · 每个专题一张"地图" | 只放链接和路线,不放正文(正文在 20-Areas) | `00-MOC/算法.md` 里一行 `- [[冒泡算法]] — 交换排序入门 \| ⭐ \| done` 就是指向正文的"入口" |
| **10-Projects** | 项目层 · 有目标+截止的学习/刷题项目 | 项目文件夹(目标、截止日期、任务清单) | 当前为空;计划如 `10-Projects/Hot100-2026Q4\`(14天刷完 Hot100) |
| **20-Areas** | 领域层 · 长期维护的知识田 | **笔记的成品正文**(正文唯一存放处) | `20-Areas/01-算法/冒泡算法.md` 整篇笔记 |
| **30-Resources** | 资源层 · 暂存的原始资料 | 没提炼的资料、图片、脚本工具,暂不体系化 | `30-Resources/image/`、`30-Resources/tools/` |
| **40-Archive** | 归档层 · 完结/过时沉底 | 完成的项目、过时知识(只进不出) | 当前为空;例:学完的 `10-Projects\` 文件夹整体移入 |
| **90-Templates** | 模板层 · 统一笔记骨架 | 写新笔记时复制的模板(不改动) | `90-Templates/20-笔记正文模板.md`(冒泡算法笔记就是从它复制改写的) |

**一句话记忆**:`00 指路 → 10 立项 → 20 沉淀正文 → 30 暂存原料 → 40 封存 → 90 给格式`。

**为什么 30 在 20 后面?** 30-Resources 是"还没提炼的原料",20-Areas 是"提炼后的成品"——原料在仓库边缘(30),提炼成知识后向核心(20)**前进**,符合 PAR 的流动方向,和数字大小不冲突(30 编号大只在命名上,不代表优先级高,代表"还没消化/偏边缘")。

## 二、五条核心规则

### 1. 流动规则(PARA 灵魂)
信息有生命周期,按方向流动,**禁止只存不动**:

```
新信息 → 30-Resources(暂存) ──提炼──→ 20-Areas(沉淀为知识)
                │                          │
                └→ 10-Projects(要用时升级) ─┘→ 40-Archive(完结/过时沉底)
```

- 新收集的资料先扔 `30-Resources`,**不要直接塞 Areas**
- 要系统学一个东西 → 在 `10-Projects` 建项目文件夹(含目标+截止+任务清单)
- **10-Projects 文件夹命名 = 阶段优先 + 时间粒度**:`{阶段}-{名称}-{时间}`(如 `02-掌握握手协议-2026Q4`)。阶段即学习顺序:`00-每日一练` 置顶(常驻)→ `01-入门`(月粒度,如 2026-10)→ `02-基础`(季度,2026Q4)→ `03-部署`(季度)→ `04-进阶`(年粒度,2027)。时间粒度随难度:低=月、中=季度、高=年;序号越大越后学、难度越高
- 学完提炼出的知识 → 写进 `20-Areas`;项目完结整个文件夹移入 `40-Archive`
- **每季度巡检一次**:Resources 里超过 3 个月没动的,要么提炼进 Areas 要么删

### 2. 写作规则(Zettelkasten 轻量版)
- 一篇笔记只讲一个主题(原子性)
- **必须用自己的话重写**——直接复制粘贴的资料没有价值,那是收藏不是学习
- 代码可以贴,但必须带"为什么这么写"的注释或说明
- 笔记之间用 `[[双链]]` 互连(如 `相关: [[冒泡算法]]`),Obsidian 里可点击,VS Code 里是纯文本不碍事

### 3. 检索规则(MOC)
- **不靠文件夹深挖找东西,靠 MOC 地图**
- 每个专题一张 MOC(如 `00-MOC\算法.md`):列出该专题所有笔记 + 推荐学习顺序 + 待补坑
- 笔记写完,记得在对应 MOC 里加一行链接

### 4. 元数据规则(frontmatter)
每篇笔记头部带 YAML 元数据,**不超过 8 个字段**:

```yaml
---
type: algorithm    # algorithm | project | system | language | tutorial
tags: [排序, 数组]
status: learning   # todo | learning | done | review
date: 2026-08-26
difficulty: 2      # 1-5 自评(算法类用)
source: 力扣912
related: "[[冒泡算法]]"
review: 2026-09-26  # 下次复习日期(可选)
---
```

### 5. 分层规则(Karpathy)
- 本库(0-Note)只放**文本成品**:md 笔记
- 二进制素材(Anki/xlsx/图片大文件/脚本/docx/pdf)放仓外 `0-Note-Data\` 或 `30-Resources\` 各素材子目录:`image\`(图片)、`tools\`(脚本)、`English\`/`Español\`(外语配套附件,与 20-Areas 同名对应)
- 知识"编译"一次:Raw 素材 → 提炼 → Areas 成品,之后持续更新成品而非重读素材

## 三、笔记怎么写(四类骨架)

写新笔记时,从 `90-Templates\` 复制对应骨架:

| 场景 | 模板 | 核心段落 |
|------|------|---------|
| 学/刷一道算法题 | `20-笔记正文模板.md` | 题意→直觉与试错→核心思路→代码→复杂度→同类题→复习记录 |
| 学一个开源项目/做项目 | `20-笔记正文模板.md` | 解决什么→架构→跑起来→核心机制→**决策与权衡**→我能复用什么→复盘 |
| 学一个系统/中间件 | `20-笔记正文模板.md` | 一句话本质→解决什么→核心概念→架构→**权衡取舍**→瓶颈→面试问法 |
| 学一门语言/技术 | `20-笔记正文模板.md` | 定位→环境速查→核心心智模型→语法差异表→坑与最佳实践→实战片段 |

> 想理解 **00~90 每层的模板 + 一个项目如何走完完整生命周期** → 看 [`90-Templates/90-模板总览与生命周期.md`](<90-Templates/90-模板总览与生命周期.md>),各层模板都放在 `90-Templates\`(00-MOC模板 / 10-项目立项模板 / 20-笔记正文模板 / 30-资源暂存模板 / 40-归档封存模板),每个都带一个「学习 Markdown(基于菜鸟教程)」的填充示例。

## 四、命名规范

- 笔记文件:`主题名.md`(中文可,简短可检索,如 `冒泡算法.md`、`docker.md`)
- 项目文件夹:`目标-截止日期`(如 `Hot100-2026Q4\`)
- MOC 文件:`专题名.md`(如 `算法.md`、`系统.md`、`外语.md`、`编程语言.md` 等)
- 语言类拆两个 MOC:自然(人类)语言(英语/西语)归 `外语.md`;**编程/标记语言**(Python/Markdown…)归 `编程语言.md`
- 不用日期前缀命名知识笔记(检索靠 MOC 和 tags,不靠时间)

## 五、AI 协作规则(给 AI 助手看)

- 本库结构见本文件;新笔记按 `90-Templates` 骨架生成,带 frontmatter
- 帮我写笔记时:提炼进 `20-Areas` 对应分类;素材性内容进 `30-Resources`
- 每次大改动后更新相关 MOC 的链接列表
- 遵守流动规则:不要把资料原样堆进 Areas

## 六、一个完整实例:一篇笔记如何在系统里流动

> 以本仓库已有的 **《冒泡算法》**(`20-Areas/01-算法/冒泡算法.md`)为线索,看它怎么生、怎么被索引、怎么用、最后怎么封存。**左边 0x 目录 = 它当前所处的阶段,右边路径 = 它实际存在的位置。**

### 第 0 步:你有个灵感 / 收集到一份原料 → 30-Resources

- 你看到一段 C 语言冒泡代码、一份别人写的题解 PDF、或一个排序动画 → 这是**原始素材**,先扔 `30-Resources/`(可加 `image/` 存图、`tools/` 存脚本)。
- 这一步只"收藏",**不整理内容**——收藏不等于学习,后面必须提炼。

### 第 1 步:决定真正学它 → 拿模板建正文,写进 20-Areas

- 从 `90-Templates/20-笔记正文模板.md` **复制一份,改名**为 `20-Areas/01-算法/冒泡算法.md`(模板本身在 90 层,永远不改,只复制)。
- 按模板骨架填:**题意(用自己的话)→ 直觉与试错 → 核心思路 → 代码 → 复杂度 → 同类题**。
- 头部写 frontmatter(≤8 字段)。本仓库里这份的真实 frontmatter 长这样:
  ```yaml
  ---
  type: algorithm
  tags: [排序, 数组, 交换排序]
  status: done
  date: 2026-08-26
  difficulty: 1
  source: 经典入门
  related: "[[快速排序]]"
  review: 2026-09-26
  ---
  ```
- 正文只放**成品**:用自己的话重写 + 带"为什么这么写"的注释。写完,原来的原始素材(第 0 步那份)要么删、要么扔回 30-Resources/Archive。

### 第 2 步:在 00-MOC 登记入口(否则这篇笔记"不可见")

- 打开 `00-MOC/算法.md`,在"笔记索引"下加一行链接:`- [[冒泡算法]] — 交换排序入门 | ⭐ | done`。
- **规则:正文放 20-Areas,MOC 只放一行链接。** 以后你想找所有排序题,不用翻文件夹,直接看 `00-MOC/算法.md` 这张地图。

### 第 3 步:要系统学(带目标+截止)→ 建 10-Projects 立项

- 如果这不是零散记一笔,而是"我要开始系统刷算法" → 建 `10-Projects/Hot100-2026Q4/`,里面写:目标(刷完 Hot100)、截止日期、任务清单。
- 清单里把《冒泡算法》作为第一题,**在笔记里用 `related: [[..]]` 双向链接**、在项目文件夹里链接回这篇笔记。这样"项目层"和"领域层"互相钩住。

### 第 4 步:学完/项目完结 → 移入 40-Archive 封存

- 一个项目刷完、目录过时 → 整个 `10-Projects/Hot100-2026Q4/` 移入 `40-Archive/`。**只进不出**,即使以后不用也不轻易删,留作历史。
- 如果只是单篇知识过时(比如某个库被淘汰),把对应笔记移到 `40-Archive/`,并在 MOC 里把它标成过时或去掉链接。

### 全程回顾(一眼看懂数字的含义)

```
灵感/素材 → 30-Resources(暂存)────┐
                                  ├─→ 20-Areas(沉淀成品) ──→ 40-Archive(封存)
模板 90-Templates ◄─复制─ 写正文 ──┤      ▲                      │
                                  └─→ 00-MOC(索引入口)          └← 学完移动
```

`00` 索引、`10` 立项、`20` 正文、`30` 原料、`40` 封存、`90` 模板——**同一份知识,随着它"越学越透",在 30→20→40 之间前进/沉底;00 永远指着它在哪,90 永远教你写**。
