Docker(容器化):课程地图

这是全局路线,不是课本身。每节课的实际难度、例子与测验,会按你上一节的真实表现校准(最近发展区原则)—— 所以顺序可能微调,但"下一步学什么"永远有答案。想跳课、换顺序、加课,直接说。

为什么这么排

先建立镜像/容器/仓库的概念骨架,再用命令行把容器跑起来,然后才写 Dockerfile —— 不先跑起来,Dockerfile 的每条指令都是抽象的。

课程序列

课号标题这节的胜利(可验证)前置状态
0001镜像、容器、仓库:三者的关系用自己的话说清三者关系,并说出容器 = 镜像 + 一层可写层无已出课
0002核心操作:run / ps / exec / logs / rm起一个容器、进去执行命令、看日志、删掉它,全程不查笔记0001待开
0003第一个容器:端口与卷用 -p 让宿主机访问容器内服务,用 -v 让容器读到宿主机文件0002待开
0004写第一个 Dockerfile用 FROM/RUN/COPY/CMD 写出最小镜像并跑起来,说清每条指令做了什么0003待开
0005镜像分层与体积优化讲清缓存为什么失效,并把镜像体积压下来一截0004待开
0006Compose:多容器编排用 compose 起 web + db 两个服务,并用一条命令拉起/停止0005待开
0007多阶段构建与 Buildx用多阶段构建把构建工具留在中间层,产出更小的运行镜像0006待开
0008实战:部署一个完整小项目把项目(与 Nginx 项目联动)在服务器上跑起来,并能排掉端口/卷/网络三类故障0007待开
