# Mission: VS Code(编辑器工作流)

> `teach` 教学工作区协议文件,与 [项目说明](<./!项目说明.md>) 配套(项目说明管任务与进度,本文件管「为什么学」)。
> 教学决策(下节教什么、给哪些资源、设计什么练习)都回到这份文件上。

## Why

这是每天用最久的工具,配置与快捷键的每一点改进都会复利到所有其他项目上 —— 写笔记、写代码、提 PR 都在里面完成。

## Success looks like

- 搭出一套个人工作区配置(`settings.json` + 常用插件),可随机器迁移
- 能用快捷键完成一次完整编辑流程:多光标改一批、跨文件跳转、重构改名、任务运行、Git 面板提交
- 能解释「为什么 VS Code 这么快」:扩展宿主进程、语言服务器(LSP)与编辑器内核的关系

## Constraints

- 窗口 —— → 2026-12-31;当前状态:未开始
- 以本机真实工作流为练习对象(写 0-Note 笔记、跑 Python 脚本、提交 Git)

## Out of scope

- 不学 VS Code 扩展开发(写插件) —— 那是另一个量级
- 不做 Vim/Neovim 对比与迁移(现有肌肉记忆保留)
