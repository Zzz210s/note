# 本地构建 Zephyr 文档(WSL2)

目标:不依赖 CI、不需要双系统,在本机验证文档改动能不能过 **与 CI 相同的 Sphinx 调用**(`-W --keep-going`,警告即错误)。

## 一、环境(2026-09-22 实测)

| 项 | 值 |
|----|-----|
| 发行版 | WSL2 里的 **Ubuntu 26.04.1 LTS**(`wsl.exe --install Ubuntu-26.04 --no-launch` 装的) |
| 内核 | `6.6.87.2-microsoft-standard-WSL2`(微软内核,**不能做内核模块实验**——内核线用不了它) |
| 资源 | 20 vCPU / 7.8 GB 内存(默认配置) |
| 工具 | Python 3.14.4、cmake 4.2.3、ninja 1.13.2、doxygen 1.15.0、git 2.53.0 |
| 代码位置 | `/root/zephyr`(WSL 内部盘,不要放 `/mnt/f`,跨盘会慢一个量级) |

**决定**:用现有 WSL2,**不装双系统**(2026-09-22 用户定)。

## 二、一次性安装步骤

```bash
# root 身份即可,不需要 sudo
wsl.exe -d Ubuntu-26.04 -u root
export DEBIAN_FRONTEND=noninteractive
apt-get update -qq
apt-get install -y -qq --no-install-recommends \
  python3-venv python3-pip python3-dev git cmake ninja-build doxygen graphviz \
  wget curl build-essential

git clone --depth 1 https://github.com/zephyrproject-rtos/zephyr.git /root/zephyr
cd /root/zephyr
python3 -m venv .venv && . .venv/bin/activate

# 关键:两个 requirements 都要装(CI 的 doc-build.yml 就是这两条)
pip install -r doc/requirements.txt --require-hashes
pip install -r scripts/requirements-actions.txt --require-hashes

# 关键:文档扩展要用 west 找工作区,必须在仓库里初始化一个本地工作区(不需要联网)
west init -l .
```

## 三、构建

```bash
cd /root/zephyr && . .venv/bin/activate && export ZEPHYR_BASE=/root/zephyr
cd doc
make html-minimal          # 轻量预览:跳过 doxygen / kconfig / 外部内容
# 产物:doc/_build/html/develop/west/workspaces.html
```

`make html-minimal` = `make html-fast` + 三个 `SKIP_*` 开关;这些开关与用法在
`doc/contribute/documentation/generation.rst` 里有正式文档(约 269-291 行),不是野路子。

## 四、实测结果

| 构建 | 结果 |
|------|------|
| 原始 upstream 树(基线) | 840/840 文档,1m15s,**2 条 warning** |
| 含我的改动(全新构建) | 840/840 文档,**8m07s**,**仍是同样 2 条 warning** |
| 含我的改动(增量) | 5/840 文档,18.6s,0 warning,产物 HTML 里能看到我加的那一节 |

两条 warning 与本改动无关,都是 release notes 里的既有问题:

```text
doc/_build/src/releases/migration-guide-4.5.rst:11: WARNING: Duplicate explicit target name: "here". [docutils]
doc/_build/src/releases/release-notes-4.5.rst:30: WARNING: Duplicate explicit target name: "here". [docutils]
```

**小结**:`doc/develop/west/` 下零 warning;我的改动在 `-W`(警告即错误)下有干净结果。那 2 条 release notes 的既有 warning 可以做一个小补丁修掉(另开 PR)。

## 五、踩坑记录

1. **只装 `doc/requirements.txt` 不够**:`jsonschema`(来自 `scripts/requirements-base.txt`)与 `tabulate`(来自 `scripts/requirements-actions.txt`)缺失,Sphinx 会在加载 `zephyr.kconfig` / `zephyr.gh_utils` 扩展时报 `Could not import extension`。CI 的 `doc-build.yml` 装的是**两份** requirements,照抄即可。
2. **必须 `west init -l .`**:否则 `zephyr.*` 扩展调用 `west.util.west_topdir()` 抛 `WestNotFound: Could not find a west workspace in this or any parent directory`。
3. **configure 前必须激活 venv**:若在没激活 venv 时 `make`(或删了 `_build` 后重跑),cmake 会报 `The 'sphinx-build' command was not found; Sphinx-based targets will not be available`,随后 `ninja: error: unknown target 'html'` —— 看着像 ninja 的问题,其实是没激活虚拟环境。
4. **`pip install` 要检查退出码**:`| tail -5` 会把失败吞掉(本机遇到过一次 pypi 读取超时),导致"看起来装好了其实缺包"。用 `> log 2>&1; echo $?` 的形式留退出码。
