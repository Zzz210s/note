# tmux

> 「SSH 断一下,跑了一小时的任务就没了」——终端复用器就是为这句话而生的。
> 它把「程序在哪儿跑」和「你从哪儿看它」拆成两件事,于是断线只等于摘下耳机,不等于关掉后台。
> tmux 是这一族里最常用的实现,它同时管三层东西:**会话 / 窗口 / 面板**。
> **本文的固定写法**:每个概念按「**为解决什么痛点而生 / 一句话定义 / 大白话注解**」三段给出,再展开细节。

## 一句话速览

| 名称 | 一句话定义 | 大白话注解 |
| --- | --- | --- |
| **终端复用器(terminal multiplexer)** | 在一个终端连接里托管多个程序,并让这套托管**独立于连接本身**存在 | 一间不随你走人的值班室 |
| **服务端(server)** | 复用器在后台常驻的那个进程,所有会话都寄生在它身上 | 值班室本身:人走灯不灭 |
| **会话(session)** | 一组窗口的容器,由服务端持有、可被反复接回 | 一张工作台 |
| **窗口(window)** | 一个占满整屏的虚拟终端,可在会话里来回切 | 浏览器里的一个标签页 |
| **面板(pane)** | 窗口内再切出的一块区域,各自跑各自的程序 | 同一屏里并排的几个格子 |
| **分离 / 接回(detach / attach)** | 人从会话上摘下 / 再挂回去;**摘下时里面的程序继续跑** | 出门不关机,回来接着坐 |

**一句话判定**:问「**我把这个终端窗口关掉,里面的程序还活不活**」——
还活着,背后就有一个终端复用器在托管它;跟着一起死,那程序就只是这个终端的孩子
([Wikipedia: Terminal multiplexer](https://en.wikipedia.org/wiki/Terminal_multiplexer))。

## 一、它到底解决了什么

### 关掉终端,程序就跟着死

> **为解决什么痛点而生**:在没有复用器的年代,一个程序跑在"某个终端的控制之下"。
> 那个终端(或它背后的连接)一断,内核就向它的前台进程组投递 `SIGHUP` —— 这个名字原意就是
> "挂断",历史上用来通知程序"电话线断了"
> ([Wikipedia: SIGHUP](https://en.wikipedia.org/wiki/SIGHUP))。于是关窗口 = 杀任务。
> **一句话定义**:在终端里启动的程序,是那个终端的**子进程**,它的标准输入输出
> 接在一对伪终端(pty)上;pty 的另一头由终端程序(或 SSH 服务端)持有
> ([Wikipedia: Pseudoterminal](https://en.wikipedia.org/wiki/Pseudoterminal))。
> **大白话注解**:程序不是"自己在跑",它一直抓着一根电话线;线被剪断,它就收到"挂断"信号。

### 把「跑」和「看」拆开

> **为解决什么痛点而生**:换个视角看这件事 —— 程序需要的其实只是一台**永远不挂断的终端**,
> 谁来看它、从几个窗口看它,都是另一回事。
> **一句话定义**:终端复用器先起一个**常驻服务端**,由它持有若干"虚拟终端";
> 你那个真实的终端窗口只是**连上去的客户端**,连得上就看得见、断了也无所谓
> ([man tmux](https://man7.org/linux/man-pages/man1/tmux.1.html))。
> **大白话注解**:以前是"你打电话给程序";现在是"程序在值班室里接电话,你只是换了一部手机打进去"。

### 三层结构:会话 / 窗口 / 面板

| 层 | 是什么 | 典型动作 | 类比 |
| --- | --- | --- | --- |
| **会话(session)** | 一组窗口的容器,服务端持有 | 新建、接回、整体关掉 | 一间值班室 |
| **窗口(window)** | 占满整屏的虚拟终端 | 新建、切换、重命名 | 值班室里的一张桌子 |
| **面板(pane)** | 窗口内切出的一块区域 | 横竖切分、在格子间跳 | 桌上摊开的几份文件 |

三层是**包含关系**:一个服务端里可以有多个会话,一个会话里可以有多个窗口,一个窗口里可以有多个面板。
所以"我在 tmux 里"这句话通常要再说清是在哪个会话的哪个窗口。

## 二、对比表:五个容易混的名词

| 名字 | 一句话判定 | 什么时候它不适用 |
| --- | --- | --- |
| **终端复用器(tmux)** | 托管**多个**程序,并让它们**脱离终端连接**活着;还能重新接回去看 | 它管不了重启:机器一重启,所有会话都没了 |
| **Shell(bash / zsh)** | 你**敲命令的那个解释器**;它本身只是会话里跑的一个程序 | 它不是窗口程序,也没有"脱离连接"这回事 |
| **终端模拟器** | **画字的那层窗口程序**(xterm、GNOME Terminal、Windows Terminal 都是) | 它只管显示与键盘;里面的程序照样跟着它一起死 |
| **`nohup`** | 只让**单个**命令**忽略挂断信号**,输出重定向进文件 | 没有窗口、没有会话,断线后**看不到也回不去** |
| **GNU screen** | 同族的更早实现,一样能分离与接回 | 功能与配置方式都比 tmux 旧,新项目多不再选它 |

一句话分工:**终端模拟器管"画",Shell 管"解释",复用器管"活得比连接久"**。
`nohup` 是这条路线上最小的一步:它只解决"别被信号杀掉",不解决"我还能回去看它"
([man nohup](https://man7.org/linux/man-pages/man1/nohup.1.html))。

## 三、核心动作:分离与接回

| 想做的事 | 概念上的说法 | 通用做法(以 tmux 为例) |
| --- | --- | --- |
| 起一个新会话并给它起名 | 创建会话 | `tmux new -s 名字` |
| 让它在后台先跑着,人先不进去 | 创建时即分离 | `tmux new -d -s 名字` |
| 看看有哪些会话还在 | 列出会话 | `tmux ls` |
| 人先离开,程序继续跑 | **分离(detach)** | 前缀键(默认 `Ctrl-b`)再按 `d` |
| 回来接着看 | **接回(attach)** | `tmux attach -t 名字` |
| 一个窗口里并排干两件事 | 切面板 | 前缀键 + `%`(竖切)/ `"`(横切) |

要点只有一条:**分离时,里面的进程一点没受影响** —— 它拿着的那个虚拟终端还在服务端手里。
这也是为什么"先 `tmux` 再跑长任务"几乎成了服务器上的肌肉记忆。
配置与键位可以写在用户自己的配置文件里(默认 `~/.tmux.conf`);不改配置也能用默认前缀键,
([Arch Wiki: tmux](https://wiki.archlinux.org/title/Tmux))。

## 四、常见误解

| 说法 | 问题在哪 | 更准的说法 |
| --- | --- | --- |
| 「tmux 是一个终端模拟器」 | 它是**跑在**终端模拟器里的程序,不画字 | 终端模拟器负责窗口与渲染,tmux 负责托管 |
| 「在 tmux 里跑就不会因为断线死掉」 | 会话活在**服务端进程**里,服务端自己死了会话就没了 | 它防的是"连接断",不防"进程崩" |
| 「用了 tmux 就不怕重启」 | 服务端与普通进程一样会随重启消失 | 跨重启要另找方案(把服务交给系统服务管理器,或靠插件做快照) |
| 「tmux 就是 `nohup` 的升级版」 | 两者解决的问题不同:一个防信号,一个给一层可回看的窗口 | 要能回去看、能分层,才需要复用器 |
| 「只有服务器才需要它」 | 本地开一堆终端窗口同样会乱 | 本地用它做"一个窗口里管三件事"也很常见 |

## 五、和相邻术语的关系

| 术语 | 一句话定义 | 与 tmux 的关系 |
| --- | --- | --- |
| **pty(伪终端)** | 内核提供的一对"虚拟串口" | 复用器给每个面板都配一对,程序以为自己对着一个真终端 |
| **SSH 会话** | 一次远程登录连接 | 断线就是这条连接没了;tmux 让程序不必跟着它死 |
| **进程组 / 会话(内核语义)** | 内核里用于投递信号与分配终端的组织单位 | 与 tmux 的"会话"同名但不同物,别混([Wikipedia: Process group](https://en.wikipedia.org/wiki/Process_group)) |
| **系统服务(systemd 单元)** | 由 init 拉起并守护的常驻进程 | 要"开机就在、崩了自起",交给它而不是 tmux |
| **终端模拟器** | 画字、收键盘的窗口程序 | tmux 的宿主:它死了,tmux 客户端也就断了 |

**一句话总结**:终端模拟器解决「**在哪儿看**」,Shell 解决「**怎么解释**」,
tmux 解决「**让它活得比你这次连接久,而且随时能回去看**」。
