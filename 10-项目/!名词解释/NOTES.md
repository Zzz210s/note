# NOTES

> 教学偏好与工作笔记。设计课程前先读这份文件。

## 教学偏好(全局,用户已确认)

- **语言与格式**:中文输出;**不用 emoji**;概念讲解固定三段式「**为解决什么痛点而生 / 一句话定义 / 大白话注解**」
- **文档风格**:结论先行、表格优先;能一段说清就不列清单;具体胜过形容
- **链接**:正文互连用 `[[双链]]`;MOC / 索引 / 课件用相对路径链接
- **篇幅**:代码文件 ≤200 行;`.md` 笔记不限长
- **每节课的硬要求**:① 一个当场可验证的"能说出区别"的小胜利 ② 等长选项的测验 ③ 一手资源引用 ④ 结尾提醒"随时追问"
- **一手资源优先**:解释性内容只从 `RESOURCES.md` 取材,不凭模型记忆;找不到就写进 Gaps

## 本项目专属(与其它 18 个学习项目的差别)

- 这里**不学一门技术**,只做名词辨析:目标是一句话定义 + 与相近名词的分界,不是会动手操作
- 一节一组名词(2~4 个),课短;长版正文留在 `20-知识/`,课件只链接过去
- 课件命名:`lessons/NNNN-<名词组>.html`;`<title>` 固定 `NNNN · 标题 · 名词解释`
- 用户 2026-09-25 的原话诉求:"对每个名词单独使用 /teach 生成简短课程让我快速了解名词(包括一些相近的对比)"

## 课程与速查卡的写法(2026-09-25 定,后续每一节都照此办)

- **课只讲一组名词**:3~5 分钟读完,单一胜利 = "能说出这一组的分界";与胜利无关的铺陈删掉
- **正文里就地给外部引用**:每个定义 / 历史 / 数值 / 机制的说法都当场附一个高信任链接(Wikipedia / 官方文档 /
  标准),不要全部堆到"一手资源"一节;引用要真的支撑那句话
- **每节课必须有 `20-知识/` 里没有的东西**:本机实测(贴真实命令与真实输出)、自造最小可跑例子、
  课上独有的判定表或类比 —— **只把长版笔记 HTML 化不算完成**(用户 2026-09-25 强调)。
  **注:这一条已被下一节「新课标准」取代**(用户同日决定课里不再用本机数据)。
- **速查卡是长期资产,课才是会被合上的那份**:每个名词组在 `reference/` 出一张打印友好的判定表
  (特征 → 结论、典型命令/符号、易混点),课里链过去;速查卡要登记在 `00-索引.md` 的「课程」块
- **辨析练习用共享组件**:`90-模板/teach-assets/discriminate.js`(复用 quiz.js 的同一个反馈环),
  每节 4 例、逐例即时反馈 + 整组计分;选项长度同样等长
- **「课里才有」固定成两类**（0004~0006 起，注：已被下一节「新课标准」取代）：① 本机实测（真实命令 + 原始输出，不转述）；② 对照实验 —— 把判据/夹具拎出来单跑一次，用结果揭穿“看起来应当没问题”。后者专治边界认知（如“某条检查 0 处 ≠ 查过”），光读代码看不出来
- **速查卡承担长期查阅,课只承担一次性理解**:判定表 / 失效表 / 用例数 / 原始输出块这类"以后还会回来查"的内容全部进卡,
  课里只留链过去的那一句(含压缩过的演示或节选);两边不重复搬运
- **术语表按技能规则维护**：`GLOSSARY.md` 只登记"用户已证实掌握"的词(能自己造句、或辨析练习一次答对之后),
  刚讲过的词不写进去;一旦进表,后面所有课件一律沿用表里的写法

## 新课标准:纯概念、不用本机数据、三段分行(2026-09-25 用户决定)

用户 2026-09-25 的原话:"痛点 / 定义 / 大白话做到分行;按照 /teach 要求安排课程,**完全忽略本机的数据和规定**,
但是是短期课程,仅起到快速了解其定义作用技术等等内容即可"。

- **本工作区的课一律不用本机数据**:不贴本机命令与输出、不引本仓库的脚本 / 路径 / 约定;
  例子改用通用或公开的(浏览器画按钮、编辑器 / 编译器 / 解释器、包管理器、界面形态这类人人可理解的对象),
  需要点名产品时用通用知名产品。**只服务某次本机实测的 RESOURCES 条目一并删掉**。
- **「痛点 / 定义 / 大白话」三段各自独立成行**:`.pain` / `.def` / `.plain` 三个类定义在共享
  `90-模板/teach-assets/lesson.css` 里,HTML 不再写重复的内联样式。
- **课只求"快速了解"**:3~5 分钟读完,一节一件紧范围的事,讲清定义、作用、关键技术点,
  并与 2~4 个相近名词区分开;操作细节留给长版词条。
- **课仍要满足 teach 的硬要求**:正文就地外部引用(6~12 条)、相近名词对比表(一句话判定 + 失效场景)、
  常见误解 2~3 条、4 例即时反馈辨析练习、3 题自测(四选项严格等长、答案字母打散)、交叉链接、
  一手资源、随时追问提醒、速查卡链接、下一节预告;`<title>` / `.lesson-meta`(含前置) / `.win` 照旧。
- **这条取代老的「课里才有两类」要求**(本机实测 / 对照实验):按新标准,那些内容不进课。
  0001~0005 已按新标准重写;**0006(巡检器)本身讲的就是本库工具**,留给下一批处理时再定取舍。
- **0002 扩为四件套**:原名「编辑器,编译器,IDE」→「编辑器,编译器,解释器,IDE」,
  课 / 词条 / 速查卡三处都改了名,并补上解释器与**混合形态**(先编译成字节码再解释 / JIT)这一节;
