CLI、TUI、GUI:你和电脑说话的三条通道

你能做到:拿到一个软件,指出它给你的界面属于哪条通道 —— 敲完整命令、按选项移动,还是用鼠标点;并说出这条通道换来什么、代价又是什么。

1 | 定义

CLI、TUI、GUI 说的是同一件事的三种做法:你用什么方式把意图送进电脑、电脑用什么方式把状态回给你。 判据只有两条 —— 屏幕上画的是字符流、字符画出的面板,还是像素;以及你是敲完整命令、按选项移动,还是用鼠标点。 三种画法各有一手定义: Wikipedia: Command-line interface、 Wikipedia: Text-based user interface、 Wikipedia: Graphical user interface。

大白话:三条通道,通向同一台电脑。走哪条,看你更想省力气,还是更想省重复。

2 | 解决的痛点

GUI 是为门槛而生的。早期只能用命令行,普通人要背下几十条命令才能干活, 这是电脑普及路上最大的障碍 —— 把功能摆进菜单、让鼠标去点,门槛就没了。

CLI 是为重复与复现而生的。每个动作都被绑在一次点击上,就没法批量、没法留痕、没法让脚本替你干。 把操作变成可复制的一行文字,自动化、批处理、远程运维才谈得上。

TUI 补的是中间那段空地。纯 CLI 看不见状态(进度、列表、当前选中项), 而 GUI 又要求图形环境,在服务器和低带宽的远程连接里太重。用字符在终端里画出面板,两头的好处都留一点。

3 | 心智模型

键盘与指针(输入) → 屏幕上的画法:字符流 / 字符面板 / 像素 → 程序收到的同一份动作 → 结果沿原路送回屏幕

分三段看。上游是输入设备与显示,它们只负责把字送进去、把状态画出来。 中段是判据所在:画面用什么材料画、你怎么操作。 下游是那个软件本身 —— 它还是它,界面形态只决定你怎么使唤它,不决定它能干什么。

4 | 类比与边界

类比:像去政务大厅办事的三条通道。递纸条进窗口按规矩办(CLI), 在自助机上用屏幕菜单一步步选(TUI),还有工作人员领着你点屏幕(GUI)。

这个类比会在三处骗你:

  • ① 大厅只让你走一条,软件却常同时开三条 —— 同一款软件既有菜单,又能用命令调用。
  • ② 窗口那头的人看不见你,程序却清楚"这一行是谁敲的" —— CLI 的输出能被下一条命令接走。
  • ③ 直觉以为 CLI 是"低级形态",其实它是最可复现的一条:一行字能贴给别人、写进脚本。

5 | 它怎么工作

  1. 先看屏幕画的是什么。只有提示符和一行行文本,是 CLI;用字符画出边框、列表和选中高亮,是 TUI; 由像素画出窗口和控件,是 GUI。判据落在材料上,不落在配色上。
  2. 再看你怎么操作。整条命令一次敲完(CLI)、方向键与快捷键在选项间移动(TUI)、指针点选(GUI)。 熟手用键盘更快,生手用鼠标更省事 —— 这是同一条通道选择的两面。
  3. CLI 的强项来自"输出是文本"。一段文字能直接成为下一条命令的输入, 这就是管道机制成立的前提(Wikipedia: Pipeline (Unix))。
  4. TUI 与 GUI 的差别落在"传字符还是传画面"。TUI 只传字符,所以远程登录里照样顺; GUI 远程要把画面一帧帧传过去,网络一差就卡。
  5. 通道不等于身份。终端窗口里敲一条命令也能启动图形程序 —— 那个窗口叫 终端模拟器; 而它里面跑着、听懂命令并启动别的程序的,是个解释器(Shell, Wikipedia: Shell (computing)), 这一层属于另一节课(0002 · 编辑器 / 编译器 / 解释器 / IDE)。

6 | 相近名词一句话判定

先问一句:屏幕上画的是什么?字符流、字符面板,还是像素?再问:你怎么操作?两条都指向同一个答案时才下结论。

名词一句话判定(看到这个就是它)它的失效场景
CLI只有文本流,一次一条命令要"发现功能"时门槛高:不先知道命令名就无从下手
TUI用字符画出面板,键盘在选项间走画图、多窗口并排、精细排版做不到
GUI用像素画窗口,指针直接点选远程带宽吃紧、要批量复现时,它反而是阻力
终端模拟器把键盘送进去、把字符画出来的那个窗口程序它只管显示:窗口一关,里面的东西跟着结束
Shell(bash / PowerShell)读入你敲的一行字,解释成命令再执行它只是窗口里跑的一个程序,不负责让任务活得比连接久

一句话分工:终端模拟器管"画",Shell 管"解释",而三种形态管"你用什么方式下命令"。

7 | 常见误解

  • 「黑框就是 CLI」:黑色只是配色。终端窗口里敲一条命令,照样能打开一个图形程序。
  • 「能用鼠标就是 GUI」:鼠标只是一种输入设备;判据是界面怎么画出来的, 用字符画的界面支持鼠标,它仍然是 TUI。
  • 「终端 = Shell = 命令行」:三个词不在同一层 —— 前者是那个窗口,中间是负责解释命令的程序, 后者是你敲字的那一行位置。

8 | 什么时候别用它

  • 第一次用某个功能、不知道该有什么选项:别硬走 CLI,菜单能看见功能,先逛一遍更省时间。
  • 要画图、剪视频、多窗口对照:别在字符环境里将就,那本来就是像素通道的活。
  • 网络差、只连了一根细线:别开远程桌面,把界面收成只传字符的那两条通道。
  • 要"关掉窗口活还继续":别指望界面形态做到这件事 —— 那是终端复用器的活(0011 · tmux),不在这一节。
  • 要判"界面好不好用":形态与通道是一回事,可用性是另一本账 —— 那要拿人来量(0007 · UI 与 UX)。
  • 事情要做几十遍、还要能复现:别在图形界面里点几十次,去把它写成一行命令。

10 | 交互练习

辨析练习(4 例):这段描述说的是哪一层?

选择范围:CLI / TUI / GUI / 终端模拟器。

1. 远程连上一台服务器,敲一行命令回车,屏幕回你几行文件名,没有全屏面板。

CLI:没有全屏面板,一次只回一段文本。它在这种场合最好用,因为只传字符、不传画面。

2. 一个编辑器:屏幕上是字符画的边框、列表与快捷键提示,用方向键在项目之间移动。

TUI:用字符画出了"面板",通道仍然是文本 —— 所以它同样能在远程登录里跑,这是它比 GUI 强的地方。

3. 双击桌面上的图标,弹出带菜单、按钮和滚动条的窗口,用鼠标拖着看。

GUI:界面由像素画成,功能摆在菜单里点一下就出来。代价是远程使用要把画面一帧帧传过去。

4. 一个窗口程序负责把键盘输入送进去、把字符画出来;关掉它,里面的活跟着结束。

终端模拟器:它管"在哪儿看"。让里面的活活得比连接久,那是另一层工具的事。

自测(3 题):选一个正确答案

每题只有一个正确选项;选完立刻看到解释。

1. 同一件事要在图形界面里重复做 20 遍,最该换哪条通道?

对。CLI 的长处就是"一条命令可复制、可重复、可写进脚本";图形界面里这件事要点 20 遍,而且很难描述给别人听。 经验法则:一件事在图形界面里重复点超过 3 遍,就该去找它的命令写法。

2. 判断一段界面属于哪种形态,判据该落在什么地方?

对。判据是"字符流 / 字符面板 / 像素"这一层。配色、启动速度都与形态无关; 鼠标只是一种输入设备 —— 用字符画的界面也可以支持鼠标。

3. 一款软件既有窗口菜单,又能用命令启动,说明什么?

对。形态是通道,不是分类标签:同一款软件可以同时给出菜单、命令和面板三种走法。 所以"这软件是 GUI 还是 CLI"这个问题本身就不成立,该问的是"它这次给我哪条通道"。
