UI 与 UX:一层看得见的表面,一段走得完的路

这节课的胜利:同一句评价能当场分到哪一层 ——「这个按钮点下去没反应」是 UI,「找了五分钟没找到入口」是 UX。 读完你会用两个可量的数字(对比度阈值、行宽)把「好看」翻译成标准,并说清它们为什么同时归这两层管。

一句话定位

两句话常被当成一件事说,其实数的东西不同:UI 数「人和机器打交道的那个面」 —— 屏幕上的控件、文字、配色与即时反馈; UX 数「一个人用它的整段经历」 —— 从想干这件事到干完的感知与反应。 它们不在同一层,也不对立:UI 做砸了 UX 一定好不了;UI 做满分,UX 仍可能不及格。

为解什么痛点而生

UI:机器内部看不见,得有个约定的面

痛点:机器的逻辑藏在里面,人只能通过一个约定好的表面去操作它、读它的状态;没有这个面,操作无从谈起。 定义:UI 是人与机器发生交互的那个空间;交互的目的,是人这端能有效操作与控制机器,同时机器回馈有助于人判断的信息 (Wikipedia: User interface)。 大白话:UI 是驾驶舱 —— 方向盘、仪表盘、按钮。它可以长成命令行、全屏文本界面或图形界面 (三种形态见 0001 · CLI、TUI、GUI),但都只是「面」。

UX:界面挑不出毛病,事照样办不成

痛点:把界面做漂亮,用户还是可能办不成事 —— 关键数据不在库里、加载要等十秒、出错后不知道该点哪。这些都不在「好不好看」那一层。 定义:UX 是一个人与某个产品 / 系统 / 服务交互时的感受与反应;ISO 9241 的措辞是「使用(或预期使用)时产生的感知与反应」 (Wikipedia: User experience)。 大白话:UI 是仪表盘,UX 是这趟车到底能不能把你送到地方 —— 找车、上车、途中、下车之后全都算。

对比表

名词一句话判定它管什么它保证不了什么
UI它落在屏幕设备那层表面上控件、排版、配色、措辞、状态可见用户能不能真把事办成(数据不全、流程太长,它管不着)
UX它落在用户走完的整条时间线上找得到、做得完、错了能恢复单个像素的对齐、某个按钮的圆角
可用性它是界面本身体检出来的一项易学、高效、少出错、用着顺代表整段体验 —— UI 可用性满分,UX 仍可不及格
可访问性它问的是换个人还能不能用键盘可达、对比度足够、色觉障碍也读得出状态一般用户的效率与愉悦(它是下限,不是全部)

NN/g 的原话把分界画得很清楚:「必须把总的用户体验与用户界面区分开,尽管 UI 显然是设计里极重要的一部分」—— 举的例子是影评网站:即使找电影的 UI 完美无缺,只要片库只有大厂电影,想看独立小片的用户 UX 依然差; 同一篇还补一句可用性是 UI 的一项质量属性,而总体验比它更宽 (NN/g: The Definition of User Experience)。

课里才有:量一量这门课自己的样式表

有一大类 UI 决策是有标准、可计算的,它们同时决定了 UX。WCAG AA 的硬要求:正文文字与背景对比度 ≥ 4.5:1, 大号文字(18pt / 24px,或加粗 14pt)可放宽到 3:1 (W3C: Understanding SC 1.4.3)。 下面这段就读本课的样式表 90-模板/teach-assets/lesson.css,按 WCAG 的相对亮度公式现算(命令与输出原样照抄,2026-09-25): 

$ cd F:/0-Note && python - <<'PY'
import re; from pathlib import Path
css = Path('90-模板/teach-assets/lesson.css').read_text(encoding='utf-8')
v = dict(re.findall(r'--([\w-]+):\s*(#[0-9a-f]{6})', css))     # 抠出 :root 里的配色
L = lambda h: sum(w*(c/12.92 if c<=.03928 else ((c+.055)/1.055)**2.4)
                  for w,c in zip((.2126,.7152,.0722), (int(h[i:i+2],16)/255 for i in (1,3,5))))
for k in ('ink','muted','accent','no','ok','rule'):
    print(k, v[k], '%.2f:1' % ((max(L(v[k]),L(v['paper']))+.05)/(min(L(v[k]),L(v['paper']))+.05)))
PY
ink    #1a1a1a  16.96:1     # 正文
muted  #6b6b6b   5.19:1     # 次要文字
accent #7a5c2e   6.02:1     # 链接
no     #a33a2a   6.40:1     # 错误态
ok     #2f6b3a   6.23:1     # 正确态
rule   #d8d4cc   1.44:1     # 分隔细线:不是文字,不受 4.5 这条约束

读法:五个着色对着纸色 #fdfcf9 全部过 4.5:1(16.96 / 6.40 / 6.23 / 6.02 / 5.19), 所以低视力读者也分得清正文、链接、对错态;唯一低于阈值的是那条 1.44:1 的条件分隔线 —— 它只是排版件,WCAG 那条 4.5 管的是文字,这里没违规。配色归 UI,「读得清」归 UX,同一个值两本账。

行宽同理:样式表写 max-width: 46rem,在 17px 字号下就是 736px,折成汉字约 43 字/行; 而公认舒服的区间是每行 45~90 个字符 —— 行再长,眼睛从行尾回到下一行行首的行程变远,容易串行 (Butterick's Practical Typography: Line length)。 一个有标准、一个靠经验,但都是「先量、再改」的手艺。

辨析练习:这句评价说的是哪一层?

共 4 例。判定靠「它在哪儿」:在屏幕设备那层 = 界面层,在用户经历的整条时间线上 = 体验层。

1. 「这个按钮点下去没有任何变化,我不知道刚才那下有没有生效。」

是界面层:缺的是「状态可见」这一项界面反馈 —— 动作发生了,面上没回话。

2. 「界面上每个地方都很漂亮,可我花了五分钟也没找到从哪儿开始下单。」

是体验层:单看每一处都挑不出毛病,走完整条路才发现办不成事 —— 正是 NN/g 影评网站那个例子的形状。

3. 「浅灰小字在奶茶色底上,低视力的人和老年人基本读不出来。」

是无障碍:换一类使用者(低视力)就用不了 —— 对照 WCAG 那条 4.5:1 就是这条的量化判据。

4. 「每一步都要重新填一遍邮箱,这活儿比原来那份纸表格还费劲。」

是可用性:界面本身能用,但「高效」这一项不达标 —— 它是 UI 的质量属性,量出来的却是一个体验问题。

自测(选项一样长,别从长度上猜)

1. 下面哪一项描述的是 UX?

对。判断法只有一条:在屏幕那层还是在你走完的时间线上 —— 「能看到的面」是 UI,「文字与底色的比值」是它的量化项, 「键盘能不能走到底」问的是可访问性。

2. 关于 WCAG AA 的对比度要求,哪句对?

对。3:1 是「大号文字」那一档的放宽值(18pt / 24px,或加粗 14pt),不是正文; 行宽 45~90 个字符是排版建议,不是可访问性标准。两边别互相顶替。

3. 关于「UI 好看就等于 UX 好吗」,哪句对?

对。NN/g 那个影评网站就是反例:找片的界面完美,片库只有大厂电影,想看独立小片的人照样办不成事 —— UI 是 UX 的必要条件,不是充分条件。

UI / UX 速查 —— 判定表(现象 → 是哪一层)、两个阈值(4.5:1 与 45~90 字符)、 本机这份样式表的实测数字、字号与行宽换算、易混点;打印一页就够。 要细节(两个词的完整定义与出处、可用性 / 信息架构 / 设计系统怎么挂上去、五条常见误解的逐条拆解)去长版词条 UI 与 UX 的区别。同属「一层一层分」这条线: 0001 · CLI、TUI、GUI 分的是界面形态,这一节分的是表面与经历。
