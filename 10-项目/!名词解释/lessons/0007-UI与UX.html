UI 与 UX:一层看得见的表面,一段走得完的路

你能做到:听到一句评价就说出它落在哪一层 —— 「按钮点下去没反应」在面上, 「找了五分钟没找到入口」在路上;并且知道「好看」里有一半是可以查、可以算的硬标准。

1 | 定义

UI 是人与机器打交道的那个面:屏幕上的控件、文字、配色,以及点下去之后那一下即时反馈。 UX 是一个人用它的整段经历:从想干这件事,到干完之后的感受与反应 (Wikipedia: User interface · Wikipedia: User experience)。

大白话:UI 是仪表盘,UX 是这趟车到底有没有把你送到地方。

2 | 解决的痛点

机器内部看不见,人只能通过一个约定好的面去操作它、读它的状态。没有这个面,连「点哪里」都无从谈起。

可把界面做漂亮,用户照样可能办不成事:要的数据不在库里、加载要等十秒、出错之后不知道该点哪儿。 这些都不在「好不好看」那一层。

还有个老毛病:「好不好用」听着像主观感受,于是没人去量它。其实它由几件可数的事组成 —— 要学多久、几步做完、错了多少次、错了能不能退回来。

3 | 心智模型

我想干一件事 → 界面这一层:控件、文字、即时反馈 → 系统内部:数据、逻辑、网络 → 结果回到界面 → 我走完的整段经历:找到、做成、恢复、回想

分三段看。上游是我的目标:我要办成一件事。中间那格是手指能碰到的地方, 它只负责「操作得动、看得懂」。下游才是我记住的东西:办成了没有、花了多久、出错时慌不慌。

两层既不同层也不对立:界面做砸了,经历一定好不了;界面做满分,经历仍可能不及格。

4 | 类比与边界

类比:像下馆子。UI 是菜单、桌椅、灯光;UX 是从进门到吃完结账的整趟 —— 等位多久、菜上没上齐、结账快不快。

这个类比会在三处骗你:

  • ① 餐厅对所有人是同一家,经历却一人一份:同一次结账,赶时间的人和慢慢吃的人评价不同。经历天生带主观成分。
  • ② 菜单做得再漂亮,冰箱里没有那道菜就是吃不上 —— 后厨不在 UI 这一层,却直接决定经历好不好。
  • ③ 类比里没有「换个人还能不能用」的位置:台阶挡住了坐轮椅的客人,而菜单本身挑不出毛病。

5 | 它怎么工作

  1. 先有一个面。机器把能做的事摆成控件或命令,把当前状态显示出来。这个面可以长成命令行、全屏文本界面或图形界面(三种形态见 0001 · CLI / TUI / GUI)。
  2. 动作要有回话。点下去之后,界面用变化、进度、提示告诉你「收到了」。业内叫状态可见:它是界面的职责,账却记在经历上。
  3. 事是系统做的,界面只传话。数据从哪来、请求多久返回、失败怎么退,决定你能不能办成事;界面只能如实演出来。
  4. 走完整条路,才形成经历。同一句吐槽在不同环节说出口,评的不是同一层:「按钮没反应」在面上,「找五分钟没找到」在路上 (NN/g: The Definition of User Experience)。
  5. 面上一大类东西是可以算的。对比度、行宽、点按目标尺寸都有标准或经验值。把「好看」翻译成数字,争论就从口味变成核对。
项硬标准或经验值出处
正文文字与背景的对比度≥ 4.5:1;大号文字可放宽到 3:1W3C: SC 1.4.3
点按目标的最小尺寸24×24 CSS 像素W3C: SC 2.5.8
一行读起来舒服的长度45~90 个字符Butterick: Line length

6 | 相近名词一句话判定

先问一句:它在哪儿?在屏幕那层就是界面,在我走完的时间线上就是经历。再问一句:它在量什么?

名词一句话判定(看到这个就是它)它的失效场景
UI(用户界面)话头落在屏幕那层表面:控件、排版、配色、反馈数据不全、流程太长,它管不着 —— 表面完美,事照样办不成
UX(用户体验)话头落在用户走完的整条时间线上管不到像素对齐、按钮圆角这类单点细节
可用性(usability)界面本身体检出的一项:可学、高效、易记、少错、满意它不等于整段经历:可用性满分,经历仍可不及格
可访问性(accessibility)问的是换一类人还能不能办成同一件事它是下限不是全部:达标只说明没人被挡在门外
交互设计设计「操作 → 反馈」这一来一回的动作序列管不到数据从哪来,也管不到买完之后的那一段

NN/g 把这条线画得很硬:「必须把总的用户体验与用户界面区分开」, 并给了个反例:找电影的界面完美无缺,片库却只有大厂片,想看小片的人经历依然是差的 (NN/g)。

7 | 常见误解

  • 「UI 好看就等于 UX 好」:错在把必要条件当充分条件。上面那个片库反例就是标准答案。
  • 「可访问性是给少数人做的额外版本」:键盘能走通、对比度够,对所有人都有效。它是下限,不是特殊分支。
  • 「好看是主观的,没法量」:等待时长、步骤数、对比度、行宽、点按尺寸都有标准或经验值;真正没法量的只是审美偏好那一小块。

8 | 什么时候别用它

  • 别用「这是界面问题」结案。先看卡在哪一层:数据不对、接口太慢,换十版配色也没用。
  • 别拿可访问性达标当体验合格证。过线只说明没人被挡在门外,离「办得顺」还远。
  • 别在审美偏好上摆标准压人。用什么字体、圆角多大是口味;对比度够不够是硬伤,两者别混着吵。
  • 别拿一个用户的一句话当结论。经历一人一份,要多人多次地看才站得住。

10 | 交互练习

辨析练习(4 例):这句评价说的是哪一层?

选择范围:界面层 / 体验层 / 可用性 / 可访问性。

1. 「这个按钮点下去没有任何变化,我不知道刚才那下有没有生效。」

界面层:缺的是「状态可见」这一项界面反馈 —— 动作发生了,面上没回话。

2. 「每个地方看着都很漂亮,可我花了五分钟也没找到从哪儿开始下单。」

体验层:单看每一处都挑不出毛病,走完整条路才发现办不成事。

3. 「浅灰小字压在奶茶色底上,低视力的人和上了年纪的人基本读不出来。」

可访问性:换一类使用者(低视力)就用不了;对照度那条 4.5:1 就是它的量化判据。

4. 「每一步都要重新填一遍邮箱,这活儿比原来那张纸表格还费劲。」

可用性:界面本身能用,但「高效」这一项不达标 —— 它是界面的一项质量属性。

自测(3 题):选一个正确答案

每题只有一个正确选项;选完立刻看到解释。

1. 下面哪一项描述的是 UX?

对。「能看到的面」是界面,「文字与底色的比值」是它的量化项,「键盘能不能走到底」问的是可访问性 —— 只有整段路是经历。

2. 关于界面与经历的关系,哪句对?

对。找电影的界面完美、片库缺片,经历照样差 —— 界面是经历的必要条件,不是充分条件。

3. 关于「好看」这件事,哪句对?

对。对比度有 4.5:1 这样的硬阈值,行宽有 45~90 字符的经验值,点按尺寸有 24×24 的下限; 真正没法量的只剩审美偏好那一小块。
