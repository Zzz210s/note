UI 与 UX:一层看得见的表面,一段走得完的路

这节课的胜利:同一句评价能当场分到哪一层 ——「按钮点下去没反应」是 UI, 「找了五分钟没找到入口」是 UX;并知道「好看」里有一半是可以查、可以算的硬标准, 以及为什么「换个人还能不能用」要单独算一账。

一句话定位

这两个词常被当成一件事说,其实数的东西不同:UI 数「人和机器打交道的那个面」 —— 屏幕上的控件、文字、配色与即时反馈;UX 数「一个人用它的整段经历」 —— 从想干这件事到干完之后的感知与反应。它们不在同一层,也不对立: UI 做砸了 UX 一定好不了;UI 做满分,UX 仍可能不及格。

三个词:痛点 / 定义 / 大白话

UI:机器内部看不见,得有一个约定的面

痛点:机器的逻辑藏在里面,人只能通过一个约定好的表面去操作它、读它的状态; 没有这个面,交互无从谈起。

定义:UI 是人与机器发生交互的那个空间;交互的目的,是人这端能有效地操作与控制机器, 同时机器回馈有助于人判断的信息(Wikipedia: User interface)。

大白话:UI 是驾驶舱 —— 方向盘、仪表盘、按钮。它可以长成命令行、全屏文本界面或图形界面 (三种形态见 0001 · CLI、TUI、GUI),但都只是「面」。

UX:界面挑不出毛病,事照样办不成

痛点:把界面做漂亮,用户还是可能办不成事 —— 需要的数据不在库里、加载要等十秒、 出错之后不知道该点哪儿。这些都不在「好不好看」那一层。

定义:UX 是一个人与某个产品 / 系统 / 服务交互时的感受与反应; ISO 9241 的措辞是「使用(或预期使用)时产生的感知与反应」 (Wikipedia: User experience)。

大白话:UI 是仪表盘,UX 是这趟车到底能不能把你送到地方 —— 找车、上车、途中、下车之后全都算。

可用性:界面本身体检出来的一项

痛点:「好不好用」听着像主观感受,于是没人去量它;可它其实由几件可数的事组成 —— 要学多久、几步做完、错了多少次、错了能不能退回来。

定义:可用性是「这个界面有多易用」,常拆成五项:可学、高效、易记、少错、满意 (NN/g: Usability 101)。

大白话:它是 UI 的一项质量属性 —— 界面能用不等于好用;量出来的却常常是一个体验问题(「每一步都要重填一遍邮箱」)。

对比表

名字一句话判定什么时候它不适用
UI它落在屏幕 / 设备那层表面上数据不全、流程太长,它管不着 —— 表面挑不出毛病,事照样办不成
UX它落在用户走完的整条时间线上管不到像素对齐、按钮圆角这类单点细节
可用性它是界面本身体检出来的一项它不等于整段体验:可用性满分,UX 仍可不及格
可访问性它问的是换个人还能不能用它是下限不是全部:达标了只说明没人被挡在门外

NN/g 的原话把分界画得很清楚:「必须把总的用户体验与用户界面区分开,尽管 UI 显然是设计里极重要的一部分」 —— 举的例子是影评网站:即使找电影的 UI 完美无缺,只要片库只有大厂电影, 想看独立小片的用户 UX 依然差;同一篇还补一句可用性是 UI 的一项质量属性,而总体验比它更宽(NN/g: The Definition of User Experience)。

把「好看」翻译成标准

一大类界面决策是有标准、可计算的,它们同时决定了体验能不能走通。下面五条都能查、能算:

项数值出处
正文文字与背景的对比度(AA)≥ 4.5:1W3C: SC 1.4.3
大号文字(18pt / 24px,或加粗 14pt)≥ 3:1同上
图形件与相邻色的对比度(理解内容所必需时)≥ 3:1W3C: SC 1.4.11
点按目标的最小尺寸(AA)24×24 CSS pxW3C: SC 2.5.8
舒服的行宽45~90 个字符Butterick: Line length

对比度是算出来的,不是看出来的:相对亮度按 0.2126 / 0.7152 / 0.0722 三个权重加权, 比值 = (L亮 + 0.05) ÷ (L暗 + 0.05)。于是纯白对纯黑 = 21:1(理论最大), 同一种颜色相叠 = 1:1(也就是看不见)。同一个数,两本账:配色是 UI 的活,「读得清」是可用性与可访问性的账 —— 过低就是有人用不了,不是在挑剔美观。

一个反向提醒:低于阈值不等于违规。WCAG 那条 4.5:1 管的是文字; 分隔细线、纯装饰的底板不在这条规则的射程里(非文字件另有 3:1 的口径,且只针对「理解内容所必需」的图形件)。 别拿一个数字去套所有东西。

常见误解

  • 「UI 好看就等于 UX 好」不成立:UI 是 UX 的必要条件,不是充分条件 —— 影评网站那个例子就是标准反例。
  • 「可访问性是给少数人做的额外版本」不成立:键盘能走通、对比度达标对所有人都有效; 它是下限,不是特殊功能。
  • 「好看是主观的,没法量」不成立:等待时长、步骤数、对比度、行宽、点按尺寸都有标准或经验值; 真正没法量的是审美偏好的那一小块。

辨析练习:这句评价说的是哪一层?

共 4 例。判定靠「它在哪儿」:在屏幕那层 = 界面,在用户经历的整条时间线上 = 体验。

1. 「这个按钮点下去没有任何变化,我不知道刚才那下有没有生效。」

是界面层:缺的是「状态可见」这一项界面反馈 —— 动作发生了,面上没回话。

2. 「界面上每个地方都很漂亮,可我花了五分钟也没找到从哪儿开始下单。」

是体验层:单看每一处都挑不出毛病,走完整条路才发现办不成事 —— 正是 NN/g 影评网站那个例子的形状。

3. 「浅灰小字在奶茶色底上,低视力的人和老年人基本读不出来。」

是无障碍:换一类使用者(低视力)就用不了 —— 对照 WCAG 那条 4.5:1 就是这句的量化判据。

4. 「每一步都要重新填一遍邮箱,这活儿比原来那份纸表格还费劲。」

是可用性:界面本身能用,但「高效」这一项不达标 —— 它是 UI 的质量属性,量出来的却是一个体验问题。

自测(选项一样长,别从长度上猜)

1. 下面哪一项描述的是 UX?

对。判断法只有一条:在屏幕那层还是在你走完的时间线上 —— 「能看到的面」是 UI, 「文字与底色的比值」是它的量化项,「键盘能不能走到底」问的是可访问性。

2. 关于 WCAG AA 的对比度要求,哪句对?

对。3:1 是「大号文字」那一档的放宽值(18pt / 24px,或加粗 14pt),不是正文; 行宽 45~90 个字符是排版建议,不是可访问性标准。两边别互相顶替。

3. 关于「UI 好看就等于 UX 好吗」,哪句对?

对。NN/g 那个影评网站就是反例:找片的界面完美,片库只有大厂电影, 想看独立小片的人照样办不成事 —— UI 是 UX 的必要条件,不是充分条件。
