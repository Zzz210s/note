SVN 与 Git:仓库放在哪,决定你怎么改

你能做到:拿到一个项目先问两句 —— 完整的仓库在谁手里、不联网能不能提交 —— 就能说出它用的是哪一种;再听到「分支很贵」「大文件总出问题」「权限只能给到整个仓库」,也知道那是哪一套模型的账。

1 | 定义

这两个词解决同一件事 —— 替一批文件记住每个版本、让多人同时改还不互相覆盖 —— 只是做法相反:一个把唯一一份放在中央,一个给每人都发一份完整的。各记一行:

  • ① SVN(Apache Subversion,集中式版本控制系统 centralized VCS) 全队的改动都存进一台中央服务器上的那一份仓库(repository);你机器上只有从它取下来的一段工作副本(working copy),提交(commit)就是把自己的改动送回那台服务器。 全公司的底稿都锁在档案室那一本:要动哪页,先借出来、改完还回去 —— 谁都绕不开这间档案室。
  • ② Git(分布式版本控制系统 distributed VCS) 每个参与者的机器上都有一份内容完整的仓库(含全部历史);提交(commit)先落在自己这台机器上,想和别人合到一起再把改动推过去。 每人手里都有一本完整的档案副本:先在自己本子上改,改完想合到一起,再和对面那份对一次。

差别就此定下:SVN 只有一份仓库,大家围着它转;Git 人人一份完整仓库,各改各的。后面所有不同 —— 分支贵不贵、离线能不能提交、权限细不细 —— 都是这一条的推论。

2 | 它们解决什么麻烦

两者面对的是同一个麻烦:一批文件被很多人反复改,得有人替每一次改动留底。这份麻烦拆开来是四件事:

  • ① 后保存的人覆盖前一个人的改动。两个人各拿一份文件改,谁最后保存谁赢,另一个那半天白干 —— 需要有东西记住「谁先改的、改的是哪一版」。
  • ② 文件名记不住历史。靠 方案-最终版2-真的最终 这类命名,过一个月没人分得清哪份是给谁看的;想找三周前那一版,只能翻邮件。
  • ③ 改坏了退不回去。没有留底只能凭记忆重写,有留底回退就是一条命令的事;出了事故也才知道是谁、在哪一步动的。
  • ④ 同时改同一个文件得有个说法。要么改之前先把文件锁住让别人等,要么各改各的、合的时候把冲突挑出来交给人决定 —— 两个词在这上面也各有偏好。

四件事都指向同一样东西:一份带历史的仓库。两个词的分别,是这份仓库放在哪儿、由谁保管。

3 | 特征矩阵

每一列都是能直接从仓库和命令上看出来的事。先问「仓库在哪」,再横着读一遍,模型就分清了。

名词 仓库在哪 提交要不要联网 分支怎么实现 分支与合并的成本 权限粒度 二进制大文件 典型命令
SVN 一台中央服务器上的唯一一份 要:提交和查历史都得连上它 目录拷贝:建分支就是复制一份目录 重:每条分支都是一份目录,合并要按版本区间逐次比对 细:可按目录、按人分别授权 友好:可只取需要的子目录,还能把单个文件锁住 svn checkout / update / commit
Git 每台机器上各有一份完整的 不要:提交先落本地,推的时候才联网 提交指针:一个分支只是一个指向某次提交的名字 轻:建、切分支几乎瞬时,合并有整套工具 粗:仓库级;要细粒度得靠托管平台或服务端钩子 不友好:历史随大文件一起膨胀,得另配 LFS git clone / commit / push

「提交要不要联网」是最好认的一列:断网还能提交的是 Git,提交前必须先连上中央服务器的是 SVN。同一件事实还决定了另外两列 —— 因为每人都有一份完整历史,Git 才能把分支做成一个便宜的名字;因为只有一份在中央,SVN 才能按目录精细授权,把权限中心和维护都放在那一台上。再补一句表里没单列的事:能不能离线查完整历史 —— Git 断网也能翻全部提交记录,SVN 本地只有你检出那一段,想看别的分支得先换过去。分布式这个词说的正是前一件事,而不是「没有服务器」。

4 | 各自怎么做

先看围着中央仓库转的那一套(以 svn 命令为例,图形客户端做的是同一件事):

  • ① 把中央仓库的一段取到本地,就是工作副本。svn checkout 取下来之后,你改的是本地这份副本;svn update 把别人已经提交的改动拉下来;svn commit 把你的改动送回去;svn switch 换到另一条分支上。这些命令都在命令行里敲(见 0001 · CLI / TUI / GUI),也有图形客户端可用。
  • ② 分支就是目录。仓库里常见的 trunk/、branches/、tags/ 只是三份目录约定:建分支等于把一份目录复制成另一份;合并(合并 merge)就是把一条目录上的若干版本区间挑到另一条上,区间挑错了冲突就多。
  • ③ 用锁和「各改各的」管并发。二进制文件(图片、模型、设计稿)不好逐行合并,可以先 svn lock 锁住,别人这段时间改不了;文本文件默认允许各改各的,提交时撞上同一段才报冲突,要人手动合。这一组取舍就是锁 lock与乐观并发。

再看每人都有一份完整仓库的那一套:

  • ④ 日常只有三步。git clone 把仓库整份取到本地,git commit 把改动记进本地历史,git push 再把本地的新提交推给对面的仓库 —— 不推也不妨碍你继续提交,断网照样工作。
  • ⑤ 分支只是一个可移动的名字。建分支就是新写一个指向某次提交的标签,所以建、切都几乎是瞬时;git merge 把两条线合到一起,git rebase 把你本地的提交依次挪到另一条线的头上(历史更整齐,但改写了原有的提交)。
  • ⑥ 暂存区与储藏把改动分开。git add 挑出这次要提交的那部分改动,git stash 把还没写完的活先收起来,好切到别的分支去救火;这两样在 SVN 里都没有对应物。
  • ⑦ 两边都能挂钩子(hook)。提交前自动跑一遍检查叫 pre-commit,就是巡检器那类检查挪到提交那一刻;推到服务器之后再自动构建、跑测试,则是发布流水线那一端的事。

5 | 各自的代价

  • ① SVN 离线就交不上。飞机上、断网时改得再多也只能攒着,回到能连上服务器才提交;中央那台一旦连不上或坏掉,全队的提交和查历史一起停 —— 它既是唯一的仓库,也是单点。
  • ② SVN 查历史、看别的分支都要联网。本地只有你检出那一段,想看同事的分支得先 switch 过去或另外检出一份;翻一条几年前的改动,也得走一趟服务器。
  • ③ SVN 的分支重、合并费手。每条分支都是仓库里实打实一份目录,项目一多、分支一密,复制和合并都慢;合并按版本区间逐个挑,区间对不上就得一条条解决冲突。
  • ④ 中央那台要人供着。权限、备份、升级都在它身上配,配错一次影响全队;它也是所有人的必经路口,而人手一份的模型没有这个路口。
  • ⑤ Git 的上手曲线陡。暂存区、本地提交、分支指针、变基这些概念一开始都反直觉;一条命令敲错(变基或强推)可能把本地还没备份的改动弄丢。
  • ⑥ Git 对大二进制文件不友好。每次改动都存一份新内容,美术资源、模型、视频放进去,仓库体积会成倍涨;要用 LFS 把大文件挪到别处存,又多一层要维护的东西。
  • ⑦ Git 的权限只能管到仓库级。「这个目录只给这几个人看」得靠托管平台或服务端钩子补,不像 SVN 那样开箱就能按目录授权。
  • ⑧ Git 允许改写历史。已经推出去的提交被变基或强推覆盖后,别人的本地历史和它对不上,合并时会冒出一堆重复提交,得手工收拾。

6 | 区分使用场景

两种模型不打架,挑的依据是「你们怎么分工、更在意哪一件事」:

  • ① 目录级权限是硬要求,或者以二进制资源为主(设计稿、模型、素材)→ 常常还是 SVN 合适:可按目录逐人授权,二进制文件能锁,不必担心同一份被两个人同时覆盖。
  • ② 开源协作、分支开得频繁、要能离线提交 → Git:分支便宜,合并有整套工具,历史就在本地这台机器上。
  • ③ 团队里有人只熟其中一种 → 跟着项目现有的走,别为了统一工具先停一天工;两种工具各自都能把活干完。
  • ④ 老项目还留在 SVN、暂时不搬家 → 用 git svn 把 SVN 仓库接到 Git 客户端上使用:提交依旧进 SVN,你在本地享受 Git 的分支与本地提交。
  • ⑤ 手上有两种项目,一种 SVN 一种 Git → 只记住那一问:完整的仓库在谁手里、提交要不要联网;答案不同,命令与习惯跟着不同。

7 | 常见误解

  • ① 「SVN 早就没人用了。」不少企业内部、游戏与动画团队仍在用它:它们要目录级权限,而且素材多是二进制文件,锁一下比逐行合并省事得多 —— 这些正是 SVN 的强项。
  • ② 「Git 是 SVN 的升级版。」它们是两种模型,不是同一个东西的旧版与新版:一个中央一份,一个人手一份。选哪个看分工方式和权限要求,不看「谁更新」。
  • ③ 「Git 也有 GitHub 这样的中央仓库,所以它其实也是集中式。」那台服务器是团队自己约定的一处落脚点。每台机器上仍然各有一份完整仓库,断网照样提交 —— 一处约定的落脚点,不改变「人人都有完整一份」这个模型。
  • ④ 「换成 Git 就不会丢改动了。」改动先落本地,要主动推才到别人那里;机器坏了、本地那份又没推出去,没推的部分就跟着一起没了。

8 | 练习

三题自测,每题只有一个正确选项;选完立刻看到解释。按题干的动作挑。

1. 每台机器上都有一份完整仓库,断网也能先提交到自己这边,想合的时候再推给对面的仓库。

对。仓库人手一份、提交先落本地,这是分布式那一套;联网只在推给对面时发生,所以断网照样能提交 —— 这也正是它和只有一份中央仓库的最大分别。

2. 建分支就是把一份目录整份复制成另一份;改二进制文件之前,可以先把文件锁住,不让别人同时动。

对。目录即分支、还能对单个文件加锁,是集中在中央那一套的做法;分支做成一个便宜的名字、大二进制文件要另配 LFS,则是人手一份那一套的账。

3. 从仓库取下来、放在你机器上让你改的那份文件与目录;你在它上面编辑,改完再提交回仓库。

对。你直接编辑并提交的那一份是工作副本,它和仓库是两回事:在 SVN 里它是你从中央取下来的一段,在 Git 里它就是那份完整仓库的当前检出。
