巡检器:把「这里还讲不讲道理」变成一条条可执行的检查

这节课的胜利:说清「巡检器 / 一致性检查器」是一类什么工具 —— 它把约定写成规则、按文件与行号报违规、用退出码给流水线一个判断 —— 并记住一条纪律:某条检查报 0 处,不等于它真的查过了。

一句话定位

巡检器(也叫一致性检查器、结构检查器)把「这个仓库 / 文档集还讲不讲道理」翻译成一组可机器判定的规则: 跑一遍重算全部,逐条报出 规则 · 文件:行号 · 原因,结论落在退出码上 (Wikipedia: Exit status)。 它是静态检查 —— 不运行内容、不判断对错,只按规则看结构与文本 (Wikipedia: Static program analysis)。 同一族的工具:Markdown 的 linter、文档站的死链检查器、代码仓库里的 pre-commit。

三个由来:痛点 / 定义 / 大白话

人眼在几十个文件时还行,到几百个必然漏

痛点:一堆文档里断掉的链接、过期的引用、与实物对不上的统计行 —— 这些毛病不逐个打开就看不见,而且它们不会让任何东西报错:页面照样能打开,提交照样能通过。

定义:巡检器把这类结构约定写成可执行判据(每条只盯一个能判定的特征), 跑一次就把整批文件重算一遍(Wikipedia: Link rot)。

大白话:像体检报告 —— 它不判断你身体好不好,只量几项指标,哪项超标就把那一项和数值指出来。

「有问题」三个字等于没查

痛点:一次全量检查只给一句「有问题」,等于把排查成本原样丢回给人; 文件一多,「去哪儿找」比「要不要修」难得多。

定义:每条问题都是一条记录 (规则编号, 文件, 行号, 详情); 行号 0 表示整文件级问题(例如「没有任何地方引用它」)。

大白话:查出血脂高,得指到哪一项、数值多少;只说「你不太健康」是废话。

检查器自己也要被检查

痛点:检查器写错了比不写更糟 —— 它会安静地放过真问题,还给你一个虚假的「全绿」。

定义:好的巡检器自带测试:在临时目录里造一个假仓库, 验证「该报的报了、不该报的没报」(Wikipedia: Test fixture)。

大白话:体检仪也要按标准样品校准一遍。这一层与 0005 · 测试夹具 是同一门手艺。

对比表

名字一句话判定什么时候它不适用
巡检器(一致性检查器)看跨文件的结构关系:链接、引用、数量、归属查不到事实错误;规则没写的关系它一概不管
linter看单个文件的格式与排版:标题层级、空行、行宽管不到文件与文件之间的关系
测试夹具(fixture)看某个程序的行为是否等于预期它只管程序,不管文档集
CI(持续集成)把上面几件事每次推送时自动跑一遍它只管「什么时候跑」,判据不来自它

一句话分工:linter 管一页排版,巡检器管整本装订,夹具管某个零件能不能动,CI 管「每次都替我按一遍开关」。 让检查在提交前自动发生的一手做法见 pre-commit; 让它在每次推送时发生的一手文档见 GitHub Actions (Wikipedia: Continuous integration)。

怎么读它的输出:只看三样

看什么长什么样(示例)用途
哪一条[R3 断链] 2 处分类计数:哪类规则命中了、各几处
在哪儿缩进的 docs/a.md:12 ../nowhere.md文件 + 行号 + 原因,直接跳过去改
过没过结论行 + 退出码(0 / 非 0)给人看红绿,给流水线当判断依据

这三样是这类工具的通用形状:规则编号让你知道「该找谁」,文件与行号让你知道「去哪儿」, 退出码让机器知道「要不要拦」。少了任何一样,它要么没法定位,要么没法接进流水线。

常见误解

  • 「全绿 = 内容没问题」不成立:它只覆盖规则里写了的那几项;事实错误、说法合不合适都不在范围内。
  • 「某条报 0 处 = 这条查过了」不成立:一条规则可能被豁免(只对某类文件生效)、 可能因为前置条件不满足而短路跳过(比如「连目标目录都没有,就直接跳过这一条」),也可能压根没覆盖你的场景。 要把「没报」当证据,得先知道它什么时候不报。
  • 「它会运行我的内容」不成立:静态检查只读文本;会执行东西的那叫测试,不叫巡检。

辨析练习:这个毛病归哪一类检查管?

共 4 例。选择范围:链接与引用、结构与数量、格式与排版、都不归它管。

1. 文档里一条指向别的文件的相对链接,目标已经被删掉了。

是链接与引用:路径与目标对不上,是这类工具最经典的一条。它与「有没有人引用它」是两件事。

2. 目录页的统计行写着「共 12 条」,实际数下来只有 11 条。

是结构与数量:数字与实物对不上 —— 链接可能都在,只是登记数没跟上。

3. 一个段落的标题层级从二级直接跳到四级,中间没有三级。

是格式与排版:这一条归 linter,它只看单个文件内部的排版,不看文件之间的关系。

4. 文中引用的某个年份事实上写错了,而格式与链接都没问题。

都不归它管:事实正确性机器判不了 —— 这类工具查的是「讲不讲道理」,不是「讲得对不对」。

自测(选项一样长,别从长度上猜)

1. 巡检器与 linter 的分工差别在哪?

对。linter 盯一个文件之内的排版(标题层级、空行、行宽),巡检器盯文件与文件之间的关系 (链接通不通、有没有人引用、登记数字对不对)。覆盖面不重叠,谁也替代不了谁。

2. 看到某条检查输出 0 处,能得出什么结论?

对。0 处有三种可能:真的干净、这一条被豁免、或者它因为前置条件不满足而短路跳过了。 要把「没报」当证据,就得先知道这条判据什么时候不报;怕它骗你,就把判据单独拎出来跑一次。

3. 下面哪一类问题巡检器能查出来?

对。断链是它的活;「年份写错」是事实错误、「标签语义」机器判不了、「排版留白」归 linter —— 后两类分别是「它查不到」和「不归它管」。
