巡检器:把"库还讲不讲道理"变成可执行的检查

这节课的胜利:说清这个库自带的 vault-check 干什么、怎么读它的输出与退出码, 以及它和 linter、测试夹具、CI 各守哪一段 —— 并记住一条纪律:某条检查输出 0 处,不等于它真的查过了。

一句话定位

巡检器是这个笔记库自己写的一组 Python 脚本(50-资源/工具/vault-check/)。它把"这个库还讲不讲道理" 翻译成 14 条机器可判定的检查(A1~A14):链接通不通、有没有人引用、索引页数字对不对得上、 成品知识住没住进项目的 20-知识/……跑一次重算全库,逐条报出 文件:行号 原因, 结论落在退出码上(Wikipedia: Exit status)。 它是静态检查:不运行笔记里的任何代码,只看结构与文本(Wikipedia: Static program analysis)。

为解什么痛点而生

人眼在几十篇时还行,到两百篇必然漏

痛点:2026-09-22 第一次认真整理这个库时,手工统计出断链 13 处、双链失效 29 处、孤篇 20 篇、元数据违规 25 处。这些问题的共性是不逐篇打开就看不见,而且它们不会让任何东西报错 —— 笔记照样能打开、能提交。 定义:巡检器把这些结构约定写成可执行判据,跑一次重算一次,结论落在退出码上。 大白话:像体检报告 —— 它不判断你身体好不好,只量血压血糖,哪项超标就把那一项和数值指出来。

"有问题"三个字等于没查

痛点:一个全库体检如果只给一句"有问题",等于把排查成本原样丢回给人。 定义:每条问题都是一条 Finding = (检查项, 文件, 行号, 详情),行号 0 表示整篇级问题。 大白话:血压超标得指到哪一项、数值多少;只说"你不太健康"是废话。

检查器自己也要被检查

痛点:检查器写错了比不写更糟 —— 它会安静地放过真问题,还给你一个虚假的"全绿"。 定义:巡检器带 selftest_*.py,在临时目录里造一个假库,验证"该报的报了、不该报的没报"。 大白话:体检仪自己也要按标准样品校准一遍;这层正是上一节讲过的 测试夹具。

与相近名词的对比

名词它看的是哪一段判据从哪来什么时候跑
巡检器(vault-check)跨篇的结构关系:链接、引用、索引、归属本库自定的 14 条(A1~A14)改完一批笔记后手动跑
linter(markdownlint)单篇的文本格式:标题层级、空行、行宽通用规则集(Wikipedia: Lint)提交前 / 写笔记时
测试夹具(fixture)某个程序的行为是否等于预期该程序的契约(逐条断言)改完代码后
CI(持续集成)把上面几件事每次推送时自动跑一遍流水线配置(GitHub Actions、 Wikipedia: CI)推送 / 提 PR 时

一句话分工:linter 管一页排版,巡检器管整本装订,夹具管某个零件能不能动,CI 管"每次都替我按一遍开关" (pre-commit 就是"提交前自动跑检查"的一手实现)。本库常驻前两者。

课里才有:它跑起来长什么样

本机真实跑一次(命令与输出原样照抄,2026-09-25;# 退出码 是注解,不是输出内容):

$ PYTHONIOENCODING=utf-8 python -B check_vault.py --quiet
[A1 断链] 0 处
……                    # A2~A14 同形,共 13 行分类计数,一律 "0 处"
结论:PASS                       # 退出码 0

再往同一目录写一个坏文件(坏 type、坏 status、一条指向 ../nowhere.md 的链接),同一命令立刻改口; 缩进的 文件:行号 原因 明细要去掉 --quiet 才有(check_vault.py 里那段包在 if not args.quiet 里):

$ PYTHONIOENCODING=utf-8 python -B check_vault.py --quiet
[A1 断链] 1 处
[A3 孤篇] 1 处
[A5/A6 元数据] 2 处
……                    # 13 行分类计数里只有这 3 组非 0
结论:FAIL                       # 退出码 1
$ PYTHONIOENCODING=utf-8 python -B check_vault.py        # 去掉 --quiet 才有明细
   50-资源/工具/vault-check/tmp-demo.md:10 ../nowhere.md
   50-资源/工具/vault-check/tmp-demo.md:0 无入链
   50-资源/工具/vault-check/tmp-demo.md:0 type=knowledge 非规范值
   50-资源/工具/vault-check/tmp-demo.md:0 status=进行中 非规范值
$ rm tmp-demo.md                 # 删掉,再跑又回到 PASS

读法只有三样:哪条(分类汇总)、几处(命中数)、行号(缩进那行,0 表示整篇级)。 一个坏文件被三条同时抓住,且每条都指到同一个文件的同一行 —— 这就是"能定位"与"只说有问题"的差别。

课里才有:0 处 ≠ 查过了

A13 报 0 处,但把这套判据拎出来单跑,结果并不一样:

$ python -c "import checks_backlink as B; ... print(B.declares_project(笔记, 文本, 项目名))"
笔记declares_project 返回A13 报不报
10-项目/2026-11-掌握Git/20-知识/Git.mdTrue不报(本来就合规)
10-项目/!名词解释/20-知识/巡检器.mdFalse不报(容器豁免)

第二行是关键:A13 明确豁免两个容器(它们没有时间盒、指不出「本项目」)。另一个案例是 A4 —— 项目连 00-索引.md 都没有时,A13 直接跳过,只由 A4 报「项目索引缺失」。"没报"有两种可能:真的干净, 或者它这一轮根本没轮到开口;要把 0 当证据,就得知道它什么时候不报。

辨析练习:这个毛病归哪条管?

共 4 例。选择范围:A1 断链、A2 双链失效、A3 孤篇、A4 项目索引覆盖。

1. 一篇笔记从头到尾没有被任何地方链接过。

是 A3 孤篇:断的是"入链",不是路径。修法是在项目索引或项目说明里登记一行链接。

2. 双链 [[冒泡算法]] 变灰点不动,因为文件已改名为"冒泡排序.md"。

是 A2 双链失效:它管 [[名]] 能不能解析到真文件;A1 只管相对路径链接。

3. 新写的知识笔记住在项目 20-知识/ 里,但项目索引页没列它。

是 A4 项目索引覆盖:文件在、链接也可能在,只是没被登记进该项目的目录页。

4. 正文写了 [看这里](<../docs/x.md>),但 ../docs/x.md 并不存在。

是 A1 断链:目标文件不存在 —— 与"有没有人链它"(A3)是两件事。

自测(选项一样长,别从长度上猜)

1. 巡检器与 linter 的分工差别在哪?

对。linter 盯一页之内的排版(标题层级、空行、行宽),巡检器盯页与页之间的关系 (链接通不通、有没有人引用、索引数字对不对)。覆盖面不重叠,谁也替代不了谁。

2. 看到某条检查输出 0 处,能得出什么结论?

对。本机实测:A13 对容器里的词条返回 False 却照样报 0 处,因为容器被豁免; 项目缺索引时 A13 也直接跳过。要把"没报"当证据,得知道它什么时候不报。

3. 下面哪一类问题巡检器能查出来?

对。断链是 A1 的活;A 是事实错误、B 是标签语义(它不管语义)、D 归 markdownlint —— 分属"它查不到"和"不归它管"两类。
