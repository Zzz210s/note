巡检器:给这个笔记库量血压

这节课的胜利:能说清这个库自带的 vault-check 干什么、怎么读它的输出, 以及它和 linter、测试夹具、CI 各自守着哪一段 —— 顺带记住一条纪律:某条检查输出 0 处,不等于它真的查过了。

一句话定位

巡检器是这个笔记库自己写的一套 Python 脚本(50-资源/工具/vault-check/)。 它把"这个库还讲不讲道理"翻译成 14 条可自动判定的检查(A1~A14): 链接通不通、有没有人引用、索引页数字对不对得上、成品知识住没住进项目的 20-知识/…… 跑一次就重算全库,逐条报出 文件:行号 原因,并用退出码表示过不过。

为解什么痛点而生

人眼在几十篇时还行,到两百篇必然漏

痛点:2026-09-22 第一次认真整理这个库时,手工统计出来的数字是断链 13 处、双链失效 29 处、 孤篇 20 篇、元数据违规 25 处。这些问题的共性:不打开每一篇、不逐个点链接就看不见; 而且它们不会让任何东西报错 —— 笔记照样能打开、能提交、能推送。 定义:巡检器就是把这些结构约定写成可执行判据的一组脚本,跑一次重算一次,结论落在退出码上。 大白话:像体检报告 —— 它不判断你身体好不好,只量血压血糖,哪项超标就把那一项和数值指出来。

"有问题"三个字等于没查

痛点:一个全库体检如果只给一句"有问题",等于把排查成本原样丢回给人; 库越大,越需要机器告诉你去哪儿改。 定义:每条问题都是一条 Finding = (检查项, 文件, 行号, 详情), 行号 0 表示"整篇级"问题(如缺 frontmatter、未登记进索引)。 大白话:血压超标得指到哪一项、数值多少;只说"你不太健康"是废话。

检查器自己也要被检查

痛点:检查器写错了比不写更糟 —— 它会安静地放过真问题,还给你一个虚假的"全绿"。 定义:巡检器带 selftest_*.py,在临时目录里造一个假库, 验证"该报的报了、不该报的没报"。 大白话:体检仪自己也要按标准样品校准一遍,才敢信它报的数值。

实测:它跑起来长什么样

在这台机器上真实跑一次(命令与输出原样照抄,2026-09-25):

cd "F:/0-Note/50-资源/工具/vault-check"
PYTHONIOENCODING=utf-8 python -B check_vault.py --quiet
[A1 断链] 0 处
[A2 双链失效] 0 处
...
[A14 索引页一致性] 0 处
结论:PASS        # 退出码 0

再临时造一个坏文件(随手写一条指向 不存在.md 的链接),同一命令立刻改口: 

[A1 断链] 1 处
   50-资源/工具/vault-check/tmp-demo.md:8 不存在.md
[A3 孤篇] 1 处
   50-资源/工具/vault-check/tmp-demo.md:0 无入链
结论:FAIL        # 退出码 1

两组输出对比着看就明白它的脾气:第一段是"分类汇总"([检查项] 命中数), 缩进那行是"一条问题"(文件:行号 详情),最后一行是结论,同时就是退出码。 那个临时文件跑完就删了 —— 这也说明它的结论是现算的,不是攒出来的。

与相近名词的对比

名词它看的是哪一段判据从哪来什么时候跑
巡检器(vault-check)跨篇的结构关系:链接、引用、索引、归属本库自定的 14 条(A1~A14)改完一批笔记后手动跑
linter(markdownlint)单篇的文本格式:标题层级、空行、行宽通用规则集(.markdownlint.jsonc)提交前 / 写笔记时
测试夹具(fixture)某个程序的行为是否等于预期该程序的契约(逐条断言)改完代码后
CI(持续集成)把上面几件事在每次推送时自动跑一遍流水线配置推送 / 提 PR 时

一句话分工:linter 管一页排版,巡检器管整本装订,夹具管某个零件能不能动,CI 管"每次都替我按一遍开关"。 本库目前只有前两者常驻,第三者在别的项目里用。

常见误解

  1. 「巡检器全绿就说明笔记写得好」 —— 它只量结构。 内容对不对、这个链接该不该指那儿、标签该不该打、归档时机对不对,它一概不管; 连"知识该不该住这个项目"也只判"住没住进 20-知识/",搬错项目它不会拦。
  2. 「巡检器和 linter 是一回事」 —— 分工不同:linter 扫单篇文本格式,巡检器扫跨篇结构关系。 两边都干净才叫干净;而且扫 markdown 时给每个路径加 : 前缀强制字面量, 并打印被扫文件数与实物对数,否则括号文件名会被静默漏扫。
  3. 「某条检查输出 0 处,就是全库都过了」 —— 有的检查会短路: A13(来源声明)在项目缺 00-索引.md 时直接不报,由 A4 单独报"项目索引缺失"。 所以"A13 = 0"不能当作来源声明齐备的证据,要验证得直接调判据函数或跑自检用例。

自测(选项一样长,别从长度上猜)

1. 巡检器与 linter 的分工差别在哪?

对。linter 盯一页之内的排版(标题层级、空行、行宽),巡检器盯页与页之间的关系 (链接通不通、有没有人引用、索引数字对不对)。两者覆盖面不重叠,谁也替代不了谁。

2. 看到某条检查输出 0 处,能得出什么结论?

对。0 处有两种可能:真的干净,或者它在这一轮根本没轮到自己开口(如 A13 因项目缺索引而短路)。 要把"没报"当成证据,就得知道这条判据什么时候会不报。

3. 下面哪一类问题巡检器能查出来?

对。断链是 A1 的活;b 是事实错误、c 是标签语义、d 是排版格式 —— 分别属于"它查不到"和"归 markdownlint 管"这两类。
