tmux:一个终端里,住着一整套会话

这节课的胜利:面对「断线任务就死」这件事,能说清终端复用器管的是哪一层 —— 它把「程序在哪儿跑」和「你从哪儿看它」拆开,并在 复用器 / Shell / 终端模拟器 / nohup 之间当场说出分界。

一句话定位

tmux 是终端复用器(terminal multiplexer):由它在后台起一个常驻服务端,服务端里装着若干 会话,会话里装着窗口,窗口里可以再切面板;你面前那个真实终端只是 连上去的客户端,所以关掉它、断开它,里面的程序都照跑 (tmux 官方仓库 · man tmux)。 判定一句话:把这个终端窗口关掉,里面的程序还活不活?活着,它背后就有一个复用器。

它解决的痛点:痛点 / 定义 / 大白话

关掉终端,程序就跟着死

痛点:跑了一小时的编译任务,偏偏这时候网络抖一下、笔记本合一下盖;再连回去,什么都没了 —— 而且它不会留下任何报错,只是安静地不存在了。

定义:在终端里启动的程序是那个终端的子进程,标准输入输出接在一对伪终端(pty)上; pty 另一头由终端程序或远程登录服务端持有,那条通路一断,内核就向程序的进程组投递挂断信号(SIGHUP) (Wikipedia: SIGHUP · Wikipedia: Pseudoterminal)。

大白话:程序一直抓着一根电话线;"挂断"这个名字的原意就是电话线断了;线一剪,它就收到通知,默认动作就是退出。

把「跑」和「看」拆成两件事

痛点:可程序真正需要的,只是一台永远不挂断的终端;谁在看它、从几个窗口看它,是另一回事 —— 这两件事被绑在一起,才有了"断线即死"。

定义:复用器先在后台起一个服务端进程,由它持有虚拟终端;真实的终端窗口只是连上去的 客户端,可断可接,服务端不受影响(Wikipedia: Terminal multiplexer)。

大白话:以前是"你打电话给程序";现在是"程序在值班室里接电话,你不过换了部手机打进去"。 人走灯不灭 —— 这就是分离(detach)。

三层结构:会话 / 窗口 / 面板

层是什么典型动作类比
会话 session一组窗口的容器,由服务端持有新建 / 接回 / 整体结束一间值班室
窗口 window一个占满整屏的虚拟终端新建 / 切换 / 重命名一张桌子
面板 pane窗口内再切出的一块区域横竖切分 / 在格子间跳桌上摊开的几份文件

三层是包含关系:一个服务端带多个会话,一个会话带多个窗口,一个窗口带多个面板。所以「我在 tmux 里」还不够, 通常得再说清是哪个会话的哪个窗口 —— 命令行的做法是给会话起名(如 tmux new -s 名字),不然只剩编号可认。

对比表:四个名字一句话分清

名字一句话判定什么时候它不适用
终端复用器(tmux)托管多个程序,并让它们脱离终端连接活着,还能再连回去看它挡不住重启:机器一重启,服务端与会话一起没了
Shell(bash / zsh)你敲命令的那个解释器,它只是会话里跑着的一个程序它不是窗口程序,也没有"脱离连接"这回事
终端模拟器画字的那层窗口程序(xterm、GNOME Terminal、Windows Terminal)它只管显示与键盘;里面的程序照样跟着它一起死
nohup只让单个命令忽略挂断信号,把输出重定向进文件没有窗口、没有会话:断线后看不到也回不去

一句话分工:终端模拟器管"画",Shell 管"解释",复用器管"活得比连接久"。nohup 是这条路上最小的一步, 只解决"别被信号杀掉",不解决"我还能回去看它"(man nohup); 同族的更早实现是 GNU screen,思路一样,新项目多不再选它(Wikipedia: GNU Screen)。

核心动作:分离与接回

想做的事概念上的说法通用做法(以 tmux 为例)
起一个新会话并起名创建会话tmux new -s 名字
先让它在后台跑着创建时即分离tmux new -d -s 名字
看看还有哪些会话列出会话tmux ls
人先离开,程序继续跑分离 detach前缀键(默认 Ctrl-b)再按 d
回来接着看接回 attachtmux attach -t 名字
一个窗口里并排干两件事切面板前缀键 + %(竖切)或 "(横切)

要点只有一条:分离的那一瞬,里面的进程一点没受影响 —— 它拿着的那个虚拟终端还在服务端手里。 键位与行为都能写在用户配置文件里(默认 ~/.tmux.conf),不改配置也能用默认前缀键 (Arch Wiki: tmux)。

常见误解

  • 「tmux 是终端模拟器」不成立:它是跑在终端模拟器里的程序,负责托管,不负责画字;两者在架构上上下两层。
  • 「在 tmux 里跑就不会死」不成立:会话活在服务端进程里,服务端自己崩了会话跟着没;它防的是"连接断",不是"进程崩"。
  • 「用了它就不怕重启」不成立:服务端和普通进程一样随重启消失;要"开机就在、崩了自起",那是系统服务管理器的活。

辨析练习:这句话说的是哪一层?

共 4 例。选择范围:终端复用器 / Shell / 终端模拟器 / nohup。

1. 关掉本地窗口后重新登录服务器,敲一条命令就能把原来那个带三个面板的界面接回来。

终端复用器:能"分离再接回"就是它的定义特征 —— 连接换了一条,托管没变。

2. 一个窗口程序负责把字符画上屏幕、把键盘输入送进去,窗口一关里面的东西全没了。

终端模拟器:它管"在哪儿看";窗口关掉就是它的连接断了,它不负责让里面的程序活着。

3. 一个程序读入你敲的一行字,把它解释成一条命令,再把结果打回给你。

Shell:解释命令是它全部的活;它自己也只是某个窗口或某个面板里跑着的一个程序。

4. 一条命令加了它,就忽略挂断信号、把输出写进文件,但断线后再也看不到它的界面。

nohup:它只解决"别被信号杀掉",不提供任何可回看的窗口 —— 这正是它与复用器的分界。

自测(选项一样长,别从长度上猜)

1. 关于 tmux 与终端模拟器的分工,哪句对?

对。终端模拟器管"在哪儿看"(窗口、渲染、键盘),复用器管"活得比连接久"(托管会话与窗口), 两者上下两层,不是同一件事的两种叫法。

2. 「关掉本地终端,里面的程序继续跑」靠的是什么?

对。程序抓着的那个虚拟终端不在你手里,而在常驻服务端手里;你断开的只是"客户端 → 服务端"这一跳, 所以程序连"被挂断"都不知道。

3. 下面哪件事终端复用器做不到?

对。会话都住在服务端进程里,重启把服务端一起带走 —— 跨重启要交给系统服务管理器(或靠外部快照工具), 那已经出了复用器的范围。
