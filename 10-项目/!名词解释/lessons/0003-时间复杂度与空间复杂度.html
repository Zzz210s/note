时间复杂度与空间复杂度:一个算法要花的两笔账

这节课的胜利:能说清这两个词各数的是什么,并当场看代码说出它的量级。 读完你就能看懂「这个算法是 O(n log n)、额外空间 O(n)」在说什么,也知道 O(1) 不等于"快"。

一句话定位

它们是同一个问题的两个答案:当输入规模 n 不断变大,这个算法要吃多少时间、额外占多少内存。 共同的语言是大 O 记号 —— 它只留"量级",故意扔掉常数与低阶项,所以不依赖机器、也不依赖具体数据 (Wikipedia: Big O notation)。

两笔账:痛点 / 定义 / 大白话

时间复杂度:不测秒表,看增长趋势

痛点:拿秒表测有两个硬伤 —— 同一段代码在高配机器和单片机上差几十倍;同一个排序, 输入已排好和完全逆序耗时天差地别。测出来的数字没法横向比较。

定义:时间复杂度描述基本操作的执行次数随 n 的增长趋势,记作 T(n) = O(f(n)):存在正数 c 与 n0, 当 n > n0 时 T(n) ≤ c·f(n) 恒成立 (Wikipedia: Time complexity)。

大白话:它是渐近上界 —— "n 足够大时,它顶多按这个量级增长"; 所以系数多少、低阶项是什么,都无所谓。

空间复杂度:数「额外」且「同时活着」的内存

痛点:算法不只花时间,还可能开一大块临时内存;而内存比时间更硬 —— 开不出来就是跑不了。

定义:空间复杂度描述算法运行期间额外申请的内存在同一时刻的峰值随 n 的增长 (Wikipedia: Space complexity)。

大白话:数的是"峰值",不是"全程累加":输入数组本身占的格子不算(那是调用方给的); 递归每深入一层就有一个栈帧同时活着,所以深度 n 的递归空间是 O(n) (Wikipedia: Call stack)。

最好 / 最坏 / 平均:另一根轴

痛点:同一个算法,输入不同复杂度就不同(冒泡排序遇上已排序的数组,一轮就退出了), 只报一个数字会误导人。

定义:它按输入分类 —— 最坏 = 最不利输入下的增长,最好 = 最有利输入下, 平均 = 随机输入下的期望 (Wikipedia: Best, worst and average case)。

大白话:前两个名词数的是"哪种资源",这三个数的是"在哪种输入下数" —— 两根轴正交,别混着背。

对比表:一句话分清,并知道什么时候它不适用

名字一句话判定什么时候它不适用
时间复杂度数基本操作次数随 n 怎么增长同量级内比快慢它给不出结论(常数被扔掉了)
空间复杂度数额外内存的同时峰值只关心时间、或内存宽裕时,它容易被忽略
最坏情况最不利输入下的增长日常表现通常比它好;它给的是安全下限,不是常态
平均情况随机输入下的期望增长输入分布未知时,"平均"没有明确定义
最好情况最有利输入下的增长单独报它没有说服力 —— 拿它当卖点是误导

量级长什么样

量级典型情形一句话
O(1)取数组第 3 个元素、哈希表查一次与规模无关
O(log n)二分查找、平衡树的查找每次砍掉一半
O(n)遍历一遍、线性查找每个元素过一遍
O(n log n)比较类排序(如归并、堆排序)排序主导
O(n²)两两比较、冒泡排序两层循环都随 n 长
O(2ⁿ)枚举子集、朴素汉诺塔每层翻一倍,规模一大就不可用

写复杂度只有三步:数基本操作的次数 → 只留最高阶那一项 → 扔掉系数。 所以 T(n) = 3n² + 100n + 5000 是 O(n²):n 足够大时,最高阶那一项压倒其余全部 (Wikipedia: Analysis of algorithms)。

常见误解

  • O(1) 不等于"快":它只说"不随 n 增长";同为 O(1) 的两个操作,常数系数可以差好几个数量级。
  • O 是上界,不是精确值:说"某算法是 O(n²)"只承诺不会超过这个量级,不代表它一定跑满 n²。
  • 空间不把输入算进去:算的是"额外"那一份;而递归未返回的每一层栈帧都要算。
  • 「快」不是量级的同义词:n 很小时,O(n²) 的实现也可能跑赢 O(n log n)(常数小、开销低)。

辨析练习:这是哪个量级?

共 4 例。选项是量级名;判定靠"基本操作次数随 n 怎么长",不靠实测秒数。

1. 一条链表从头走到尾,每个节点看一眼。

是线性级:一层循环(或一路递归)走完 n 个元素,操作次数与 n 成正比。

2. n 个元素各自再和其余 n 个元素逐对比较一次。

是平方级:两层循环都随 n 增长,n² 次比较 —— 冒泡排序、简单两两对比都是这个形状。

3. 一段代码没有循环、没有递归,只有几个赋值和一次算术运算。

是常量级:操作次数与 n 无关。注意它只说"不随规模变",不说"很快"。

4. 每次把查找范围砍掉一半,所以 100 万条数据最多查 20 次。

是对数级:砍几次才到 1,就是几次操作 —— 2²⁰ ≈ 100 万,所以 20 次。二分查找就是这个形状。

自测(选项一样长,别从长度上猜)

1. 说某算法的时间复杂度是 O(1),它承诺了什么?

对。O(1) 只说"操作次数与 n 无关",不说快慢:常数系数被扔掉了,同是 O(1) 也能差好几个数量级。 「内存占用不随规模变化」说的是空间复杂度那一侧,别把两个词混起来用。

2. 空间复杂度数的是哪一部分内存?

对。两个限定词缺一不可:额外(不含输入)与同时活着(数峰值而非全程累加)。 递归栈帧要算进额外那一份 —— 归并排序就是"栈 O(log n) + 辅助数组 O(n),数组主导 = O(n)"。

3. 同一算法在不同输入下复杂度不同,一般报哪个?

对。面试与竞赛默认报平均或最坏 —— 最坏给出安全下限,平均代表日常; 只有题目专门问"最好情况"时才报最好(冒泡带早退是 O(n),但拿它当卖点没有说服力)。 另外,复杂度是"数出来"的,不靠秒表测量,所以"实测平均""三次均值"都不是它的口径。
