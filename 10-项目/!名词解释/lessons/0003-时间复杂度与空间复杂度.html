时间复杂度与空间复杂度:一个算法要花的两笔账

这节课的胜利:能说清这两个词各数的是什么,以及「最好 / 最坏 / 平均」为什么是另一件事。 读完你就能看懂任何一句「这个算法是 O(n log n)、额外空间 O(n)」在说什么,并知道 O(1) 并不等于"快"。

一句话定位

它们是同一个问题的两个答案:当输入规模 n 不断变大,这个算法要吃多少时间、额外占多少内存。 共同的语言是大 O 记号 —— 它只留"量级",故意扔掉常数和低阶项,所以不依赖机器、也不依赖具体数据, 两条增长曲线一比就能看出谁更扛得住大数据。

为解什么痛点而生

时间复杂度:不测秒表,看增长趋势

痛点:拿秒表测有两个硬伤 —— 同一段代码在你电脑和树莓派上差几十倍;同一个排序, 输入已排好和完全逆序耗时天差地别。测出来的数字没法横向比较。 定义:时间复杂度描述基本操作的执行次数随 n 的增长趋势,记作 T(n) = O(f(n)): 存在正数 c 与 n0,当 n > n0 时 T(n) ≤ c·f(n) 恒成立。 大白话:它是渐近上界 —— "n 足够大时,它顶多按这个量级增长";所以系数多少、低阶项是什么都无所谓, f(n) 是什么量级才要紧。

空间复杂度:数「额外」且「同时活着」的内存

痛点:算法不只花时间,还可能开一大块临时内存;而内存比时间更硬 —— 开不出来就是跑不了。 定义:空间复杂度描述算法运行期间额外申请的内存在同一时刻的峰值随 n 的增长。 大白话:数的是"峰值",不是"全程累加":输入数组本身占的格子不算(那是调用方给的); 递归每深入一层就有一个栈帧活着,递归到第 k 层还没返回,就有 k 个栈帧同时占着内存。

最好 / 最坏 / 平均:另一根轴

痛点:同一个算法,输入不同复杂度就不同(冒泡排序遇上已排序的数组,一轮就退出了), 只报一个数字会误导人。 定义:它按输入分类 —— 最坏 = 最不利输入下的增长,最好 = 最有利输入下,平均 = 随机输入下的期望。 大白话:前两个名词数的是"哪种资源",这三个数的是"在哪种输入下数" —— 两根轴正交,别混着背。

常见误解

  1. 「O(1) 就是快」 —— 它只说"不随 n 增长"。一次操作花 10 秒和花 1 微秒都是 O(1), 因为常数系数被扔掉了;反过来,n 很小时 O(n²) 也可能跑赢 O(n log n)(常数小)。
  2. 空间复杂度要把输入数组算进去 —— 不算。"额外"指的是算法自己申请的内存, 输入是调用方给的;所以原地排序(冒泡)是 O(1) 空间,归并排序要开辅助数组才是 O(n)。
  3. 递归不占空间 —— 每层未返回的调用都有一个栈帧活着;递归扫一条链表深 n 层,空间就是 O(n), n 太大会直接爆栈。

自测(选项一样长,别从长度上猜)

1. 说某算法的时间复杂度是 O(1),它承诺了什么?

对。O(1) 只说"操作次数与 n 无关",不说快慢:常数系数被扔掉了,一次操作可以很慢。 c 说的是空间复杂度那一侧,别把两个词混起来用。

2. 空间复杂度数的是哪一部分内存?

对。两个限定词缺一不可:额外(不含输入)与同时活着(数峰值而非全程累加)。 递归栈帧要算进额外那一份 —— 归并排序就是"栈 O(log n) + 辅助数组 O(n),数组主导 = O(n)"。

3. 同一算法在不同输入下复杂度不同,一般报哪个?

对。面试与竞赛默认报平均或最坏 —— 最坏给出安全下限,平均代表日常; 只有题目专门问"最好情况"时才报最好(冒泡带早退是 O(n),但拿它当卖点没有说服力)。
