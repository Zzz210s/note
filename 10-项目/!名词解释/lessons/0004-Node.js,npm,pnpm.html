Node.js 与三个包管理器:一层跑代码,一层取包

这节课的胜利:把跑代码的那一层与取包的那一层分开, 并说出包会被放在哪几个地方。遇到"装不上 / 找不到模块"时,先判断该查版本、查锁文件,还是查路径。

一句话定位

它们常被并排提起,却不在同一层:Node.js 是运行时(让 JavaScript 在浏览器外执行), npm / pnpm / yarn 是包管理器(把别人的代码取回来、装进项目、写进锁文件记账)。 最省事的辨认办法:看项目目录里躺着哪个锁文件 —— 那一个就决定了这个项目该用哪个工具。

三层角色:痛点 / 定义 / 大白话

Node.js:让 JS 长脚上岸

痛点:JavaScript 起初只能活在浏览器里 —— 想写后端、写命令行工具、写构建脚本,就得换语言。

定义:Node.js 是让 JavaScript 能在浏览器之外运行的运行时环境,基于 V8 引擎构建 (Node.js 官方: Introduction to Node.js)。

大白话:给这门语言装了台通用发动机 —— 原来只能在泳池里游的鱼,现在能上岸跑。

npm / pnpm / yarn:把别人的代码取回来并记账

痛点:早期复用别人的代码靠"手动拷文件 + 口头约定版本",依赖失控、 "在我机器上是好的"成了常态;每个项目再把同一个包真身拷一份,又吃磁盘又慢。

定义:包管理器负责从 registry 取包、安装、升级,并把结果记进 package.json 与锁文件(npm 官方: About npm、 npm 官方: package-lock.json); pnpm 用内容寻址的全机包仓库 + 硬链接装依赖,项目里的 node_modules/ 放的是指向仓库的链接, 依赖树严格按声明来(pnpm 官方: Motivation、 pnpm 官方: 符号链接布局)。

大白话:应用商店加快递员 —— 取包、放进项目、写一张发货单(锁文件)。 pnpm 的差别是"全机只留一份真身,项目里放链接而不是拷贝",顺手把"偷用别人依赖"的路堵死。

npx / corepack / 包仓库:三个配角

痛点:有些命令只想跑一次,不值得装进项目;而不同项目还要求不同版本的包管理器, 手动换版本极易忘。

定义:npx 临时获取并执行一条命令,用完不长期保留 (npm 官方: npx); corepack 按项目声明的版本切换 npm / pnpm / yarn (Node.js 官方: corepack); 包仓库(store)是全机共享的依赖真身存放处,项目里只放链接。

大白话:npx 是"试一下就走"的窗口,corepack 是包管理器自己的换挡杆, 包仓库是"全机共用的仓库",三者都只服务前面两层。

对比表:一句话分清,并知道什么时候它不适用

名字一句话判定什么时候它不适用
Node.js(运行时)它在执行代码装不上包、找不到依赖,它一点都不管
npm / pnpm / yarn(包管理器)它取包并记账(写锁文件)它不执行你的业务代码
npx(执行器)取一次、跑一次、不长期留项目真正依赖的包必须写进 package.json,不能靠它
包仓库(store)它全机只存依赖真身它不参与解析,项目里找不到模块与它无关
corepack(换挡杆)它按项目声明切换包管理器版本项目没声明版本时它无从下手

两条容易踩的认知

  • 全局安装是给命令行用的,不是给 import 用的:模块解析只沿"当前目录往上找 node_modules"(Node.js 官方: Modules), 全局目录不在那条路上 —— 所以"我明明全局装过了"不等于"代码能用它"。
  • 一个项目只用一套锁文件:npm ↔ package-lock.json、pnpm ↔ pnpm-lock.yaml、 yarn ↔ yarn.lock(Yarn 官方: yarn.lock)。 混用会互相覆盖,锁文件来回改。

常见误解

  • 「装了 Node 就等于装了包管理器」:npm / npx / corepack 通常随 Node 一同分发,pnpm 与 yarn 要另外装。
  • 「包管理器是运行时的一部分」:它们是两个独立的版本号,各自升级、各管一件事。
  • 「node_modules/ 与锁文件都要入库」: 锁文件记录"该装哪些确切版本与来源",是可复现的依据,该入库;node_modules/ 是可重建的产物,不该入库。

辨析练习:这句话在说哪一层?

共 4 例。判定靠"它在跑代码、在取包、在借用一次,还是在存放包"。

1. 敲 npx cowsay hi,跑完一次,机器上没多留下什么。

是执行器:定位就是"取一次、跑一次、不长期留";项目真正依赖的必须写进 package.json。

2. 项目里的 node_modules/ 是一堆指向别处的链接,真身全机只存了一份。

是包仓库:它既不取包也不执行,只负责全机保存依赖真身,项目里用硬链接指过来。

3. 敲下 node server.js,一个 HTTP 服务开始监听端口。

是运行时:它在执行代码。npm / pnpm 在这一步完全没有出场。

4. 敲 pnpm add lodash,包进了 node_modules,锁文件也多了一行。

是管理器:取包 + 记账(写进锁文件)正是它的两个核心动作。

自测(选项一样长,别从长度上猜)

1. 四个说法里,哪一个描述的是运行时?

对。运行时负责执行代码:「把别人的代码装进项目」是包管理器,「全机只保存一份依赖真身」是 pnpm 的包仓库, 「临时下载并执行掉一条命令」是 npx —— 四个都在场,只有一个在这层。

2. 一个包用全局方式装过了,这意味着什么?

对。模块解析只沿当前目录往上找 node_modules,全局目录不在那条路上。 「照样导入不到代码」说得太绝(目录下恰好有 node_modules 时也能解析到);「会顶掉本地那一份」与「不占用本机磁盘」是想象出来的行为。

3. node_modules/ 与锁文件,哪个该进版本库?

对。锁文件记录"装哪些确切版本与来源",是可复现的依据;node_modules/ 是可重建的产物。 「两者都不入库也照样能复现」忽略了这样一条:没有锁文件,同一份 package.json 可能装出不同版本。
