UI / UX 速查

问一句话就分完:「它在哪儿」 —— 在屏幕/设备那一层是 UI,在用户经历的整条时间线上是 UX。 再问一句:「换个人还能不能用」 —— 那是可访问性;「这一项易不易学、高不高效」 —— 那是可用性。

分工表(四个词)

名字在哪一层它管什么它保证不了什么
UI屏幕 / 设备表面控件、排版、配色、措辞、即时反馈、状态可见用户能不能真把事办成
UX用户走完的整条时间线入口找得到、流程做得完、错了能恢复像素对齐、圆角大小
可用性UI 的一项质量属性易学、高效、少出错、用着顺等价于整段体验
可访问性换一类使用者之后键盘可达、对比度足够、色觉障碍仍能读出状态一般用户的效率与愉悦

出处:NN/g: The Definition of User Experience —— 「必须把总的用户体验与用户界面区分开」,并且可用性是 UI 的一项质量属性,总体验比它更宽。

行宽换算:一个汉字占满一个 em;拉丁字母平均约半个 em。所以 736px ÷ 17px ≈ 43 个汉字宽, 换成正文字符大约落在 45~90 这个区间的中段 —— 中文排版用「一行 2 个多字母表」来估最省事。

本机实测:这门课自己的配色对比度

算法 = WCAG 相对亮度公式(每通道线性化后按 0.2126 / 0.7152 / 0.0722 加权),对比度 = (L亮+0.05)/(L暗+0.05)。 配色取自 90-模板/teach-assets/lesson.css,背景为纸色 #fdfcf9:

变量色值用途对比度4.5:1
--ink#1a1a1a正文16.96:1过
--no#a33a2a错误态文字6.40:1过
--ok#2f6b3a正确态文字6.23:1过
--accent#7a5c2e链接 / 强调6.02:1过
--muted#6b6b6b次要文字(页眉、页脚)5.19:1过
--rule#d8d4cc分隔细线1.44:1非文字,不受约束

最后一行是这张卡最有用的一条:低于 4.5 不等于违规 —— WCAG 那条管的是文字; 细线、图标底板、纯装饰属于另一档(非文字对比另有 3:1 的口径,且只针对「理解内容所必需」的图形件, 见 W3C: SC 1.4.11)。 别拿一个数字去套所有东西。

症状反查:读起来别扭,先量哪一项

症状先量典型修法
字看得见但读不清文字与底色的对比度加深文字色或换浅底,直到 ≥ 4.5:1
读两行就串行、找不到下一行开头每行字符数(或内容区宽度)收窄内容区到 45~90 字符区间
不知道刚才那下有没有生效有没有可见状态反馈加 loading / 成功 / 失败三态

易混点

  • UI 好看 ≠ UX 好:UI 是必要条件,不是充分条件;影评网站那个例子是标准反例。
  • UX 不等于屏幕上的一切:购买、开箱、售后、客服都在 NN/g 的定义里。
  • 可用性是 UI 的属性,可访问性是底线要求:前者管「好不好用」,后者管「换个人还能不能用」。
  • 可访问性不是「给少数人做的额外版本」:键盘可达、对比度达标对所有人都有效。
  • 主观的体验里有一半是可量的:等待时长、步骤数、对比度、行宽都有标准或经验值。
  • 三种界面形态不改变这套分法:CLI / TUI / GUI 只是「面」的不同形态,UX 依旧在面之外。
