UI / UX 速查

问一句话就分完:「它在哪儿」 —— 在屏幕 / 设备那一层是 UI,在用户经历的整条时间线上是 UX。 再问一句:「换个人还能不能用」 —— 那是可访问性;「这一项易不易学、高不高效」 —— 那是可用性。

分工表(四个词)

名字在哪一层它管什么它保证不了什么
UI屏幕 / 设备表面控件、排版、配色、措辞、即时反馈、状态可见用户能不能真把事办成
UX用户走完的整条时间线入口找得到、流程做得完、错了能恢复像素对齐、按钮圆角
可用性UI 的一项质量属性易学、高效、易记、少出错、满意等价于整段体验
可访问性换一类使用者之后键盘可达、对比度足够、色觉障碍仍能读出状态一般用户的效率与愉悦(它是下限)

出处:NN/g: The Definition of User Experience —— 「必须把总的用户体验与用户界面区分开」,并且可用性是 UI 的一项质量属性,总体验比它更宽; 五项可用性口径见 NN/g: Usability 101。

可用性的五项分量(可逐项查)

分量问的问题
可学性第一次上手要多长时间
高效熟练后完成一次要几步、多长
易记隔一阵再用,还记得怎么操作吗
少错出错的频率与恢复的难易
满意用起来主观上烦不烦

两项容易混的一线之隔:可用性是「把这套界面做好用」,是 UI 的一项质量属性; 可访问性是「换一种能力的使用者还能不能用同一套界面把事办成」,它是下限而不是特殊分支。 同一层上还有一件常被忽略的事:UI 只决定「这一步好不好操作」,整段经历好不好要走完整条路径才知道。

判定表:看到这个,就是这个结论

你观察到的现象结论判据
按钮点下去没有任何可见变化UI 问题(反馈缺失)动作发生了,面上没回话 —— 界面该给人「状态可见」
每一处都好看,但找不到入口UX 问题(信息架构)单点挑不出毛病,整条路走不通
浅灰小字在浅底上,低视力读不出可访问性问题对照 WCAG 那条 4.5:1 阈值可量化
每一步都要重填邮箱可用性问题界面能用,但「高效」这一项不达标

五条可查、可算的阈值

项数值出处
正文文字与背景的对比度(AA)≥ 4.5:1W3C: SC 1.4.3
大号文字(18pt / 24px,或加粗 14pt)≥ 3:1同上
图形件与相邻色的对比度(理解内容所必需时)≥ 3:1W3C: SC 1.4.11
点按目标的最小尺寸(AA)24×24 CSS pxW3C: SC 2.5.8
舒服的行宽45~90 个字符(含空格)Butterick: Line length

对比度是算出来的,不是看出来的:相对亮度按 0.2126 / 0.7152 / 0.0722 三个权重加权, 比值 = (L亮 + 0.05) ÷ (L暗 + 0.05)。于是纯白对纯黑 = 21:1(理论最大), 同一种颜色相叠 = 1:1(看不见)。同一个数,两本账:配色是 UI 的活, 「读得清」是可用性与可访问性的账。

反向提醒:低于阈值不等于违规。WCAG 那条 4.5:1 管的是文字; 分隔细线、纯装饰底板不在它的射程里(非文字件另有 3:1 的口径,且只针对「理解内容所必需」的图形件)。 别拿一个数字去套所有东西。

症状反查:读起来别扭,先量哪一项

症状先量典型修法
字看得见但读不清文字与底色的对比度加深文字色或换浅底,直到 ≥ 4.5:1
读两行就串行、找不到下一行开头每行字符数(或内容区宽度)收窄内容区到 45~90 字符区间
不知道刚才那下有没有生效有没有可见状态反馈加 loading / 成功 / 失败三态
知道要干什么,就是找不到入口导航与命名(信息架构)把入口放进用户会先看的路径上
颜色一换,信息就读不出来是否只靠颜色表意配色 + 形状 / 文字双重编码
键盘用户走到一半走不动Tab 顺序与焦点可见性补焦点样式、按阅读顺序排 Tab
手机上老点错点按目标的尺寸与间距撑到 24×24 CSS px 以上,目标之间留间距

易混点

  • UI 好看 ≠ UX 好:UI 是必要条件,不是充分条件;影评网站那个例子是标准反例。
  • UX 不等于屏幕上的一切:购买、开箱、售后、客服都在 NN/g 的定义里。
  • 可用性是 UI 的属性,可访问性是底线要求:前者管「好不好用」,后者管「换个人还能不能用」。
  • 可访问性不是「给少数人做的额外版本」:键盘可达、对比度达标对所有人都有效。
  • 主观的体验里有一半是可量的:等待时长、步骤数、对比度、行宽、点按尺寸都有标准或经验值。
  • 三种界面形态不改变这套分法:CLI / TUI / GUI 只是「面」的不同形态,UX 依旧在面之外。

相邻术语

术语一句话与这两个词的关系
人机交互(HCI)研究人与计算机如何相互作用的学科UI / UX 都是它的研究对象:HCI 是学科,UI / UX 是对象
交互设计设计「操作 → 反馈」这一来一回的动作序列落在 UI 与 UX 的接缝上:动作发生在 UI,效果体现在体验里
信息架构内容怎么分类、怎么命名、怎么被找到「界面很漂亮但找不到入口」往往是它失手
可用性测试找人真用一遍、把卡住的地方记下来量 UX 的主要手段;它测过程,不测像素
设计系统一套可复用的组件 + 规范 + 令牌把 UI 的重复决策固化,顺带保住可访问性的下限

一句总结:UI 是那一层看得见的表面,UX 是用这层表面走完的整段路 —— UI 做砸了 UX 一定好不了,UI 做满分 UX 仍可能不及格。
