CLI / TUI / GUI 速查

判定顺序:先看屏幕上画的是什么(字符流 / 字符画出的面板 / 像素),再看你怎么操作(敲完整命令 / 键盘选项 / 鼠标点选)。两者都指向同一个答案时才下结论。

判定表:看到这个,就是那个

你观察到的现象结论判据
只有一个提示符和一行行输出,靠成套命令推进CLI没有全屏面板,程序一次只回一段文本
黑框里画出边框、列表、当前选中项的高亮TUI用字符画出了"面板",通道仍是文本
有窗口、菜单、图标、滚动条,指针能点GUI界面由像素画成
它的输出能被 | / > 接走喂给下一条命令至少含 CLI 通道能接走的前提是输出为文本流
SSH 里用着顺手,几百 KB 的网速就够CLI 或 TUI只传字符,不传画面
远程用起来卡顿、鼠标漂移GUI远程桌面一帧帧传画面
同一款软件既有菜单又能写命令调用多通道并存界面形态是通道,不是软件的类别标签

三个反例(最容易判错的地方)

  • 「黑框 = CLI」不成立:终端窗口里敲 code .,打开的是 GUI 编辑器;黑色只是配色。
  • 「能用鼠标 = GUI」不成立:vim 支持鼠标点光标,它仍是 TUI(字符画出的面板)。
  • 「命令行 = 某个程序」不成立:命令行是你敲字的那一行,不是软件名。

终端 / Shell / 命令行:三个词不在同一层

这张表是概念层次,不是形态分类 —— 终端模拟器本身是窗口程序,形态上算 GUI;它里面跑着的 Shell 与 CLI 才是文本通道。

词它是什么常见例子
终端(terminal)那个窗口:把键盘输入送进去、把字符画出来Windows Terminal、iTerm2、GNOME Terminal
控制台(console)历史上指物理操作台;现在多与「终端」当同义词用不必纠结,见到就按终端理解
Shell窗口里跑着的解释器:听懂命令、启动别的程序bash、zsh、PowerShell
命令行你敲字的那一行位置,不是程序提示符 $ 之后
CLI 程序被 Shell 调起来的干活的程序git、npm、python、ls

串起来读一句:你打开「终端」→ 里面跑着 Shell → 你在「命令行」上敲字 → 调用各种 CLI 程序;如果那个程序的界面是画出来的,它就是个 TUI。

常见实例(帮你对号入座)

形态判据一句话常见例子
CLI只有文本流,一次一条命令bash、git、npm、python、gcc
TUI用字符画出面板,键盘推进vim、htop、lazygit、ncdu
GUI用像素画出窗口,指针点选浏览器、VS Code、文件管理器、Windows Terminal

注意最后一行里的 Windows Terminal:它是终端模拟器,自己是个窗口程序(形态上算 GUI), 它里面跑着的 Shell 与 CLI 程序才是文本通道 —— 这就是「概念层次」与「界面形态」两根轴相交的地方。

三形态横向对比(按维度查)

维度CLITUIGUI
操作方式键盘打字键盘为主 + 可选鼠标鼠标 / 触摸
学习门槛最高中最低
熟练后速度最高高中
功能发现性最弱(得先知道)中最强(菜单可见)
自动化 / 脚本最强弱几乎不行
可复现 / 可分享最好(一条命令)中差(「你点第 3 个按钮」)
远程(SSH)最好(只传文字)好很差(传画面)
资源占用最低低高
图形 / 多媒体无无(字符画)强

很多软件同时提供三种外壳:VS Code 是 GUI,但内置终端(CLI)、命令面板(TUI 味),还能 code . 从命令行调用; Git 有 git(CLI)、lazygit(TUI)、图形客户端(GUI)。所以三形态是层次关系,不是替代关系 —— 后两者的内部往往也在调用命令行。

典型符号与按键

类型记号含义

>把输出写进文件
--help大多数 CLI 自带的用法说明

GUI无通用记号交互靠视觉位置(菜单、按钮、拖放)

怎么选(三条经验法则)

  1. 一件事要在界面里重复点超过 3 遍 —— 去找它的命令写法。
  2. 要留下文字记录、要给别人复现、要写进脚本 —— 用 CLI。
  3. 要边看状态边操作(监视、逐项确认) —— TUI 最省事;画图、排版、多窗口对照 —— GUI。
