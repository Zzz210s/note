夹具 / 替身 / 测试数据速查

先问一件事:它在整套测试里扮演谁。管"开演前的舞台"的是夹具;替某个外部依赖上场的是替身(mock / stub / fake / spy / dummy);喂进去的原料是测试数据。三者不并列 —— 替身常被装进夹具里,数据常由夹具准备。

判定表:一句话认出它

名字一句话判定它提供什么典型形态
夹具(fixture)它把开演前的舞台摆成固定位置确定的环境 / 状态 / 样例输入(含准备与收尾)setUp/tearDown、@pytest.fixture、临时目录、假库
dummy它只为填参数,没人打算碰它一个占位的空对象 / 空值传进去就被忽略的占位参数
stub它会念写死的台词固定的返回值 / 固定状态read() -> "OK" 之类的死值
fake它有真本事但走捷径能用的替代实现内存数据库、本地假对象替远端服务
spy它包在真货外面记账,本体照跑调用记录,而真实行为不变包装函数、录制调用次数与参数
mock它自带期望,不合就自己判失败预置的交互契约(次数 / 参数 / 顺序)单元测试里的 mock 对象与验证
测试数据它是喂进去的原料,不是机制一批数据本身样例文档、坏配置、边界值表

组合关系:stub / fake / spy / mock 是"某一个外部依赖装得像不像",夹具是"整台机器的初始状态" —— 所以替身通常由夹具准备出来、再注入被测代码。

这个词借自机械加工:车床上的工件不能用手按着加工,得用夹具把它固定在确定位置 —— 位置固定了,刀具每次走的路径才有意义,加工结果才能重复;换个工件装进同一个夹具,就能用同一套程序加工。 软件测试借的是同一个隐喻:把被测对象的前置条件固定住,让每次运行具有可比性。

这个词在不同场合指三层不同的东西,先认清是哪一层:

层次一句话典型形态
① 前提(经典含义)测试前把系统置入确定状态、测完恢复原状初始数据、临时目录、环境变量、起好的服务
② 样例文件预先准备好的一组输入样本,用来触发特定分支小仓库、样例文档、坏配置
③ 可独立运行的测试脚本把前提、调用与一组断言打包在一起,跑完报 PASS=n FAIL=m自包含的 runner 脚本

区分一句话:①②是前提 / 原料,③是把前提和检查打包在一起的那套装置。

与相邻测试类型的关系

术语一句话与夹具的关系
单元测试针对最小代码单元(一个函数)的测试常需夹具提供初始数据
集成测试验证多个组件协同是否正确夹具更重(要起服务、建临时目录)
端到端(E2E)从用户入口到尾端结果的完整链路夹具 = 整套环境
冒烟测试只验证「主要功能还能跑起来」的最小集合可看作夹具的一个子集
断言一条「结果必须等于 X」的判定夹具运行器的组成单元

一句话总结:夹具负责把前提固定住,断言负责逐条问对不对,运行器负责跑完收口报数。

失效场景:它的结论什么时候不能信

名字什么时候它的结论不能信
夹具(fixture)夹具自己写错 → 误报;夹具被放宽 → 把风险藏起来。报红先分"夹具错"还是"被测代码错",不许先改夹具
dummy被测代码一旦真的用了它,行为就是未定义的(它本来就没打算被用)
stub它在替你的代码回答 —— 死值本身错了,测试照样全绿
fake它自己也有 bug,而且"与真实现的差异"会随真实现演进而悄悄积累
spy只观察不隔离:依赖还是真的,离线场景根本跑不起来
mock期望钉死了交互细节,实现一换写法就红 —— 测的是实现印记,不是行为
测试数据数据自己不合法,或压根覆盖不到目标分支

一个夹具长什么样(结构,而不是某一份具体代码)

不管用什么框架,一个夹具都只有三段:准备(把环境置为确定状态)→ 断言(逐条声明期望)→ 收尾(恢复原状)。三段写在同一处,跑完报"过了几条、错了几条"。

段做什么不做会怎样
准备(setUp)建临时目录 / 连干净数据库 / 造样例输入结果随上次运行的残留而变,"时好时坏"
断言逐条声明"此处应当是 X"只剩"我觉得应该没问题"
收尾(tearDown)删临时文件 / 关连接 / 还原状态污染下一次运行,测试顺序互相干扰

怎么读「过了几条 / 错了几条」

  • n 是逐条通过的断言数,m 是不通过的条数;m ≠ 0 就是失败。
  • 逐条打印的那一行说明才是定位信息 —— 只有汇总数字说不清哪一条红了。
  • 断言失败时应当当场报出"期望多少、实际多少",并以非零退出码收场,这样自动化流程才能据此判红。
  • 夹具能证明的是逻辑与契约,证明不了"真机上真的能跑";没跑过的必须在脚本头与文档里显式声明。

易混点

  • mock 不是夹具:mock 是替身,范围小得多;它常被夹具准备好后注入。
  • stub 与 fake 的分界:stub 是"死值"(不实现逻辑),fake 是"能用的简化实现"。
  • spy 与 mock 的分界:spy 默认跑真的、只记录;mock 自带期望、自己判失败。
  • 测试数据不是替身:它是输入,替身是"假的依赖"。
  • 同一个词在不同报告里可能是另一层含义:见到"夹具"先问它指前提、样例,还是那个 runner。
