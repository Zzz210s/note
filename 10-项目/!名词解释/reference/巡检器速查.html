巡检器(A1~A14)速查

它只做一件事:把"这个库还讲不讲道理"翻译成 14 条机器可判定的检查,跑一次重算全库,逐条报 文件:行号 原因,并把结论放进退出码。读它只读三样:哪条、几处、行号。

命令与退出码

cd "F:/0-Note/50-资源/工具/vault-check"
PYTHONIOENCODING=utf-8 python -B check_vault.py            # 全量:分类计数 + 逐条问题 + 提示
PYTHONIOENCODING=utf-8 python -B check_vault.py --quiet    # 只要分类计数 + 结论(缩进明细被压掉)
PYTHONIOENCODING=utf-8 python -B check_vault.py --json     # 机器可读,喂给别的脚本
# 缩进那行“文件:行号 原因”是 if not args.quiet 里打的,所以 --quiet 只剩分类计数
退出码含义怎么用
0全库无问题check_vault.py --quiet || echo "库里还有问题" 可接进脚本
1至少一条真问题看缩进行里的 文件:行号 原因 定位

输出三层:分类汇总([A1 断链] 1 处)、逐条问题(缩进一行,行号 0 表示整篇级)、结论(最后一行 结论:PASS / FAIL)。

症状反查:看到什么,是哪条在报

A1~A14 各查什么

编号查的是判据要点
A1 断链相对路径链接的目标是否存在跳过 http/#/mailto;代码块先被抹白再扫
A2 双链失效[[名]] / [[目录/名]] 能否解析到真文件裸名按文件名命中,带路径的按路径后缀命中(库里有 18 个同名 !项目说明.md)
A3 孤篇全库没有任何入链的笔记裸双链只在"该名全库唯一"时才算数
A4 项目索引覆盖项目 20-知识/ 每篇都出现在项目索引里有 20-知识 却缺 00-索引.md 时另报「项目索引缺失」
A5/A6 元数据缺 frontmatter / type 非 8 种规范值 / status 非 4 种 / 字段数 > 8根索引、90-模板、!问题追踪 等豁免
A7 路线一致性根索引的路线与 10-项目 双向一致,项目状态与产出相符有产出的项目不能停在 todo
A8 标签规范同一标签的全库大小写冲突不误伤 Linux / RFID 这类按官方写法保留的专名
A9 索引页统计项目统计行与根汇总行必须与实物一致统计行须落在文件前 8 行
A10 知识归属成品知识是否住进项目 / 容器的 20-知识/裸 10-项目/20-知识/ 没有归属,照报;只查知识类 type
A11 教学工作区三件套齐不齐、课有没有登记、课件引用的本地文件在不在、容器词条有没有对应课删掉任一份也逃不掉管辖;容器与学习项目同一套判据
A12 归档判据40-归档/ 的项目必须在根索引留一行登记归档物从入口消失就成了找不回来的死文件
A13 双向链接项目知识笔记必须声明自己的来源项目两个容器与没有 !项目说明.md 的目录豁免
A14 索引页一致性根索引要逐行列全子目录;项目索引的链接数要等于实物数缺索引 / 未登记 / 统计行分别归 A4/A4/A9,它不重复报

不属于它的两样东西

东西它管什么为什么不在这里
提示通道可归档:<项目>(A12)、根索引未创建(A14)只是"该有人动手了",打印在独立小节,不进 FAIL 计数、不影响退出码
单篇排版标题层级、空行、行宽归 markdownlint(linter);巡检器只看跨篇关系

夹具在临时目录里造一个假库,验证两件事:该报的报了、不该报的没报。没有自检的检查器比没有检查器更危险 —— 它会给一个虚假的全绿。

一个坏文件同时被三条抓住,每条都指到同一个文件的同一行 —— 这就是"能定位"与"只说有问题"的差别。结论是现算的,不是攒的。

边界:0 处不等于"查过了"

  • A13 对容器豁免:直接调 declares_project(路径, 文本, 项目名) 实测 —— 学习项目的 Git.md 返回 True;容器的词条 !名词解释/20-知识/巡检器.md 返回 False,而 A13 照样报 0 处(容器没有「本项目」可指)。
  • A4 会短路:项目连 00-索引.md 都没有时,A13 不重复报,只由 A4 报「项目索引缺失」。
  • 要把"没报"当证据,就得知道这条判据什么时候会不报 —— 否则直接把判据函数拎出来单跑一次。

易混点

  • 它是静态检查,不跑笔记里的代码:查的是结构与格式,查不到事实错误、语义对不对。
  • 它和 linter 谁也不替代谁:一个管跨篇关系,一个管单篇排版。
  • 全绿只说明"结构自洽":链接该不该指那儿、标签合不合适,它一概不管。
  • 源文件都守 ≤200 行:加不动了就按主题拆新文件(checks_extra.py 当年就是这么来的)。
