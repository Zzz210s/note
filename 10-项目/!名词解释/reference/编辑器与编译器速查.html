编辑器 / 编译器 / 解释器 / IDE 速查

只有一个问题需要回答:它在链路里干什么活。改文本是一层、把文本变成能跑的东西是另一层、把前两层打包成工作室是第三层。名字混起来,几乎都是把不同层当成了同一件事。

判定表:看到这个,就是那个

你观察到的现象结论判据
它让你写、让你改,但从不判断代码对不对编辑器只碰文本层
整份读完,产出一个新文件;改一行要重来一遍编译器先翻译完,再统一执行
逐句读、当场执行,不留下可执行产物解释器边翻边跑
一个界面里集齐编辑、运行、调试、项目管理IDE集成外壳,把前两层包起来
装了它,代码还是跑不起来只装了编辑器层缺执行层
点了「运行」按钮却报找不到 python / gcc集成外壳在替你调用执行层按钮本身不执行代码,它去喊执行层
报错信息里有 error: 和行号编译器在跟你说话解释器则是在跑到那一句时才报错

本机实测(2026-09-25 23:44,原始输出)

# 源文件 → 可执行文件:两件完全不同的东西(sum.c 是 8 行 C 源码)
$ ls -l sum.c
-rw-r--r-- 1 23652 197609 132  9月 25 23:44 sum.c
$ file sum.c
sum.c: C source, ASCII text
$ gcc sum.c -o sum.exe && ls -l sum.exe
-rwxr-xr-x 1 23652 197609 53026  9月 25 23:44 sum.exe
$ file sum.exe
sum.exe: PE32+ executable for MS Windows 5.02 (console), x86-64, 16 sections
$ ./sum.exe
10
# 解释器也有编译这一步,只是产物是内部字节码,不是可执行文件
$ ls -l tiny.py
-rw-r--r-- 1 23652 197609 11  9月 25 23:44 tiny.py
$ python -m py_compile tiny.py && ls -l __pycache__/
total 1
-rw-r--r-- 1 23652 197609 138  9月 25 23:44 tiny.cpython-314.pyc
$ python -c "import dis; dis.dis('x = 1 + 2')"   # 第二行那个空行也是输出的一部分
  0           RESUME                   0

  1           LOAD_SMALL_INT           3
              STORE_NAME               0 (x)
              LOAD_CONST               1 (None)
              RETURN_VALUE

字节码里没有加法这一步 —— 常量在装进文件之前就被折叠掉了: 1 + 2 已经变成 LOAD_SMALL_INT 3。这就是"编译发生在运行之前"的直接证据。

数值对照

对象大小类型谁产出的
sum.c132 BC source, ASCII text编辑器写下的人类文本(8 行)
sum.exe53026 BPE32+ executable, x86-64gcc(编译器)
tiny.py11 BPython script, ASCII text编辑器写下的人类文本

产物比源文件大约 400 倍(本轮 53026/132)—— 因为里面装的是机器指令、启动代码与程序头,不再是你能读的文本。 绝对字节数随编译器版本与源码内容变,量级关系不变。

易混点

  • VS Code 出厂是编辑器;装了语言插件后能做补全、跳转、调试,和 IDE 的边界才变模糊 —— 那是"装上插件之后"。
  • 本机 装了两套 JetBrains IDE:where.exe idea64 答 E:\0-IntelliJ IDEA 2025.1.2\…\bin\idea64.exe, where.exe webstorm64 答 E:\0-WebStorm 2025.3.4\…\bin\webstorm64.exe。C:\Program Files\JetBrains 不存在, 但它不能当"没装 IDE"的证据 —— 查一个目录不算查过,要直接 where.exe <可执行名>。
  • 装的 JetBrains 是完整 IDE;VS Code 装上语言插件后也能补全 / 跳转 / 调试,那才是"插件拼出来的像 IDE"。
  • 调试器、Linter、语言服务器、构建工具是配套角色,不在这四层里;IDE 只是把其中几个收进同一个界面。
  • 「Python 是解释型语言」说的是默认实现 CPython 的执行方式,不排除别的实现先编译。
