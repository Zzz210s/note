前端 / 后端 / 接口 速查

判定表:看它跑在谁的地盘上

你看到的现象它属于典型代表
浏览器开发者工具里能看到它的代码前端HTML / CSS / JavaScript 组成的页面
代码在别人的服务器上跑,你看不见后端处理登录、下单、发邮件的服务
给的不是页面,而是一段数据接口(API)返回 JSON 的网址
只有数据,没有规则数据库存用户、订单的表
页面在发布前就生成好了静态站点(SSG,见另一课)发布一堆 .html 文件

三问定位法

任何一个功能都可以问这三句:

  • ① 这份逻辑跑在谁的机器上?你的浏览器里 = 前端;服务器上 = 后端。
  • ② 它产出的是画面,还是数据?画面 = 前端;数据 = 后端或接口。
  • ③ 两边靠什么说话?接口 —— 前端不认识数据库,只认识接口。

典型技术栈(按角色查)

角色干什么常见名字
前端把数据画成界面、处理点击与输入React / Vue / Svelte
后端校验规则、拼装数据、调用别的服务Node.js / Python / Go / Java
接口约定"问什么、答什么"REST / GraphQL / gRPC

症状反查:出现这个,先查那一处

症状多半是
改一个按钮颜色,还得重新发布服务器样式被写进了后端模板 —— 本该在前端
手机 App 里又抄了一遍同样的业务规则规则没沉到接口后面,被复制到了每个前端
页面白屏,但接口返回正常前端拿到数据却没画出来(前端的问题)
页面能打开,数字是旧的一直不变后端或缓存的问题,不是前端

易混点

  • 前端 ≠ 美化。它还包括状态管理、性能、可访问性 —— 一个复杂页面的前端代码往往比后端还多。
  • 后端 ≠ 数据库。数据库只存数据;规则、校验、编排都在后端。
  • 接口 ≠ 只有 REST。REST 只是一种风格;GraphQL、gRPC 也是接口。
  • 前后端不是"两台机器",而是"两个地盘"。它们可以跑在同一台机器上,只是分工不同。
  • 静态站点会模糊这条线(页面在发布时生成,不在请求时算)—— 见 0017 · SSG 与 0016 · 静态部署与其它部署。
