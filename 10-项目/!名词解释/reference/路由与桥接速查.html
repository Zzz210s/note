路由模式 / 桥接模式速查

只问三个问题:谁在拨号 → 谁在做 NAT → 谁发 IP(DHCP)。 再加一条辅助判据:两边在不在同一网段。四个答案都齐,这台设备处在哪一态就定了。

三问判定表

问题路由模式(NAT)桥接模式
谁在拨号?它自己(PPPoE,拿到运营商给的地址)不是它 —— 连拨号都不参与
谁在做 NAT?它自己没有人做地址转换
谁发 IP(DHCP)?它自己上游那台设备(通常就是路由器 / 光猫)
两边的地址不同网段(WAN 侧 / LAN 侧各一个)同一网段,掩码也一致

四态对照表(同一组问题在虚拟化里的四种答案)

模式一句话判定局域网里别人看它典型用途
桥接(Bridged)并进同一个二层网络,IP 由上游发看得见,能直连虚拟机当服务器、要被抓包 / 被访问
NAT(路由式)走宿主这个中间人出去看不见上网、装包、日常开发
仅主机(Host-only)只有宿主与它能互通,宿主上的虚拟网卡类似回环看不见干净的内部测试网
内部网络(Internal)只有被点名的虚拟机互通,连宿主都进不来看不见隔离实验、集群互联

取舍的官方口径(VirtualBox 手册 第 6 章): 桥接「直接与物理网卡交换数据包,绕过宿主操作系统的网络栈」——局域网能直连它,宿主的防火墙 / 代理却不再管它; 仅主机是「创建一块虚拟网络接口(类似回环接口)」,所以天生通不了外网。

症状反查:看到这个,就是这个结论

观察到的现象结论判据
虚拟机 / WSL 里 ip route 的默认网关,是宿主上某块虚拟网卡的地址NAT(路由式)下一跳落在另一个网段的一台设备上
虚拟机的 IP 与手机、笔记本同网段,路由器认得它桥接地址由上游 DHCP 发,网段没变
能上外网,但局域网里另一台机器连不上它,也没配端口转发NAT外面只看得见中间人,入站要显式放行
只能与自己的宿主互通,上不了外网仅主机地址与物理网络不重叠,没接第二块网卡
两台虚拟机互通,连宿主都访问不到它们内部网络只有被点名的成员在这张网里
tracert 第一跳是某个内网地址那台设备在做转发 / NAT第一跳 = 你这侧第一个会转发包的设备
光猫不拨号、不发 IP,路由器拿到了公网地址光猫桥接 + 路由器路由三个问题全落在路由器身上
端口转发配了一层仍不通,日志里出现两次内网地址双重 NAT光猫也做了一次 NAT,需在两台设备上各配一次
局域网里的设备发现不了它(mDNS / 广播收不到)它不在同一个二层网络里广播不过路由器,只过桥

读法:WSL 的默认网关 192.168.192.1 与 Windows 上那块 WSL 虚拟网卡的地址是同一个 —— Windows 就是 WSL 的网关与 NAT。两个网段 192.168.1.0/24 与 192.168.192.0/20 互不相干,跨段必有中间人。

可达性实验:外面能不能主动连进来

$ wsl.exe -e bash -lc "python3 -m http.server 8899 --bind 0.0.0.0 &"   # WSL 里起监听
$ curl -s -o /dev/null -w "%{http_code}\n" http://192.168.203.127:8899/  # Windows -> WSL
200
$ curl -s -o /dev/null -w "%{http_code}\n" http://192.168.1.10:8899/     # Windows -> 本机的局域网地址
000                                                                      # curl: (7) Failed to connect
$ netsh interface portproxy show all                                     # 空:没配过任何入站转发

200 证明宿主能直达 VM(它就是网关);000 证明 VM 的服务没有出现在这台机器的局域网地址上。 要让外面访问,得显式做端口转发或换网络模式 ——「外面看不见我」是 NAT 的代价,也是它默认安全的理由。

改 WSL 的网络模式(%UserProfile%\.wslconfig)

networkingMode含义备注
nat默认:独立私有网段 + 宿主机做 NAT写别的非法值时也回落到它
bridged并进宿主所在的二层网络自 WSL 2.4.5 起标记为 deprecated,别新用
mirrored把 Windows 的网卡镜像进 Linux官方现在推荐的方向;localhost 两边直通

本机 C:\Users\23652\.wslconfig 不存在 → 用的是默认 nat。出处: Microsoft Learn: WSL 高级设置。 另外 WSL 的 DHCP / DNS 默认由宿主代管(dnsTunneling / dnsProxy),这也是上面出现 10.255.255.254 的原因。

易混点

  • 名字不算数:家用「路由器」里的交换芯片在做桥接,很多「路由器」实际被当交换机 / AP 用 —— 看谁在跨段转发。
  • NAT 与路由是两个动作:纯转发不做转换照样合法,专线场景常常只打通二层。
  • 桥接不等于更快:它换来的是「被局域网看见」;代价是绕过宿主网络栈、失去隔离。
  • localhost 能通不代表没有 NAT:那是宿主做的转发(localhostForwarding),与「外面能不能直连」是两件事。
  • 判网段要看掩码:192.168.203.127/20 与 192.168.192.1 属于同一段(192.168.192.0/20),只看地址会误判。
  • tracert 会被本机代理污染:本机跑着 TUN 代理时,对公网地址的第一跳会直接是目标地址,没有参考价值。
