时间复杂度 / 空间复杂度速查

先问数哪种资源(时间 / 额外内存),再问在哪种输入下数(最坏 / 平均 / 最好)。两根轴正交,别混着背。写复杂度时只留最高阶、扔掉系数与低阶项。

判定表:看到这个写法,就是这个量级

代码特征时间复杂度为什么
没有循环、没有递归,只有赋值与算术O(1)操作次数与输入规模无关
每次把查找范围砍掉一半(二分)O(log n)砍几次才到 1,就是几次操作
一层循环,或一条链表走到底O(n)每个元素过一遍
先排序(比较排序),再线性扫一遍O(n log n)排序主导,后面的线性项被扔掉
两层循环都随 n 增长(两两比较)O(n²)n 个元素各自再扫 n 个
每个元素分两支递归(子集、汉诺塔)O(2ⁿ)每层翻一倍
嵌套里有一个是常数(固定 26 个字母)降一阶常数层不随 n 增长,算 O(1) 因子

手算三步

  1. 数基本操作的执行次数,写成 n 的式子(一层循环加一项)。
  2. 只留最高阶那一项:n² + n + 5 → n²。
  3. 扔掉系数:3n² → n²。

所以 T(n) = 3n² + 100n + 5000 是 O(n²):n 足够大时,最高阶那一项压倒其余全部。

喻体拿最上面一本二分翻字典每本看一眼优秀的排序两两比较宇宙寿命也跑不完

量级与常数是两件事

O(1) 只承诺"操作次数不随 n 增长",它不是"快"的同义词:两个都记作 O(1) 的操作, 一个可能是寄存器里的加法,另一个可能是发一次网络请求 —— 相差几个数量级,却都符合 O(1) 的定义。 常数系数被大 O 扔掉了,所以要在同一量级里挑实现时,量级表帮不了你,只能去看实测或实现细节。

反过来,量级的威力只有在 n 变大时才显出来:把 n 翻一倍,O(n) 的耗时大致翻倍,O(n²) 大致翻四倍 (因为 (2n)² = 4n²),O(2ⁿ) 则直接翻倍再翻倍。所以"哪个更快"要先问"n 有多大":n 很小时, 常数小的 O(n²) 可能跑赢 O(n log n);n 一大,量级就压倒一切。

空间数的是哪一份

别数要数
输入数据本身占的内存(那是调用方给的)算法额外申请的内存
全程累加过的每一块临时内存同一时刻同时活着的峰值
程序的历史峰值递归未返回的每一层栈帧都要算

典型取值:原地交换 = O(1);辅助数组 = O(n);递归深度 n = O(n) 栈帧(太深会爆栈);归并排序取大的那份 = O(n)。

最好 / 最坏 / 平均:另一根轴

说法说的是什么时候报
最坏情况最不利输入下的增长默认报它:给安全下限
平均情况随机输入下的期望增长日常表现,常与最坏同阶
最好情况最有利输入下的增长只有被专门问到时才报

易混点

  • O(1) ≠ 快:同量级的两个操作,耗时可以差好几个数量级;n 很小时 O(n²) 也可能跑赢 O(n log n)(常数小)。
  • 空间不把输入算进去:算的是"额外"那一份。
  • 递归占空间:每层未返回的调用都有一个栈帧同时活着。
  • O 是上界:说"某算法是 O(n²)"不等于它一定跑满 n²,只承诺不会超过这个量级。
