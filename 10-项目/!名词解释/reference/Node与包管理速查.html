Node.js / npm / pnpm 速查

按顺序问三个问题:这一层是跑代码还是取包 → 包存在哪一份 → 锁文件是谁写的。三个都有答案,「装不上 / 找不到模块」该往哪查就定了。

分工表(一层一个角色)

名字在哪一层一句话职责
Node.js运行时让 JavaScript 在浏览器外执行
npm包管理器从 registry 取包、装包、写 lockfile 记账
npx包执行器临时获取并执行一条命令,用完不长期留
pnpm包管理器全机共享内容寻址仓库 + 硬链接 + 严格依赖树
yarn包管理器npm 的另一个替代品,老项目里常见
corepack包管理器的换挡杆按项目声明的版本切换 npm / pnpm / yarn
nvm / fnm / voltaNode 版本切换器一台机器上并存多个 Node 版本,按项目 / 目录切

配套概念(它们不是软件,是约定与文件)

概念一句话缺了它会怎样
package.json项目的身份证 + 购物清单:元信息、依赖范围、可跑脚本别人不知道要装什么、怎么跑
lockfile精确到最小版本的购物小票同一份 package.json 在不同时间 / 机器装出不同结果
node_modules/收货仓库:包的真身堆在这里import / require 找不到东西
registry商店地址:提供包下载服务的远程仓库包无处发布、无处获取
语义化版本主版本.次版本.修订号 的编号约定升级时无从判断会不会改坏你

用一句话串起来:Node.js 是发动机,npm / pnpm 是应用商店 + 快递员,package.json 是购物清单,node_modules/ 是收货仓库。

判定表:看到这个,就是这个结论

你观察到的现象结论判据
目录里只有 package-lock.json这个项目用 npm锁文件与包管理器一一对应
目录里是 pnpm-lock.yaml这个项目用 pnpm同一项目别混用两套锁文件
目录里是 yarn.lock这个项目用 yarn见到就跟着它,别换
跑过 npx cowsay hi,机器上没多装东西临时执行器在工作npx 只取一次、执行完就走
import pako 报 MODULE_NOT_FOUND,但 npm ls -g 里明明有全局装的包不在模块搜索路径里全局是给命令行用的,不是给 import 用的
package.json 里有 "packageManager": "pnpm@…"corepack 照它切版本声明是给 corepack 读的
node_modules/ 里是一堆符号链接pnpm 的布局,不是损坏链接指向全机仓库里的真身
node_modules/ 被 .gitignore 忽略正常产物不入库,锁文件才入
同一个包,换了台机器装出来不一样锁文件没入库或没跟着用锁文件记的是确切版本与来源

包会被放在哪几个地方

位置怎么看给谁用
项目的本地依赖npm root / pnpm root —— 跟着当前目录往上找最近的 node_modules你的代码 import 它
npm 的全局安装npm root -g / npm ls -g --depth=0(与当前目录无关)命令行工具;不是 import 的来源
pnpm 的全局安装pnpm list -g --depth=0与 npm 的全局目录互不相干
pnpm 的全机包仓库pnpm store path该盘所有 pnpm 项目共享;项目里放硬链接指过来

两个包管理器的"全局"不是同一个目录 —— 这就是「-g 装过了为什么还找不到」的常见原因之一。

为什么 store 与"哪块盘"有关:硬链接只能建在同一块盘上,所以 pnpm 的 store 总落在"安装发生的那块盘"上 (pnpm 官方: storeDir);仓库与安装不同盘时会复制而不是链接 (pnpm 官方: FAQ)。 所以报这个值必须先说清是在哪个目录下跑的。

lockfile 与 node_modules 要点

  • 锁文件入库,node_modules/ 不入库:前者是"该装哪些确切版本"的记录,后者是可重建的产物。
  • 一个项目只用一套:npm ↔ package-lock.json、pnpm ↔ pnpm-lock.yaml、yarn ↔ yarn.lock。混用会互相覆盖,锁文件来回改。
  • 版本号的写法有区别:^1.2.3 允许升到 1.x、~1.2.3 只允许 1.2.x、1.2.3 钉死 —— 所以同一条命令在不同时间装出的版本可能不同,这正是需要锁文件的原因。
  • npx 不是"轻量全局安装":真要长期用,装进项目(首选)或明确全局安装。

易混点

  • Node.js 不是一门语言:语言是 JavaScript,Node 是运行环境(runtime)。
  • Node 不是浏览器:浏览器有 window / document,Node 有 process / fs —— 同一门语言、两套宿主能力。
  • 装了 Node ≠ 装了 pnpm:npm / npx / corepack 随 Node 来,pnpm 与 yarn 通常要另外装。
  • 包管理器不是运行时:npm -v 和 node -v 是两个独立的版本号。
  • registry 只有一份配置:npm 与 pnpm 的 config get registry 读的是同一份用户级 .npmrc,不是两套 —— 换镜像源通常改一处就够。
  • "安装慢"是三层里哪一层:取包(网络 / registry)、解包写盘(文件数)、链接(硬链接受限时退化成复制)。
