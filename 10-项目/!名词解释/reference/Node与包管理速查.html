Node.js / npm / pnpm 速查

按顺序问三个问题:这一层是跑代码还是取包 → 包存在哪一份 → 锁文件是谁写的。三个都有答案,「装不上 / 找不到模块」该往哪查就定了。

lockfile 与 node_modules 要点

  • 锁文件入库,node_modules/ 不入库:前者是"该装哪些确切版本"的记录,后者是可重建的产物。
  • 一个项目只用一套:npm ↔ package-lock.json、pnpm ↔ pnpm-lock.yaml、yarn ↔ yarn.lock。混用会互相覆盖,锁文件来回改。
  • 版本号的写法有区别:^1.2.3 允许升到 1.x、~1.2.3 只允许 1.2.x、1.2.3 钉死 —— 所以同一条命令在不同时间装出的版本可能不同,这正是需要锁文件的原因。
  • npx 不是"轻量全局安装":真要长期用,装进项目(首选)或明确全局安装。

易混点

  • 装了 Node ≠ 装了 pnpm:npm / npx / corepack 随 Node 来,pnpm 要另外装。
  • 包管理器不是运行时:npm -v 和 node -v 是两个独立的版本号。
  • 本机 registry 两边一样:npm config get registry 与 pnpm config get registry 都返回 https://registry.npmjs.org/ —— 因为读的是同一份 ~/.npmrc,不是两套配置。
  • "安装慢"是三层里哪一层:取包(网络/registry)、解包写盘(文件数)、链接(硬链接受限时退化成复制)。
