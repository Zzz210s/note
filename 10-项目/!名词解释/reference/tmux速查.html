tmux 速查

先问一句:把这个终端窗口关掉,里面的程序还活不活?活着,背后就有一个终端复用器在托管; 跟着死,那程序只是这个终端的孩子。第二句问:这句话说的是哪一层 —— 画字的窗口程序、解释命令的 Shell、托管会话的复用器,还是只让命令别被信号杀掉的那一步。见下表。

判定表:四个名字一句话分清

名字它管什么它不管什么一句话判定
终端复用器(tmux)在后台托管多个会话 / 窗口 / 面板,让它们不随连接消失不画字;挡不住机器重启;不守护崩溃的进程断线后还能接回来,它是哪一个
Shell(bash / zsh)读入一行字,解释成命令再执行不是窗口程序,没有"脱离连接"这回事敲命令时你在跟它说话
终端模拟器把字符画到屏幕、把键盘输入送进去不托管;窗口一关,里面的程序跟着一起死那个可以最小化、关掉的窗口程序
nohup让单个命令忽略挂断信号,输出重定向进文件没有窗口、没有会话:断线后看不到也回不去只求"别死",不求"还能看"

出处:man tmux · tmux 官方仓库 · Wikipedia: Terminal multiplexer · SIGHUP · man nohup。

三层结构

层是什么类比常用动作
会话 session一组窗口的容器,由后台服务端持有一间值班室新建 / 接回 / 整体结束
窗口 window占满整屏的虚拟终端一张桌子新建 / 切换 / 重命名
面板 pane窗口内切出的一块区域桌上摊开的几份文件竖切 / 横切 / 在格子间跳

三层是包含关系:服务端 → 会话 → 窗口 → 面板。会话名是你在断线后找回它的钥匙,所以起名比编号省事。

常用动作(以 tmux 为例)

想做的事做法
新建会话并起名tmux new -s 名字
后台起一个先不进去的会话tmux new -d -s 名字
列出还在的会话tmux ls
分离(人走,程序留)前缀键(默认 Ctrl-b)再按 d
接回某个会话tmux attach -t 名字
在会话里新开窗口前缀键 + c
竖切 / 横切面板前缀键 + % / 前缀键 + "
在面板之间跳前缀键 + 方向键(或前缀键 + o)
改键位 / 行为写进配置文件(默认 ~/.tmux.conf),改完重载配置即可
结束整个会话tmux kill-session -t 名字;动手前先确认里面没有还在跑的事

键位与默认值以 man tmux 为准; 配置与常见写法见 Arch Wiki: tmux。

症状反查:看到这个,就是这个结论

观察到的现象结论下一步
断线重连后敲 tmux ls,列表里还有那个会话程序由服务端托管,没跟着连接死tmux attach -t 名字 接回去
同一个会话在两个窗口里显示同样的内容这是设计如此:多客户端共享一个会话想各看各的,各起一个会话
机器重启后 tmux ls 说没有服务端服务端随重启消失,会话一起没了需要跨重启就交给系统服务管理器
窗口一关,里面的命令立刻退出那个命令直接跑在终端模拟器下,没有复用器托管先起会话,再在会话里跑
命令加了 nohup 还在跑,但看不到界面了nohup 只防信号,不提供可回看的窗口看输出文件;要界面就改用复用器
按了前缀键却什么都没发生前缀键只是"下一个键交给 tmux 解释"前缀键之后要再按一个动作键(如 d / c / %)

容易踩的坑

  • 「装了 tmux 就等于有终端」不成立:它需要一个宿主(终端模拟器或一次远程登录)才能连上去看。
  • 「在里面跑就不会崩」不成立:它防的是连接断,不防进程自己出错或被系统清理。
  • 内核里也有个"会话"概念:那是进程组织与信号投递的单位,和 tmux 的会话同名不同物,别混着推理。
  • 要"开机就在、崩了自起",那是系统服务管理器的活;复用器给不了这份保证。
  • 先给会话起名再断线:不然重连后只能对着编号猜哪个是哪个。
