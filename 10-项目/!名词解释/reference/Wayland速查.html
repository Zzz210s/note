Wayland 速查

先问一句:谁在画窗口内容、谁在管输入与显示?答「客户端画进缓冲区、合成器合成并显示」就是 Wayland; 答「客户端发请求、服务端画并管前缓冲」就是 X11。第二句问:这个工具靠什么通路干活 —— 读屏、抓键、录流、还是把整屏送出去?四类各自有替代路线,见下表。

分工对照表

维度X11(Xorg)Wayland
谁画窗口内容客户端把渲染请求交给 X 服务端,由它编程硬件(也支持客户端直接渲染)客户端自己画进缓冲区,把缓冲区交给合成器
谁管前缓冲与显示X 服务端合成器(合成后直接排一次页翻转)
点击落在哪个窗口服务端判断,但它不知道合成器的缩放 / 旋转合成器判断:场景树由它维护,会做逆变换
跨网络显示原生支持(把显示指到另一台机器)不在协议范围内(官方 FAQ 原话:No, that is outside the scope of Wayland)
客户端能读别人的画面吗能默认不能,要经合成器或门户
全局快捷键 / 抓键客户端可直接抓经 xdg-desktop-portal 的 GlobalShortcuts
老程序怎么办本来就是 X11靠 Xwayland 兼容层显示

出处:Wayland 官方:Architecture · FAQ · Wikipedia: Wayland (protocol) · Wikipedia: X Window System。

四类工具的替代路线

能力X11 下的常规做法Wayland 下的做法常见工具
截图向服务端要整屏像素按合成器分家,或走 Screenshot 门户import / maim / scrot(X11)· grim(wlroots 系)· GNOME 自带 · Spectacle(Plasma)
录屏 / 共享程序抓屏 + 编码经 ScreenCast 门户拿一条流(底层常是 PipeWire)OBS、浏览器共享、wf-recorder / wl-screenrec(wlroots 系)

症状反查:看到这个,就是这个结论

观察到的现象结论判据
echo $XDG_SESSION_TYPE 答 wayland这是一次 Wayland 会话变量为空时说明它不是一次图形登录会话
通用的抓屏命令报「无法打开显示」或抓到黑屏它走的是 X11 那条老路Wayland 下要换该合成器支持的工具,或走门户
录屏软件列不出窗口 / 共享黑屏它没走 ScreenCast 门户门户版才会弹「选择要共享的窗口」
某个快捷键在某个程序里失效它试图抓全局键盘Wayland 下要经 GlobalShortcuts 门户注册
把显示指到另一台机器,窗口出不来Wayland 协议不支持远程渲染远程要做在整屏 / 整桌面上(RDP / VNC)
程序启动参数里写着显示后端的选择项这是客户端的后端选择可强制退回兼容层(如 GTK 的 GDK_BACKEND=x11)
某个老程序窗口还能用,但抓屏 / 快捷键对它是另一套它正跑在 Xwayland 上用 xlsclients -l 能列出所有 Xwayland 程序
会话的套接字文件存在当前会话有一个 Wayland 合成器它是指向 unix 域套接字的符号链接(不是网络端口)

容易踩的坑

  • 「我装了 Wayland」这句话不成立:装的是合成器(Mutter / KWin / Sway / Weston…),Wayland 只是协议。
  • 能跑 X11 程序不等于还在 X11 里:Xwayland 只是把老程序显示出来,它的窗口照样由合成器合成。
  • 抓不到屏不等于屏幕坏了:先确认是工具不支持这个合成器,还是程序没走门户。
  • 远程桌面的实现换了一代:各家合成器各带一套 RDP / VNC 方案,不再靠协议自带的网络透明。
  • 换个查看方式再下结论:先看会话类型与套接字,再用 xlsclients 判断程序是不是跑在兼容层上, 比猜「是不是不支持」有用。
