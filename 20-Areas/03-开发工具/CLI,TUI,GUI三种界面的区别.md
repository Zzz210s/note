# CLI、TUI、GUI 三种界面的区别

> 一句话:**这三种都是"你跟电脑打交道的方式",区别只在"你用眼睛看什么、用手怎么操作"。**
> 本文用大白话讲清各自是什么、好在哪、差在哪,最后给一张对比表和"该用哪个"的判断法。
> 关联阅读:[编辑器,编译器,IDE的区别](<编辑器,编译器,IDE的区别.md>)。

---

## 一、先打个比方

去餐厅吃饭,有三种点菜方式:

| 方式 | 好比是 | 对应 |
| --- | --- | --- |
| **GUI** | 看着图画菜单,手指点一点 | 桌面窗口、按钮、鼠标 |
| **CLI** | 对着柜台报菜名,一句一句说 | 终端里敲命令 |
| **TUI** | 站在菜单牌前,用方向键上下选,牌子上有实时状态 | 终端里画出来的界面 |

三种都能吃到饭,只是"交流"的快慢、门槛、适合的场景不一样。

---

## 二、GUI(图形用户界面)

**全称** Graphic User Interface。**大白话:看得见、摸得着的界面。**

- **长什么样**:窗口、图标、按钮、下拉菜单、鼠标指针。你认识的一整套 Windows 桌面、浏览器、微信、设置面板,全是 GUI。
- **怎么操作**:鼠标点、拖拽、滚轮、手势。
- **好在哪**:
  - 零门槛。第一次用电脑就会点按钮,不用背任何东西。
  - **能"发现"功能**:菜单里有啥你一眼看得见,适合"我也不知道要干啥,先逛逛"。
  - 天生会画图、放视频、做排版。
- **差在哪**:
  - **重复劳动慢**:装 20 个软件,就得点 20 遍向导。
  - **很难自动化**:你没法让电脑"每天自动帮你点这些按钮"。
  - **吃资源**:要渲染画面、要显存、要内存。
  - **远程很费劲**:通过网络看远程桌面,其实是把整幅画面一帧帧传过来,网络一差就卡。
  - **功能被开发者锁死**:开发者没做那个按钮,你就做不了那件事。

---

## 三、CLI(命令行界面)

**全称** Command Line Interface。**大白话:打字下命令,电脑用文字回你。**

- **长什么样**:一个"黑框"(其实底色字体都能配),里面一个提示符等你输入,回车后吐出一堆文字。Windows 的 cmd / PowerShell、Git Bash、Linux 的 bash / zsh 都是。
- **怎么操作**:键盘输入命令 + 参数,按回车。
  - 例:`git status`、`npm install`、`ls -la`
- **好在哪**:
  - **精确**:`git commit -m "修正错别字"` 就是这一件事,没有歧义。
  - **能组合**:一个小工具只干一件事,用管道 `|` 串起来干大事。例:`ls | grep 2026 | wc -l`(列出文件、筛出带 2026 的、数个数)。
  - **能自动化/能脚本化**:命令能写进脚本,让电脑自己跑;这是"运维/构建/CI"的基础。
  - **可复现、可分享**:一条命令复制给别人,对方结果一样。GUI 的"你点第 3 个按钮"很难描述准。
  - **省资源、远程友好**:SSH 连服务器只传文字,几百 KB 的网速就能干活。
- **差在哪**:
  - **门槛陡**:得知道命令叫什么、参数怎么拼。忘了就只能查。
  - **没有"发现性"**:黑框不会告诉你"其实还有 30 个命令你能用"。
  - 干图形类活儿基本没戏。
  - 打错一个字符可能就"删错东西"(威力大 = 风险大)。

---

## 四、TUI(终端用户界面)

**全称** Terminal User Interface(也叫字符界面 / 文本界面)。**大白话:在"黑框"里画出来的"图形界面"。**

- **长什么样**:它仍然跑在终端里,但用字符画出框线、面板、表格、进度条、颜色,甚至能用鼠标点。看起来"像"GUI,其实底层还是文字。
  - 常见例子:`htop` / `btop`(看 CPU 内存)、`lazygit`(Git 的图形化操作)、`vim` / `neovim`(编辑器)、`ncdu`(分析磁盘占用)、`ranger`(文件管理)。
  - 本机在用的:`pi`(AI 编程助手本体)、`ais`(会话看板)、`cmder`(终端外壳)。
- **怎么操作**:键盘为主(方向键、Tab 切换、快捷键),不少程序也支持鼠标。
- **它站在哪个位置**:正好夹在 CLI 和 GUI 中间 ——
  - 比纯 CLI **直观**:状态看得见(进度、列表、当前项)。
  - 比 GUI **轻**:不依赖桌面环境,SSH 里照样跑。
- **好在哪**:远程服务器上也能有"像样的操作界面";键盘全程不离手,效率高;启动快、占用小。
- **差在哪**:还是得记快捷键;不同程序的键位不统一;鼠标支持参差不齐;遇到中文/字符编码、字体缺字可能显示错位。

## 五、三者对比表

| 维度 | GUI | TUI | CLI |
| --- | --- | --- | --- |
| 操作方式 | 鼠标/触摸 | 键盘为主(+鼠标) | 键盘纯打字 |
| 学习门槛 | 最低 | 中 | 最高 |
| 熟练后速度 | 中 | 高 | 最高 |
| 功能发现性 | 最强(菜单可见) | 中 | 最弱(得先知道) |
| 自动化/脚本 | 几乎不行 | 弱 | 最强 |
| 可复现/可分享 | 差("你点第 3 个按钮") | 中 | 最好(一条命令) |
| 远程使用(SSH) | 很差(传画面) | 好 | 最好(只传文字) |
| 资源占用 | 高 | 低 | 最低 |
| 图形/多媒体能力 | 强 | 无(字符画) | 无 |
| 典型场景 | 日常办公、设计、娱乐 | 运维监视、Git、编辑、批量管理 | 部署、构建、脚本、排错 |
| 代表软件 | Windows 桌面、浏览器、VS Code | btop、lazygit、vim、pi、ais | bash、PowerShell、git、npm |

> 注意:很多软件**同时提供三种外壳**。VS Code 是 GUI,但它内置终端(CLI)、命令面板(TUI 味)、还能 `code .` 从命令行调用;Git 有 `git` 命令(CLI)、`lazygit`(TUI)、GitHub Desktop(GUI)。所以它们是**层次关系,不是替代关系**。

## 六、怎么选(实用判断法)

- **要自动化、要重复做、要留痕给别人复现** → **CLI**
  - 例:批量改名、部署、定时备份、构建项目。
- **要一边看状态一边操作** → **TUI**
  - 例:看进程/内存排行、交互式提交 Git、翻磁盘占用、在服务器上选文件。
- **不知道从哪下手、或者要画图/排版/多窗口并排** → **GUI**
  - 例:第一次用某个功能、修图、剪视频、开一堆窗口对照。
- **经验法则**:
  1. 一件事要在 GUI 里重复点超过 3 遍 → 想想有没有 CLI 做法。
  2. 一条 CLI 命令长到你记不住 → 找找有没有对应的 TUI。
  3. CLI 的输出太多看不过来(比如一屏滚过去的构建日志) → 找带 TUI 的替代品。

**底层关系记住一句**:CLI 是地基,TUI 是在地基上"搭了个看得见的架子",GUI 是另起一栋精装修的楼 —— 后两者内部往往也在调用命令行。

## 七、顺带理清几个容易混的词

| 词 | 大白话 |
| --- | --- |
| 终端(Terminal) | 那个"窗口"本身 —— 用来跑命令行程序的载体(如 Windows Terminal、cmder) |
| 控制台(Console) | 早期指物理操作台,现在常和"终端"混用 |
| Shell | 终端里"负责解释你命令"的那层程序 —— bash、zsh、PowerShell、cmd |
| 命令行(Command line) | 你输入指令的那一行,也泛指"用命令干活"这种方式 |
| CLI 程序 | 一个只能/主要以命令方式使用的程序(如 `git`、`pandoc`) |

一句话串起来:**你打开"终端" → 里面跑着"Shell" → 你在"命令行"上敲字 → 调用各种"CLI 程序";如果那个程序的界面是画出来的,它就是个"TUI"。**
