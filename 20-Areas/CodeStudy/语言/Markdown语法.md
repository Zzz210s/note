# Markdown 语法

> 本笔记由项目 `10-Projects/掌握Markdown-2026Q4` 提炼而来;内容整理自菜鸟教程(runoob.com),是该项目在 20-Areas 沉淀的**成品正文**。

## 一句话本质

用 `#`、`*`、`|` 等直观符号写**纯文本**,再通过解析器转换成 HTML/PDF/Word。易读易写、与版本控制友好(纯文本可 diff)。文件后缀 `.md` / `.markdown`。

## 核心内容(用自己的话)

- **标题**:`#` 表示 1~6 级,`#` 与文字之间要有空格且 `#` 位于行首;也可用 `=` 表示一级、`-` 表示二级。
- **列表**:无序 `*` / `+` / `-` + 空格;有序 `1.`;嵌套靠缩进;任务列表 `- [ ]`(未完成)/ `- [x]`(已完成)。
- **表格**:`|` 分隔单元格、`---` 分隔表头(至少三个连字符);`:---` 左对齐、`---:` 右对齐、`:---:` 居中。
- **代码块**:用三个反引号 ``` 包裹并写语言名(如 ```` ```markdown ````),即可语法高亮。
- **强调**:`*斜体*` / `**粗体**`;删除线 `~~文字~~`。
- **链接与图片**:`[文字](网址)`、`![说明](图片地址)`。
- **区块引用**:行首 `>`。
- **HTML 嵌入**:基础语法不足时,可直接嵌入 HTML 标签实现复杂格式。

## 为什么这么写 / 权衡

- 相比 HTML/LaTeX:学习成本低、编写效率高、专注内容而非格式。
- Markdown 本质是到 HTML 的简化:源码 → 解析器 → HTML → 浏览器渲染。
- 删除线、任务列表属 **GFM(GitHub 风格)扩展**,并非所有平台原生支持,跨平台使用要小心。

## 坑与最佳实践

- `#` 必须在行首、且与文字间留空格,否则不解析为标题。
- 标题层级不要跳级(如 2 级直接跳到 4 级),保持结构清晰。
- 表格分隔线至少三个 `-`;对齐靠 `:` 的位置。
- 跨平台写作时,优先用基础语法,把 GFM 扩展当增强。
