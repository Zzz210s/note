# 时间复杂度与空间复杂度

> 算法分析的通用语言:本仓库所有算法笔记「复杂度」一节都基于此。

## 一句话本质

大O记号(Big-O)衡量的是:当输入规模 n 不断变大时,算法的**时间消耗**或**额外空间消耗**的增长趋势。它故意扔掉常数和低阶项,只保留"量级",这样就能不依赖具体机器、不依赖具体数据,横向比较两个算法谁更扛得住大数据。

## 核心内容(用自己的话)

### 1. 为什么需要它

衡量算法快慢,最朴素的想法是「拿秒表测」。但这有两个硬伤:

- **依赖机器**:同一段代码在你电脑跑 0.1s,在树莓派可能 2s
- **依赖数据**:同一个排序,输入已排好(一遍过)和完全逆序(最慢),耗时天差地别

复杂度分析绕开这两点:不测绝对时间,只看「输入规模 n 变大时,操作次数的增长曲线」。它给的是**趋势**不是**实测**,但趋势对了一般就不会错——n 足够大时,量级小的算法必然胜出。

### 2. 大O记号定义

设 T(n) 是输入规模为 n 时基本操作的执行次数。说 T(n) = O(f(n)),意思是:存在正数 c 和 n0,当 n > n0 时,**T(n) ≤ c·f(n)** 恒成立。

人话翻译:

- 它是**上界**(更精确说是渐近上界)
- "≤ c·f(n)" 且只看 n 很大时——所以常数 c 多少无所谓、低阶项无所谓、f(n) 是什么量级才要紧
- 算法 A 是 O(n)、算法 B 是 O(n²):n 小时谁快不一定,n 大了 A 必赢

### 3. 常见量级速查(从小到大)

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)

直观感受(n=100,设常数都为 1):

| 量级    | 操作次数   | 喻体                        |
| ------- | ---------- | --------------------------- |
| O(1)    | 1          | 伸手拿桌上最上面一本书      |
| O(log n) | ~7        | 二分翻字典,每次砍一半      |
| O(n)    | 100        | 把书架每本看一眼            |
| O(n log n) | ~664    | 优秀的排序                  |
| O(n²)   | 10000      | 双重循环两两比较            |
| O(2ⁿ)   | 10³⁰       | 指数爆炸,宇宙寿命都跑不完  |
| O(n!)   | 10¹⁵⁸      | 全排列,比指数还凶          |

### 4. 怎么手算时间复杂度

三步:

1. **数基本操作执行次数**——一般盯最内层循环体,看它被执行多少次
2. **取最高阶,扔掉低阶**——n²+n,只要 n²
3. **扔掉常数系数**——3n² 和 100n²,都是 O(n²)

口诀:**最高阶为主,系数常数全扔**。

### 5. 空间复杂度

同理,只不过数的是算法**运行过程中额外申请的内存**随 n 的增长趋势(不算输入本身占的空间)。

- 只用几个临时变量 -> O(1),叫**原地算法**(in-place),如冒泡排序
- 开一个长度 n 的辅助数组 -> O(n),如归并排序
- 递归调用栈深度 k -> O(k);递归每层再开数组要叠加

### 6. 最好 / 最坏 / 平均(以冒泡排序为例,带 swapped 优化)

同一算法,不同输入复杂度可能不同。**计算的关键是:数清基本操作(这里是比较)在每种输入下到底执行了几次。** 设数组长度为 n,内层基本操作是 `arr[j] > arr[j+1]` 的一次比较。

**最坏(完全逆序)**——每轮都有交换、跑满 n-1 轮:
- 第 1 轮比较 n-1 次,第 2 轮 n-2 次,…,第 n-1 轮 1 次
- 比较总次数 = (n-1) + (n-2) + … + 1
- 等差数列求和 = n(n-1)/2 ≈ n²/2
- 去系数 1/2 -> **O(n²)**

**最好(已经有序)**——第 1 轮扫一遍做 n-1 次比较、0 次交换,swapped 保持 false,立即退出:
- 比较总次数 = n-1 -> **O(n)**
- 关键:swapped 早退把轮数从 n-1 压到 1

**平均(随机输入)**——随机序列要到很靠后才稳定,轮数仍是 O(n) 级别,每轮比较数仍是 n-1、n-2、… 的量级:
- 期望比较次数仍为 n(n-1)/2 量级 -> **O(n²)**
- 另一角度:随机数组逆序对期望 n(n-1)/4 个,每次交换消除 1 个逆序对;但比较次数 ≥ 交换次数,主导项仍是 O(n²)

> 口诀:**最好/最坏/平均的差别,来自基本操作在不同输入下执行次数不同。算它,就是数它。**

面试/竞赛默认报**平均或最坏**,除非题目特别问最好情况。

## 代码举例

> 每段代码:开头是**全局原理注释**(讲清怎么跑、为什么是这个复杂度),再逐元素注释,变量名语义化(不用 `a`/`m`/`lo`/`hi` 这种随意名)。

### O(1) 常数时间
```cpp
// 运行原理:数组在内存中连续存放,首元素就在数组起始地址处。
// 下标 arr[0] = 起始地址 + 0*sizeof(int),只是一次寻址运算,
// 与数组多长无关——无论 10 个还是 10 亿个元素都固定一步 -> O(1)。
int first(vector<int>& arr) {       // arr:待取首元素的数组(按引用传,不拷贝)
    return arr[0];                  // 返回首元素
}
```

### O(log n) 对数时间
```cpp
// 运行原理(二分查找):对有序数组反复取中点比较,每轮把候选区间砍掉一半。
// 设区间长度为 L,每轮 L -> L/2,直到 L=1 停止。
// 砍 k 次后 L = n / 2^k,令其 = 1 得 2^k = n -> k = log2(n),
// 即最多比较 log2(n) 次 -> O(log n)。
int binary_search(vector<int>& arr, int target) {
    int left = 0;                   // left:候选区间左边界(含)
    int right = arr.size() - 1;     // right:候选区间右边界(含)
    while (left <= right) {         // 区间非空就继续
        int mid = (left + right) / 2;   // mid:中点下标
        if (arr[mid] == target) {
            return mid;             // 命中,返回下标
        } else if (arr[mid] < target) {
            left = mid + 1;         // 目标比中点大,丢掉左半 [left..mid]
        } else {
            right = mid - 1;        // 目标比中点小,丢掉右半 [mid..right]
        }
    }
    return -1;                      // 区间空了仍未命中,表示不存在
}
```

### O(n) 线性时间
```cpp
// 运行原理(求最大值):最大值一定在数组里,从头扫到尾逐个比较即可。
// 每个元素恰好访问 1 次,共 n 次比较,无嵌套循环 -> O(n)。
int find_max(vector<int>& arr) {
    int maxVal = arr[0];            // maxVal:已扫部分的最大值,先假定首元素最大
    for (int val : arr) {           // val:当前遍历到的元素
        if (val > maxVal) {
            maxVal = val;           // 发现更大的,更新最大值
        }
    }
    return maxVal;
}
```

### O(n log n) 线性对数
```cpp
// 运行原理(归并排序):
// 1) 分:把数组对半切成两段,递归把每段排好
// 2) 治:用 merge 把两个已有序的半段合并成一段有序
// 递归深度:每次折半 -> 共 log2(n) 层
// 每层代价:merge 合并两段总共扫 n 个元素 -> O(n)
// 总代价 = 层数 × 每层代价 = log2(n) × O(n) = O(n log n)
void merge(vector<int>& arr, int left, int mid, int right);  // 前置声明,定义在下方

// 对 arr[left..right) 区间排序(左闭右开)
void merge_sort(vector<int>& arr, int left, int right) {
    if (right - left <= 1) return;  // 长度 <=1 已经有序,递归终点
    int mid = (left + right) / 2;   // 中点
    merge_sort(arr, left,  mid);    // 排左半 arr[left..mid)
    merge_sort(arr, mid,   right);  // 排右半 arr[mid..right)
    merge(arr, left, mid, right);   // 合并两段
}

// 合并 arr[left..mid) 和 arr[mid..right) 两段有序子数组(双指针法)
void merge(vector<int>& arr, int left, int mid, int right) {
    vector<int> leftPart(arr.begin() + left,  arr.begin() + mid);   // 左半副本
    vector<int> rightPart(arr.begin() + mid, arr.begin() + right);  // 右半副本
    int leftIdx = 0, rightIdx = 0, outIdx = left;  // 三个指针:左段读位 / 右段读位 / 原数组写位
    while (leftIdx < (int)leftPart.size() && rightIdx < (int)rightPart.size()) {
        // 两段都未取尽,取较小者写入;用 <= 而非 < 保证稳定性(相等时左段先出)
        arr[outIdx++] = (leftPart[leftIdx] <= rightPart[rightIdx]) ? leftPart[leftIdx++] : rightPart[rightIdx++];
    }
    while (leftIdx  < (int)leftPart.size())  arr[outIdx++] = leftPart[leftIdx++];   // 左段剩余直接接上
    while (rightIdx < (int)rightPart.size()) arr[outIdx++] = rightPart[rightIdx++]; // 右段剩余直接接上
}
```

### O(n²) 平方时间
```cpp
// 运行原理(冒泡排序,见 [[冒泡算法]]):
// 相邻比较、大数后移。每完成一轮完整扫描,当前未排序区的最大值
// 必然"冒泡"到末尾,于是末尾有序区每轮长 1、未排序区每轮短 1。
// 比较次数 = (n-1) + (n-2) + … + 1 = n(n-1)/2 ≈ n²/2,去系数 -> O(n²)。
void bubble_sort(vector<int>& arr) {
    int n = arr.size();
    for (int round = 0; round < n - 1; ++round)         // round:第几轮冒泡,共 n-1 轮
        for (int j = 0; j < n - 1 - round; ++j) {       // j:内层比较下标,末尾 round 个已就位不再扫
            if (arr[j] > arr[j + 1]) {
                swap(arr[j], arr[j + 1]);               // 相邻逆序则交换(用 > 不用 >=,保稳定)
            }
        }
}
```

### O(2ⁿ) 指数时间(警示:别这么写)
```cpp
// 运行原理(朴素递归斐波那契):
// fib(n) = fib(n-1) + fib(n-2),每次调用裂成两个子调用,
// 递归树是一棵二叉树,节点数随层数翻倍增长。
// 设 T(n) 为调用次数:T(n) = T(n-1) + T(n-2) + 1,
// 此递推与斐波那契数列本身同阶,解为 T(n) ≈ O(2^n)
// (更精确约 1.618^n,大O 取上界记 O(2^n))。n=40 已卡顿,n=50 基本跑不出。
int fib(int n) {                      // n:求第 n 个斐波那契数
    if (n <= 1) return n;            // 递归终点:fib(0)=0, fib(1)=1
    return fib(n - 1) + fib(n - 2);   // 裂成两个子调用,大量重复计算(如 fib(3) 被反复算)
}
```
> 加记忆化(memo)后降到 O(n)——这是「空间换时间」最经典的例子。

## 为什么这么写 / 权衡

- **大O故意忽略常数**:所以 O(n) 不一定处处比 O(n²) 快。n 很小时,常数大的 O(n) 算法可能更慢(比如归并 vs 插入排序,n<10 时插入常更快)。但工程里数据量一旦上来,量级必胜,所以分析时只看量级是对的。
- **空间换时间 / 时间换空间**:哈希表用 O(n) 额外空间,把查找从 O(n) 降到 O(1);压缩算法用 CPU 时间换存储空间。没有免费午餐,复杂度就是把这种取舍量化出来。
- **递归复杂度别拍脑袋**:画递归树算总节点数,或套主定理(Master Theorem)T(n)=aT(n/b)+f(n)。

## 坑与最佳实践

- **循环层数 ≠ 复杂度层数**:双层循环不一定是 O(n²)——若内层步长是 `i *= 2`(每次翻倍)那是 O(log n),整段是 O(n log n)。看的是**内层体执行总次数**,不是套了几层。
- **别把输入规模搞混**:n 是什么?数组长度?矩阵边长(矩阵元素是 n²)?还是数字的位数?矩阵边长为 n 时遍历元素是 O(n²) 不是 O(n)。
- **平均和最坏要分清**:快排平均 O(n log n)、最坏 O(n²);面试报复杂度时主动说清是哪种。
- **递归别忘调用栈空间**:递归深度 k 就有 O(k) 的栈空间,递归太深会 StackOverflow,不光是时间的事。
