# 记录:阅读站改 VS Code 式工作台(2026-10)

> 起因:在线阅读站 `index.html` 原先是「自动生成的单页阅读页」,只看得到卡片列表;用户要**像 VS Code 一样的工作台**观感,并要**分屏随时切换**,课程次数不再依赖本机改名脚本。
> 结论:站点外壳整体重写成工作台(活动栏 / 侧栏两棵树 / 每组标签栏 / 两组分屏 / 状态栏),计数改由站点自己记(localStorage + 烘焙种子),旧四套本机计数方案全部退役。以下是前后对照、关键决定与遗留。

## 一、改了什么

### 工作台骨架

`index.html` 现在是 VS Code 式外壳,自顶向下五层:

| 区块 | 规格 | 实现 |
|---|---|---|
| 标题栏 | 深色,含品牌名与主题切换 | `site_render.py` 骨架 + `site_work_css.WORK_CSS` |
| 活动栏 | 48px,课程 / 笔记 / 主题 / 菜单 | 同上 |
| 侧栏 | 260px,可折叠;每棵树顶部一个搜索框 | `site_parts.py` 两棵树 + `site_work_split.py` 开合 |
| 编辑区 | 每组一条标签栏(35px)+ 组内 `iframe.lesson-frame` | `site_work_js.py` / `site_work_split.py` |
| 状态栏 | 24px,强调蓝 | `site_render.py` |

外壳固定高度,长侧栏不会把活动栏顶出视口;≤768px 时侧栏收成抽屉(可点控件 ≥44px)。

### 侧栏两棵树

- **课程树**:按工作区(项目)分组,每组下列 `lessons/*.html`。
- **笔记树**:**按项目 + 按标签**平铺列出 `20-知识/` 笔记与 `50-资源/记录/` 记录。
- 两棵树共用一套过滤:侧栏搜索词 + 侧栏 chip + 欢迎页 chip 三处叠加(同组多 chip 取 OR)。

### 分组与分屏

- 每个组(panel)自带标签栏;**最多两组**。
- `Ctrl+\` 拆分 / 合并:源组空了即消失;拖动标签可换组(落点是提示高亮)。
- 布局(组数、各组标签、选中项、分屏状态、侧栏开合、主题)存 `localStorage`,刷新后还原。
- 快捷键:`Ctrl+P` 快速打开、`Ctrl+Shift+P` 命令面板、`Ctrl+B` 侧栏、`Ctrl+W` 关标签、`Ctrl+\` 分屏。

### 快速打开与命令面板

- `Ctrl+P`:按课号 / 标题模糊搜课,回车在**当前组**开标签。
- `Ctrl+Shift+P`:命令面板,含「切换主题」「清空本地计数」等动作。
- 工作台侧的所有交互都走 `window.__work`(open / close / empty / setSplit / setSide),第三段 IIFE 汇总筛选。

### 计数改站点记录

- 显示值 = **烘焙种子** + **本浏览器增量**:
  - 烘焙种子在生成站点时并入页面(`50-资源/工具/site-build/counts-seed.json` → `window.__COUNTS__`);
  - 之后从站点打开课只写 `localStorage`(`note:counts`),**不回写文件、不上传**。
- 页面侧标识是 **slug**,种子键是**仓库相对路径**,join 必须走条目清单的 `entry["path"]`(种子键用当前路径,文件改名即静默丢弃那一条烘焙历史)。
- 只统计「从站点打开」的课;换设备 / 清缓存后增量归零,只剩烘焙历史。它记活跃度,不代表学会。

### 旧四套本机计数方案退役清单(逐项)

| # | 方案 | 位置 | 退役动作 |
|---|---|---|---|
| 1 | 文件名 `x<次数>-` 前缀 | 各 `lessons/*.html` | 5 个已加前缀的课改名;79 处引用 / 24 文件同步(**Task 1**) |
| 2 | 本机计数小服务 | `50-资源/工具/lesson-track/` | 删 11 文件 / 2 目录;先停掉 8787 后台服务(它会每 10 秒按 `counts.json` 把前缀加回来并自动提交)(**Task 3**) |
| 3 | 课页关闭信标 | 全库 HTML 内联 `lesson-close-beacon.js` | 61 处已入库 HTML 逐字节删行 + 脚本本体删除(**Task 2**) |
| 4 | 打开文件夹自动起服务 | `.vscode/tasks.json` | 随方案 2 一起删除(`folderOpen` 自动任务,当时还要用户手动授权) |

配套:计数历史一次性烘进 `counts-seed.json`(6 条 7 次,后按要求删掉一条退役速查卡键,余 5 条)。

## 二、为什么

1. **要 VS Code 观感**:卡片列表看不出「有一堆课、有一堆笔记」的层级;活动栏 + 两棵树 + 标签栏 + 状态栏是熟悉的操作隐喻,进来就会用。
2. **要分屏随时切换**:看课时想对照另一节课或一篇笔记,单页阅读页做不到;两组分屏 + 拖标签换组最直接。
3. **次数由站点记**:旧方案要在本机常驻服务、改文件名、重写全库引用,还会与 VS Code 自动任务互相拉扯(Task 1 就撞上服务把改名回退);站点自己记,零本机依赖,换台机器打开还是同一个页面。

## 三、关键决定与代价

| 决定 | 理由 | 代价 |
|---|---|---|
| **课用 `iframe` 内嵌**,不把课正文拆进工作台 | 课有自己的一整套样式(`lesson.css`);内联会与工作台 CSS 打架,且 41 节课要逐页改写 | 课不跟随工作台主题;编辑区多一条「内嵌文档」标题条说明它未适配 |
| **两组分屏上限** | 两组是「对照」的最小可用单位,再多标签栏与拖拽逻辑复杂度陡增 | 想要 3/4 宫格对照时做不到(见遗留) |
| **默认浅色**(VS Code Light Modern 取向) | 课件纸底本来就是浅色,浅色外壳与内嵌课观感连续;暗色另给一套 | 首次访问不会跟随系统深色偏好,要手动切 |
| **欢迎页改成「空态」**,不占标签 | 欢迎页占一个标签会挤掉真实课,关掉又要找回;空态即「该组无标签时」显示的占位 | 逻辑上「没有标签」与「显示欢迎页」绑定,删掉所有标签就回空态 |
| **anchor 从 `<项目>-<条目>` 改成纯 slug** | 侧栏树项 `data-key`、卡片 `id`、`window.__COUNTS__` 键必须同一个口径;带项目前缀的三段式对齐成本高、易错 | 与旧阅读站 spec 5.3 的 anchor 口径不同,旧锚点外链会失效(当时未公开,影响面为零) |

## 五、遗留

1. **笔记树「按项目 + 按标签」目前平铺**,未做两级折叠;笔记 / 记录一多,侧栏会很长(课程树已有工作区分组)。
2. **`lesson.css` 仍无暗色**:工作台切暗色时,内嵌的课仍是浅色纸底(靠「内嵌文档」标题条说明,不算故障,但观感不统一)。
3. **4 宫格分屏未做**:分屏上限固定在两组,想做四宫格要改标签栏 / 拖拽 / 布局记忆三处。
