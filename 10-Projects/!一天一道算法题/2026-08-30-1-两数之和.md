## ② 题意(用自己的话)

给定一个整数数组 `nums` 和目标值 `target`，需要找到两个不同下标 `i`、`j`，使得：

```text
nums[i] + nums[j] == target
```

返回这两个元素的下标。题目保证每组输入只有一个有效答案，并且不能重复使用同一个数组元素。

例如：

```text
nums = [2, 7, 11, 15], target = 9
```

因为 `nums[0] + nums[1] == 2 + 7 == 9`，所以返回 `[0, 1]`。

## ③ 踩坑与卡点

> 本节是根据源代码反推的 AI 示例，不是本人当时的真实独立思考记录。

- **第一反应:** AI 示例采用两层循环枚举所有下标组合，但这种做法的时间复杂度是 `O(n²)`；题目要求尝试使用低于 `O(n²)` 的算法，因此进一步使用哈希表优化查找。
- **卡在哪:** `[思路][通用]` 如果对当前数字再从剩余数组中线性查找互补数，会重新扫描数组，复杂度仍然较高；应使用哈希表把查找降为平均 `O(1)`。
- **错误思路(防再犯):**
  - 先排序再用双指针虽然可以找到两个数，但排序会改变元素顺序，需要额外保存原始下标；本题直接使用哈希表更简单。
  - 不能只保存数字而不保存下标，因为题目要求返回数组下标。
  - 必须先查找互补数，再保存当前数字。否则当 `nums = [3, 3]`、`target = 6` 时，可能让当前元素与自己匹配。

## ④ 正确思路(看题解后)

### 1. 核心观察

对于当前元素 `num = nums[i]`，如果它要和另一个数相加得到 `target`，那么另一个数一定是：

```text
complement = target - num
```

因此问题转化为：

> 在遍历到 `nums[i]` 时，判断 `complement` 是否已经在前面出现过。

### 2. 哈希表的含义

源代码中的：

```cpp
unordered_map<int, int> seen;
```

含义是：

```text
键:   已经遍历过的数组元素值
值:   该元素对应的数组下标
```

例如遍历到数组下标 `0` 时，`nums[0] = 2`，会记录：

```text
seen[2] = 0
```

之后遍历到 `7` 时，计算出互补数 `9 - 7 = 2`，在 `seen` 中找到 `2`，就能得到答案下标 `0` 和 `1`。

### 3. 为什么必须先查后存

源代码的顺序是：

```cpp
auto it = seen.find(complement);

if (it != seen.end()) {
    return {it->second, i};
}

seen[num] = i;
```

也就是：

1. 先查当前数字需要的互补数
2. 查不到时，才把当前数字存入哈希表

这样可以保证哈希表中保存的都是当前元素之前的元素，不会把当前元素和自己匹配。

以 `nums = [3, 3]`、`target = 6` 为例：

| 下标 | 当前值 | 互补数 | 查找结果 | 查找后操作 |
|------|--------|--------|----------|------------|
| 0 | 3 | 3 | 没找到 | 保存 `3 -> 0` |
| 1 | 3 | 3 | 找到下标 0 | 返回 `[0, 1]` |

### 4. 遍历示例

以 `nums = [2, 7, 11, 15]`、`target = 9` 为例：

| 下标 `i` | 当前值 `num` | 互补数 `target-num` | `seen` 查找 | 操作 |
|----------|--------------|---------------------|-------------|------|
| 0 | 2 | 7 | 不存在 | 保存 `2 -> 0` |
| 1 | 7 | 2 | 存在，位置为 0 | 返回 `[0, 1]` |

找到答案后可以立即返回，不需要继续遍历。

## ⑤ 代码

```cpp
// LeetCode 的 C++ 判题环境通常会提供常用标准库上下文。
// 如果在本地编译，需要补充：
// #include <unordered_map>
// #include <vector>
// using namespace std;

class Solution {
public:
    // 返回数组中和为 target 的两个元素下标。
    vector<int> twoSum(vector<int>& nums, int target) {
        // 哈希表：元素值 -> 该元素的数组下标。
        unordered_map<int, int> seen;

        // 预留哈希桶，减少插入过程中反复扩容和 rehash 的次数。
        // 这是性能优化，不影响算法正确性。
        seen.reserve(nums.size());

        // 从左到右遍历数组。
        for (int i = 0; i < (int)nums.size(); ++i) {
            // 当前正在处理的元素值。
            int num = nums[i];

            // 当前元素需要寻找的互补数。
            int complement = target - num;

            // 先查找互补数是否已经在前面出现过。
            auto it = seen.find(complement);

            if (it != seen.end()) {
                // it->second 是互补数的下标，i 是当前元素下标。
                return {it->second, i};
            }

            // 查找失败后，再保存当前元素及其下标。
            // 先查后存可以避免当前元素与自己匹配。
            seen[num] = i;
        }

        // 题目保证一定有答案，因此正常情况下不会执行到这里。
        return {};
    }
};
```

### 源代码细节说明

- `class Solution`:LeetCode 规定的解题类名。
- `vector<int>& nums`:输入数组按引用传递，避免复制整个数组；LeetCode 给定的函数签名不是 `const` 引用，因此沿用原签名。
- `int target`:目标和。
- `unordered_map<int, int> seen`:哈希表，平均情况下支持常数时间的查找和插入。
- `seen.reserve(nums.size())`:预留容量，减少哈希表扩容次数；不是必须操作。
- `for (int i = 0; i < (int)nums.size(); ++i)`:使用 `i` 遍历数组下标。
- `auto it`:由编译器自动推导为哈希表迭代器。
- `seen.find(complement)`:查找互补数。
- `it != seen.end()`:判断是否查找成功。
- `it->second`:取得互补数对应的数组下标。
- `return {it->second, i}`:使用初始化列表构造并返回两个下标。
- `seen[num] = i`:把当前数字和下标保存到哈希表中；如果数字重复，会覆盖之前保存的下标。本题中保存最近一次下标仍然可以得到正确答案。

## ⑥ 复杂度

- **时间复杂度:**平均 `O(n)`。
  - 数组只遍历一次。
  - `unordered_map` 的查找和插入平均为 `O(1)`。
  - `n` 表示数组长度。
- **空间复杂度:**`O(n)`。
  - 最坏情况下，哈希表会保存数组中的全部元素。
- **严格的最坏情况:**`unordered_map` 在哈希冲突严重时可能退化为 `O(n)` 查找，但通常算法分析按平均 `O(1)` 处理。
