> **给执行者:** 本文件只定义"做什么、做到什么算成、产物放哪"。采购、焊接、实测、发帖由本人执行。
> **上级文档:** [项目说明](<!项目说明.md>) / [实施计划总览](<!实施计划.md>)
> **串联项目:** [2026Q4-复刻L-ink智能名片](<../2026Q4-复刻L-ink智能名片/!项目说明.md>)

**目标:** 把 L-ink 复刻做成"面试官愿意追问 20 分钟"的旗舰硬件作品 —— 实物 + 可复现的实测数据 + 英文作品集 + 一次真实的上游社区贡献。

**为什么是它:** 目标行业是 IoT / 消费电子 / 通信,面试官看得懂硬件,看不懂开发者工具。一张"手机贴近即刷屏、全程无电池"的卡,自带演示效果,且能讲出 NFC 能量采集、超低功耗设计、墨水屏驱动三条技术链路。

**约束:**

- 不复用 `netscope` / `ai-session-hub` 作为作品集主角
- 所有数据必须实测,禁止用规格书标称值冒充实测值
- 英文 README 与视频是**对外产物**,必须无 emoji、无中式英语残留
- 作品集页面复用现有 `personal-content` / `personal-site` 基础设施(内容是新的)

### Task 3.2:实测数据采集(面试的核心弹药)

**Files:**
- Create: `技术证据/L-ink/01-实测数据.md`

**Interfaces:**
- Consumes: Task 3.1 的实物
- Produces: Task 3.3 / 3.4 / 3.5 全部要引用的数字

- [ ] **Step 1:先写测量方案,再动手测**

```markdown
## 测量方案
| 待测量 | 方法 | 器材 | 不确定度来源 |
|--------|------|------|--------------|
| 能量采集输出电压 | 万用表跨接整流后储能电容 | 万用表 | 负载变化、场强距离 |
| 采集电流 | 串入 INA219 或采样电阻 + ADC | INA219 / MCU ADC | 采样率、量程 |
| 唤醒阈值 | 逐步拉开手机距离,记录首次唤醒距离 | 卷尺 + 手机 | 手机型号差异 |
| 单次刷新功耗 | 电流曲线对时间积分 | 示波器 / MCU 采样 | 刷新波形采样密度 |
| 刷新耗时 | 固件打点计时 | 串口日志 | 时钟精度 |
```

- [ ] **Step 2:无示波器时的替代路径(必须写进方案,避免卡死)**

用 MCU 的 ADC 以固定间隔采样储能电容电压并串口输出,再在 PC 侧做积分与曲线绘制。代价是时间分辨率低,需在文档里写明这一限制。

- [ ] **Step 3:记录每组数据的条件**

每条数据必须带:手机型号、贴合位置、距离、环境温度、固件版本。**没有条件的数字在面试里站不住。**

- [ ] **Step 4:判据**

`01-实测数据.md` 里每项都有"数值 + 测量方法 + 条件 + 不确定度";至少覆盖:采集电压、唤醒距离、单次刷新耗时、单次刷新功耗。

### Task 3.5:上游社区贡献(高 star 项目的真实互动)

**Files:**
- Create: `技术证据/L-ink/02-上游回帖记录.md`

**Interfaces:**
- Consumes: Task 3.2 的实测数据
- Produces: "高 star 项目贡献者"的可验证证据

**背景(规划阶段已核实):** 上游 `peng-zhihui/L-ink_Card` 有 7,646 star,但 **2021-01 后停更**,56 个 open issue(混有垃圾广告,也有真实技术提问,例如"能量采集能输出 3.3V 的电压吗""NFC 读不到卡号")。停更仓库的 PR 难以合并,所以这条线的正确打法是**用实测数据回答真问题**,而不是提 PR。

- [ ] **Step 1:挑 2-3 个真实技术问题(避开垃圾 issue)**

- [ ] **Step 2:回帖必须包含三要素**

① 我的实测数据(带测量条件);② 结论与适用边界(什么情况下不成立);③ 可复现的方法(怎么自己测一遍)。**只写"我也遇到了"不算贡献。**

- [ ] **Step 3:同步到社区 fork**

上游停更时,社区 fork(`simonire/L-ink_Card`)是活的那一支。把有价值的结论也贴到 fork 的 issue / PR 区。

- [ ] **Step 4:判据**

`02-上游回帖记录.md` 里每条回帖都有链接、内容摘要、是否被回应;至少 2 条有技术内容(不是"求带"式发言)。

## 风险与对策

| 风险 | 对策 |
|------|------|
| 采购或打板周期长 / 焊接失败 | 用三轨道设计兜底:退到轨道 B(开发板原型),链路完整即可讲故事 |
| 缺示波器导致功耗测不准 | 用 MCU ADC 采样替代,并在文档里写明时间分辨率限制 |
| 上游停更导致贡献"无处合并" | 这条线本就不追求合并,追求"用实测数据回答了真问题";合并类贡献由计划 2 承担 |
| 数据造假冲动 | 硬约束:每个数字必须有测量条件;写不清条件的数据一律删掉 |
