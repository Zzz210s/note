# 2027-拿下海外销售实习 · 实施计划

> **给执行者:** 本计划按任务逐条执行,`- [ ]` 可勾选。这是求职与作品计划,不是代码计划 —— 每个任务的"验证"= 交付物能被外部检查(文件存在、链接可访问、数据有记录),不是跑测试。
> **本项目 spec:** [项目说明](<!项目说明.md>)

**目标:** 在 2027 年暑期实习窗口内拿到技术型海外销售/售前方向 offer,同时留下可验证的技术作品与销售实践证据。

**架构:** 四轨并行(材料 / 技术证据 / 销售实践 / 语言与行业),但**分五个子计划交付**,顺序由依赖关系决定:先出材料以便立即海投,技术证据与销售实践随后并行推进。

**约束(来自 spec,逐条适用):**

- star 数与徽章**不作为指标**,只作副产品观察
- **轨 C(销售实践)权重高于轨 B(技术证据)**
- 不复用 `netscope` / `ai-session-hub` 作为旗舰作品
- 语言目标:英语六级 + 西班牙语 B2(以证书为准)
- 无日历时间轴,事件驱动:上一件做完就开下一件
- 输出禁 emoji;简历等对外文件用 docx/pdf 导出(**不入库**,vault 已忽略 `*.docx` `*.pdf`),Markdown 源文件入库

```bash
toolbox create kernel-dev --image fedora-toolbox:44
```

| 路线 | 需要什么 | 说明 |

```bash
lsusb                     # 插上模组后读 VID:PID
```

- [ ] **Step 2:在内核树里找同类条目**


```bash
make defconfig && make modules_prepare
```

- [ ] **Step 4:checkpatch + 提交信息**

```bash
./scripts/checkpatch.pl --strict --git HEAD
```

提交信息写法(上游真实范例):`net: usb: qmi_wwan: add <厂商> <型号>`;正文说明模组的组合模式与用途。

- [ ] **Step 5:发给正确的人**

```bash
./scripts/get_maintainer.pl -f drivers/net/usb/qmi_wwan.c
```

`qmi_wwan.c` 归 netdev;`option.c` 归 linux-usb。按脚本输出填 `--to` / `--cc`。

- [ ] **Step 6:跟进 review 直到有结论**

判据:补丁在 `lore.kernel.org` 可见;状态(合并 / 需改 / 被拒)写进 `02-模组补丁.md`,并把链接同步到 `提交清单.md`。
