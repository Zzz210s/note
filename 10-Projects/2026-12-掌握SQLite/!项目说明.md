# 2026-12-掌握SQLite

> 属于 `10-Projects\` 项目层(月粒度 · 基础 · 数据底座,未开始 → 待学任务,排在「2026-11-掌握Git」之后)。
> 定位:边缘函数工程师知识树的**数据层底座**——本机 AI 工具链(pi 的 codegraph 索引库、magic-context 记忆库)与边缘数据库(Cloudflare D1 即基于 SQLite)都以它做地基;2027 年学「掌握边缘函数原理」之前先吃透它。与「掌握Docker / Nginx」的部署线并行,SQLite 走**数据线**,实战锚点用自己机器上已有的真实 SQLite 库,不另造场景。

- **目标:** 掌握 SQLite 嵌入式数据库:能用 CLI + 一门语言(Python `sqlite3` / Node `node:sqlite`)建库建表、写查询、上索引、开事务,并讲清"什么时候该用、什么时候不该用"
- **状态:** 未开始
- **起止:** 2026-12-01 → 2026-12-31(撞期顺延,以 00-MOC/系统.md 学习路线为准)
- **为什么做:** 零配置单文件 = 练 SQL 与数据库原理成本最低的入口;且本机已有大量 SQLite 在跑(见 [01-SQLite介绍.md](<01-SQLite介绍.md>)「你可能早就在用」),学会即能读懂自己的工具
- **验收:**
  1. 30 秒讲清"SQLite 是什么、为什么是嵌入式单文件、何时不该用"(能对照 MySQL/PostgreSQL)
  2. 用 CLI + 至少一门语言完成一个自选小数据应用:设计表 → CRUD → 加索引 → 事务,并用 `EXPLAIN QUERY PLAN` 证明一次慢查询被索引提速
  3. 读懂本机一个真实 SQLite 库(任一被 codegraph 索引仓库的 `.codegraph/index.sqlite`,或 magic-context 的 context.db)的表结构,写出 ≥3 条有意义查询
  4. 沉淀笔记写进 20-Areas、踩坑记录归档、文件夹移入 40-Archive、更新 00-MOC/系统.md 勾选

### 阶段0 概念与 CLI(12-01 → 12-07)
- [ ] 是什么:嵌入式 / 无服务器 / 零配置 / 单文件 / ACID / 公有领域;与 MySQL/PostgreSQL 的根本区别(库内嵌进程 vs 独立服务进程走网络)
- [ ] 工具链就位:命令行 `sqlite3` + DB Browser for SQLite(SQLiteBrowser)可视化;`.help` / dot-command 速查
- [ ] CLI 基本功:建库建表、增删改查、`.open` / `.tables` / `.schema` / `.mode` / `.headers on` / `.import`
- [ ] 数据模型:五个存储类(NULL/INTEGER/REAL/TEXT/BLOB);动态类型与类型亲和性(Type Affinity),"弱类型"的便利与坑

### 阶段1 查询与设计(12-08 → 12-14)
- [ ] SQL 核心:WHERE / JOIN(inner/left)/ 聚合 GROUP BY / 子查询 / ORDER BY / LIMIT
- [ ] 约束与表设计:PRIMARY KEY / FOREIGN KEY / UNIQUE / NOT NULL / CHECK / DEFAULT;INTEGER PRIMARY KEY 自增与 `sqlite_sequence`;正规化到"够用"程度
- [ ] 索引:为什么能加速、`CREATE INDEX`、`EXPLAIN QUERY PLAN` 读执行计划、何时不该加索引
- [ ] 进阶查询:视图 VIEW、CTE(WITH)、窗口函数(ROW_NUMBER / RANK / LAG 等)

### 阶段2 可靠性与高级特性(12-15 → 12-21)
- [ ] 事务:ACID 四性;BEGIN / COMMIT / ROLLBACK;锁与并发模型(单写多读)

- [ ] 备份与迁移:`.backup` / `VACUUM INTO` / checkpoint;为什么活跃库不能只 `cp`
- [ ] 触发器 TRIGGER;`ALTER TABLE` 能力边界(改/删列受限 → 重建表套路)
- [ ] 高级:JSON 函数(json_extract / json_each / json_set);FTS5 全文检索(中文注意点见 02 文档)

- [ ] 实战二:打开本机真实库——任一被 codegraph 索引仓库的 `.codegraph/index.sqlite`,用 `.schema` 看懂表结构,写 ≥3 条有意义查询(如"哪个文件被引用最多")
