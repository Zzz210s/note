# 0-Note · 程序员知识库总纲

**[English](./README.md) | 简体中文**

> 一套纯 Markdown、工具无关、AI 友好的程序员知识管理体系。
> 整合 PARA(行动分类)+ Zettelkasten(原子写作)+ MOC(索引地图)+ Johnny.Decimal(编号定位)+ Karpathy 分层(素材/成品分离)。
> 本文件是体系的**唯一规则源**:人和 AI 都按此规则使用本库。

## 一、目录体系(编号即优先级)

```text
0-Note\
├── 00-索引\    索引入口层   里面装着根索引 `00-索引.md`(全库唯一入口一页:每个项目的名称 / 状态 / 知识数 / 入口)
├── 10-项目\    项目层   项目自足:计划、原料、知识、模板都在一个文件夹里(容器:`!名词解释\`、`!系统与工具\`)
├── 40-归档\    归档层   完成的项目、过时的知识(只进不出)
├── 50-资源\    资源层   收集的资料/工具/脚本/图片,暂不体系化
├── 90-模板\    模板层   全库统一的笔记骨架
└── README.md   本文件(总纲)
```

> **为什么根索引住在一个文件夹里:** `00-索引/00-索引.md` 是**刻意**做成目录的。Windows 资源管理器永远把文件夹排在文件之前,没有任何开关能把两者混排,所以顶层放一个 `00-索引.md` 文件,它必然被排到 `10-项目\`、`40-归档\`、`50-资源\`、`90-模板\` 之后;把入口做成以 `00-` 开头的文件夹,它在任何机器、任何默认视图里都排在最上面。**请不要把它“优化”回顶层单文件。**

配套仓外目录(可选,**当前未创建**;需要时自行建):

- `F:\0-Note-Data\` — 建议用它放 Anki 牌组、xlsx/csv、处理脚本等原始素材,按 `英语` 等同名对应;本仓库不依赖它

### 00~90 到底什么意思(编号即优先级,也是知识生命周期)

> 目录名里的**数字前缀**两层含义:①大数字 = 越接近仓库边缘(数字小=越核心、越常动);②每层代表知识在其生命周期中的一个**阶段**。**同一个主题的笔记,会随它在生命周期里的位置变化,在不同层之间移动。** 下面用本仓库里真实存在的文件举例(归档层目前为空,那一行给的是归档后的形状),这样你对号入座:

| 目录 | 含义 | 放什么 | 仓库里的**真实例子** |
|------|------|--------|--------------------|
| **00-索引** | 索引入口层 · 里面是根索引 `00-索引/00-索引.md` | 只放链接和路线:`10-项目/` 下每个目录一行(名称 / 状态 / 知识数 / 入口);正文在所属项目的 `20-知识\` | 根索引里 `## 项目清单` 那张表 |
| **10-项目** | 项目层 · 有目标+截止,项目自足 | 项目文件夹(`!项目说明.md`、`00-索引.md`,可选 `!实施计划.md` / `90-模板\`)+ 项目内的 `20-知识\`(**笔记的成品正文**,唯一存放处) | `10-项目/2026-12-掌握SQLite/00-索引.md` 与同项目的 `20-知识/SQLite介绍.md` |
| **40-归档** | 归档层 · 完结/过时沉底 | 完成的项目、过时知识(整包搬入,只进不出) | 目前为空(还没有项目满足四条判据);归档后形如 `40-归档/2026-10-掌握Markdown/`,它的笔记随整包走在 `20-知识/` 里 |
| **50-资源** | 资源层 · 暂存的原始资料 | 没提炼的资料、图片、脚本工具,暂不体系化 | `50-资源/图片/`、`50-资源/工具/`、`50-资源/英语/` |
| **90-模板** | 模板层 · 统一笔记骨架 | 写新笔记时复制的模板(不改动),以及教学共享样式(课件的 `lesson.css` / `quiz.js`) | `90-模板/20-笔记正文模板.md`(冒泡算法笔记就是从它复制改写的)、`90-模板/teach-assets/lesson.css`(所有课程的 `lessons/` 与 `reference/` 共用) |

**一句话记忆**(按知识流向,不按编号大小):`00 指路 → 10 立项 → 50 暂存原料 → 20 沉淀正文 → 40 封存 → 90 给格式`。

**编号只是层名,不是流程顺序**:知识按"原料 → 立项 → 成品 → 索引 → 封存"流动(见第二节「流动规则」),`50-资源` 编号靠后是因为它离核心最远(还没消化的原料),不代表优先级低。

**这一层默认不进远程仓库**:图片、外语素材等大件只留在本机(`.gitignore` 里用 `50-资源/*` 整体忽略、再开白名单),入版的只有巡检器等工具、记录类笔记、被索引页引用的讲解。所以新克隆的机器上 `50-资源/图片/`、`50-资源/英语/` 不存在,指向它们的链接只在本机有效。

### teach 产物落在哪一层(教学项目专用)

`10-项目/` 下的每个学习项目**同时是一个 `teach` 教学工作区**。它的产物各归其位;`00-索引.md` 的「课程」块负责把课程登记出来(巡检 A11 守):

| teach 产物 | 位置 | 属于哪层 / 为什么 |
|------|------|------|
| `MISSION.md` / `RESOURCES.md` / `NOTES.md` | 项目根 | **项目状态层**:为什么学 / 可信来源 / 教学偏好。技能协议文件名必须英文,整体豁免 A3 与 A5-A6 |
| `lessons/*.html` | 项目内 `lessons/` | **项目产物**:一节课一个文件,每节在 `00-索引.md` 的「课程」块登记一行 —— 否则课只躺在文件夹里,从目录页看不出来 |
| `reference/*.html` | 项目内 `reference/` | **项目产物**:速查卡,同样登记进「课程」块 |
| `reference/课程地图.html` | 同上 | **课程的「计划」入口**:每节标题 / 可验证的胜利 / 前置依赖 / 状态(相当于课程自己的 `00-索引.md`) |
| `learning-records/*.md`、`GLOSSARY.md` | 项目根下 | **项目产物**(按需创建):只在该主题被证实掌握后才写,不记过程流水账 |
| 共享 `lesson.css` + `quiz.js` | `90-模板/teach-assets/` | **格式层**:全库唯一一份(与 14 个 md 模板同层),课件相对引用它,不按项目复制 |

### 归档判据(四条机械条件,巡检器 A12 守)

一个项目要整包搬进 `40-归档/`,必须**四条同时成立**:

1. `!项目说明.md` 的 frontmatter 里 `status: done`
2. 「出口」或「验收」小节里没有未勾选项(`- [ ]`)
3. 正文含「复盘」小节
4. 「任务清单」小节里没有未勾选项

- **位置只是状态的镜像,判据永远看 `status` 与出口勾选**:四条判据不读文件夹路径。不许为了"整理得干净"而提前搬家
- **四条全满足只给提示**:巡检器在独立的 `[提示]` 小节打印 `可归档:<项目名>`,**不算 FAIL**;搬不搬仍由人决定
- **缺小节按"不满足"处理**:没有「出口/验收」或「任务清单」小节时无从验证收尾,就不出提示(误报比漏报贵)
- **反向检查是硬错误(A12)**:已经在 `40-归档/` 下的项目(带 `!项目说明.md` 的目录)必须在根 `00-索引/00-索引.md` 留有一行登记;归档物从索引里消失,就成了找不回来的死文件。留行的写法:「计划与进度」里那行勾成 `- [x]`,「项目清单」表里状态改成 `归档`

## 二、五条核心规则

### 1. 流动规则(PARA 灵魂)

信息有生命周期,按方向流动,**禁止只存不动**:

```text
新信息 → 50-资源(暂存) ──提炼──→ 10-项目/<项目>/20-知识(沉淀为知识)
         │                                         │
         └→ 10-项目(要用时立项) ───────────────────┴→ 40-归档(整包封存)
```

- 新收集的资料先扔 `50-资源`,**不要直接塞进项目的 `20-知识/`**
- 要系统学一个东西 → 在 `10-项目` 建项目文件夹(含目标+截止+任务清单)
- **10-项目 文件夹命名 = 时间粒度置顶 + 符号置顶 + 索引承载**:命名 `{时间粒度}-{名称}`,`!` 前缀置顶常驻项(每日一练,`!一天一道算法题`)。时间粒度=难度:入门用月(`2026-10-掌握Markdown`)、基础/部署用季度(`2026Q4-掌握Docker`)、进阶用年(`2027-掌握边缘函数原理`);字典序自动排成 月→季→年。`!`(ASCII 最小)替代数字序号实现置顶;组内精确学习顺序由根 `00-索引/00-索引.md` 的「学习路线」承载(如先 Docker 后握手协议、代理服务器最后)。
- 学完提炼出的知识 → 写进所属项目的 `20-知识/`;四条归档判据全满足的项目,整个文件夹移入 `40-归档`
- **每季度巡检一次**:`50-资源` 里超过 3 个月没动的,要么提炼进所属项目的 `20-知识/` 要么删

### 2. 写作规则(Zettelkasten 轻量版)

- 一篇笔记只讲一个主题(原子性)
- **必须用自己的话重写**——直接复制粘贴的资料没有价值,那是收藏不是学习
- 代码可以贴,但必须带"为什么这么写"的注释或说明
- 笔记之间用 `[[双链]]` 互连(如 `相关: [[冒泡算法]]`),Obsidian 里可点击,VS Code 里是纯文本不碍事

### 3. 检索规则(索引页)

- **不靠文件夹深挖找东西,靠索引页**
- 两级:根 `00-索引/00-索引.md` 一页列出全部项目;每个项目/容器的 `00-索引.md` 列出它的全部知识 + 推荐学习顺序 + 待补坑
- 笔记写完,在所属项目的 `00-索引.md` 加一行;新建项目时在根页加一行
- 链接双轨制:**正文互连用 `[[双链]]`**(Obsidian 里可点);**索引页 / README 用相对路径链接**(VS Code / GitHub 可点)。同名文件的双链必须带路径,如 `[[2026-掌握西班牙语B2/!项目说明|项目说明]]`
- 索引页的统计行(如 `> 本项目知识 12 篇 · 状态 learning · 覆盖 12/12(100%)`)必须落在文件前 8 行:巡检 A9 就在那里读它,并按实物核验它的篇数、覆盖与状态
- 两个容器(`!名词解释` / `!系统与工具`)**不是项目、永不归档**:根索引与容器自己的统计行里,人读状态一律写 **`常驻`**;容器没有 `!项目说明.md`(A9 不核它的状态),而 frontmatter 的 `status` 只能取四个机器值之一(A5 守),所以容器索引页的 frontmatter 保留 `done`、不要改写成 `常驻`

### 4. 元数据规则(frontmatter)

每篇笔记头部带 YAML 元数据,**不超过 8 个字段**:

```yaml
---
type: algorithm    # algorithm | project | system | language | tutorial | log | note | concept
tags: [排序, 数组]
status: learning   # todo | learning | done | review
date: 2026-08-26
difficulty: 2      # 1-5 自评(算法类用)
source: 力扣912
related: "[[冒泡算法]]"
review: 2026-09-26  # 下次复习日期(可选)
---
```

- `type` 另两个容易含混的取值:`note` = 项目内的每日/清单/索引类笔记(如西语每日笔记、词汇表);`concept` = 概念辨析/对比讲解(如 CLI-TUI-GUI、编辑器编译器IDE、测试夹具)
- 项目 `status` 判定口径(巡检器 A7 的依据):项目内除 `!项目说明.md` 与 `00-索引.md` 外还有任何 `.md`(含 `!实施计划.md`)→ `learning`;只有这两份 → `todo`
- **名词解释的判据**(2026-09-23 定,2026-09-25 改住址):跨领域、工具与工程类的**名词与概念辨析**统一放容器 `10-项目/!名词解释/20-知识/`(如「编辑器/编译器/IDE 的区别」「CLI/TUI/GUI」「Node.js/npm/pnpm」「测试夹具」);**属于某学科内部的概念留在该学科项目自己的 `20-知识/`**。文件夹内不放操作步骤,操作类内容进对应技术分类
- **教学工作区(teach,2026-09-24 起)**:`10-项目/` 下每个学习项目同时是一个 `teach` 教学工作区。状态层是 `MISSION.md`(为什么学)/ `RESOURCES.md`(可信资源)/ `NOTES.md`(教学偏好);产物是 `lessons/*.html`(一节课一个文件)、`reference/*.html`(速查卡)、`learning-records/*.md`(学习记录,按需创建)、`GLOSSARY.md`(术语表,只收已掌握的)。这些是**技能协议文件**,所以文件名保留英文(库规「目录名用中文」的例外),并豁免 A3 孤篇 / A5-A6 元数据 / A7 项目产出计数 —— 由巡检器 **A11** 单独守它们的完整性。共享样式表与测验组件全库只有一份:`90-模板/teach-assets/`(与 14 个 md 模板同层;lessons 相对引用,不按项目复制)。课程(课程地图 / 每节课 / 速查卡)必须在项目 `00-索引.md` 的「课程」块登记,否则 A11 报 —— 课在文件夹里躺着、目录页看不出来,等于没适配
- **知识类笔记必须住进项目/容器的 `20-知识/`**(巡检器 A10 强制,2026-09-23 定,2026-09-25 反转):`type` 为 `algorithm` / `language` / `system` / `concept` / `tutorial` 的成品正文必须落在 `10-项目/<项目或容器>/20-知识/`;项目根只允许 `project`(脚手架)、`note`(项目内每日/清单)、`log`(记录)。确实只服务于本项目的文档,把 `type` 改成 `note` 或 `log` 即可,不必搬家
- 巡检器跑法(A1~A14;退出码 0 = PASS):`cd 50-资源/工具/vault-check && PYTHONIOENCODING=utf-8 python -B check_vault.py`;要机器可读结果加 `--json`。两个提示通道(可归档项目、根索引尚未创建)各自打印 `[提示]` 小节,不计入 FAIL。旧 `--coverage` / `--moc-stats` 两个开关已在 2026-09-25 随那 5 张旧 MOC 文件一并删除(注意 `00-索引/` 这个目录名现在装的是根索引页) —— 看覆盖率读各项目 `00-索引.md` 顶部的统计行(A9 守着它与实物一致)

### 5. 分层规则(Karpathy)

- 本库(0-Note)只放**文本成品**:md 笔记
- 二进制素材(Anki/xlsx/图片大文件/脚本/docx/pdf)放仓外 `0-Note-Data\` 或 `50-资源\` 各素材子目录:`图片\`(图片)、`工具\`(脚本)、`英语\`(外语配套附件)。注意:`*.sh` / `*.docx` / `*.xlsx` / `*.pptx` / `*.pdf` 已被 `.gitignore` 忽略,这些文件只留在本机、**不入库**
- **`50-资源` 整体不入库**(2026-09-23 起):`.gitignore` 用 `50-资源/*` 忽略全部,只白名单保留 `工具/vault-check/`(巡检器)、`记录/`、`Zephyr/`、`工具/Markdown资料收集.md`。图片与外语素材只在本机、不进远程,也不进历史
- 知识"编译"一次:Raw 素材 → 提炼 → 成品笔记(住所属项目的 `20-知识/`),之后持续更新成品而非重读素材

## 三、笔记怎么写(四类骨架)

写新笔记时,从 `90-模板\` 复制对应骨架:

| 场景 | 模板 | 核心段落 |
|------|------|---------|
| 学/刷一道算法题 | `20-笔记正文模板.md` | 题意→直觉与试错→核心思路→代码→复杂度→同类题→复习记录 |
| 学一个开源项目/做项目 | `20-笔记正文模板.md` | 解决什么→架构→跑起来→核心机制→**决策与权衡**→我能复用什么→复盘 |
| 学一个系统/中间件 | `20-笔记正文模板.md` | 一句话本质→解决什么→核心概念→架构→**权衡取舍**→瓶颈→面试问法 |
| 学一门语言/技术 | `20-笔记正文模板.md` | 定位→环境速查→核心心智模型→语法差异表→坑与最佳实践→实战片段 |

> 想理解 **00~90 每层的模板 + 一个项目如何走完完整生命周期** → 看 [`90-模板/90-模板总览与生命周期.md`](<90-模板/90-模板总览与生命周期.md>),各层模板都放在 `90-模板\`(00-索引模板 / 10-项目立项模板 / 20-笔记正文模板 / 40-归档封存模板 / 50-资源暂存模板),每个都带一个「学习 Markdown(基于菜鸟教程)」的填充示例。

## 四、命名规范

- 笔记文件:`主题名.md`(中文可,简短可检索,如 `冒泡算法.md`、`docker.md`)
- 项目文件夹:`{时间粒度}-{名称}`(如 `2026-10-刷完Hot100/`);常驻项加 `!` 前缀置顶,如 `!一天一道算法题/`
- 索引页:根级一页 `00-索引/00-索引.md`(在 `00-索引\` 目录里,见第一节)+ 每个项目/容器一页(如 `10-项目/!一天一道算法题/00-索引.md`)
- 自然语言(英语/西语)各有自己的学习项目;**编程/标记语言**(Python/Markdown…)的笔记留在产生它的技术项目里(不再有全局语言 MOC)
- 不用日期前缀命名知识笔记(检索靠索引页和 tags,不靠时间)

## 五、记录与笔记的区分

本库正文只放两类东西,写入前先分清:**笔记**是提炼的知识(原理/方法/权衡),**记录**是事件流水(某天发生了什么、怎么处理、要留意什么)。

| 类别 | 定义 | 文件名 | 归属 | frontmatter type |
|---|---|---|---|---|
| **笔记** | 提炼后的知识:原理/方法/权衡取舍 | `主题.md`,无日期前缀 | 所属项目的 `20-知识/` | `algorithm` / `system` / `language` / `tutorial` / `note` / `concept` |
| **记录** | 事件流水/日志/提醒:发生了什么 + 处理 + 留意点 | `记录-事件名.md` | `50-资源/记录/` | `log` |

- 事件里若沉淀出可复用方法 → 方法提炼成笔记进所属项目的 `20-知识/`,记录里留 `related` 链接指向它
- 记录归资源层:随季度清理规则处置(3 个月无引用即归档/删除),不占项目的 `20-知识/`

## 六、AI 协作规则(给 AI 助手看)

- 本库结构见本文件;新笔记按 `90-模板` 骨架生成,带 frontmatter
- 帮我写笔记时:提炼进所属项目的 `20-知识/`;素材性内容进 `50-资源`
- 每次大改动后更新所属项目的 `00-索引.md`;项目增删、改名、归档时同步根 `00-索引/00-索引.md`
- 遵守流动规则:不要把资料原样堆进项目的 `20-知识/`
- 只有四条归档判据全满足才把项目移入 `40-归档/`;不许为了"整理干净"提前搬

## 七、一个完整实例:一篇笔记如何在系统里流动

> 以本仓库已有的 **《冒泡算法》**(`10-项目/!一天一道算法题/20-知识/冒泡算法.md`)为线索,看它怎么生、怎么被索引、怎么用、最后怎么封存。**左边 0x 目录 = 它当前所处的阶段,右边路径 = 它实际存在的位置。**

### 第 0 步:你有个灵感 / 收集到一份原料 → 50-资源

- 你看到一段 C 语言冒泡代码、一份别人写的题解 PDF、或一个排序动画 → 这是**原始素材**,先扔 `50-资源/`(可加 `图片/` 存图、`工具/` 存脚本)。
- 这一步只"收藏",**不整理内容**——收藏不等于学习,后面必须提炼。

### 第 1 步:决定真正学它 → 拿模板建正文,写进项目自己的 20-知识

- 从 `90-模板/20-笔记正文模板.md` **复制一份,改名**为 `10-项目/!一天一道算法题/20-知识/冒泡算法.md`(模板本身在 90 层,永远不改,只复制)。
- 按模板骨架填:**题意(用自己的话)→ 直觉与试错 → 核心思路 → 代码 → 复杂度 → 同类题**。
- 头部写 frontmatter(≤8 字段)。本仓库里这份的真实 frontmatter 长这样:

  ```yaml
  ---
  type: algorithm
  tags: [排序, 数组, 交换排序]
  status: done
  date: 2026-08-26
  difficulty: 1
  source: 经典入门
  related: "[[快速排序]]"
  review: 2026-09-26
  ---
  ```

- 正文只放**成品**:用自己的话重写 + 带"为什么这么写"的注释。写完,原来的原始素材(第 0 步那份)要么删、要么扔回 `50-资源/`。

### 第 2 步:在本项目 00-索引.md 登记入口(否则这篇笔记"不可见")

- 打开 `10-项目/!一天一道算法题/00-索引.md`,在"知识产出"下加一行链接:`- [冒泡算法](<20-知识/冒泡算法.md>) — 交换排序入门 | 重点 | done`。
- **规则:正文放项目自己的 `20-知识/`,索引只放一行链接。** 以后你想找所有排序题,不用翻文件夹,直接看这张地图。

### 第 3 步:要系统学(带目标+截止)→ 建 10-项目 立项

- 如果这不是零散记一笔,而是"我要开始系统刷算法" → 建 `10-项目/2026-10-刷完Hot100/`,里面写:目标(刷完 Hot100)、截止日期、任务清单。(命名见上方规则:时间粒度置顶)
- 清单里把《冒泡算法》作为第一题,**在笔记里用 `related: [[..]]` 双向链接**、在项目文件夹里链接回这篇笔记。这样项目与笔记互相钩住。
- 顺带在根 `00-索引/00-索引.md` 加一行,让新项目进全库入口。

### 第 4 步:四条归档判据全满足 → 整包移入 40-归档 封存

- 一个项目刷完、`status` 已 `done`、「验收」与「任务清单」全勾、正文有「复盘」→ 巡检器提示 `可归档:<项目名>`,把整个 `10-项目/2026-10-刷完Hot100/` 移入 `40-归档/`。**只进不出**,即使以后不用也不轻易删,留作历史。
- 单篇知识过时(比如某个库被淘汰),它是随项目走的:项目归档时笔记跟着进 `40-归档/…/20-知识/`;若这篇只服务一个项目却还没到归档时候,把 `type` 改成 `note` / `log` 留在项目根,不单独搬走。
- 归档后**仍要在根 `00-索引/00-索引.md` 留一行登记**——这是 A12 的反向检查,索引里消失的归档物等于死文件。

### 全程回顾(一眼看懂数字的含义)

```text
灵感/素材 → 50-资源(暂存) ────────┐
                                  ├─→ 10-项目/<项目>/20-知识(沉淀成品) ──→ 40-归档(封存) ← 学完移动
模板 90-模板 ◄─复制─ 写正文 ──────┤                     ▲
                                  └─→ 00-索引\00-索引.md(根索引)+ <项目>\00-索引.md(项目索引页)
```

`00` 索引、`10` 立项、`20` 正文、`40` 封存、`50` 原料、`90` 模板——**同一份知识,随着它"越学越透",在 50→20→40 之间(原料 → 正文 → 沉底)前进/沉底;00 永远指着它在哪,90 永远教你写**。
