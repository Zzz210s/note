# 0-Note · 程序员知识库总纲

**[English](./README.md) | 简体中文**

> 一套纯 Markdown、工具无关、AI 友好的程序员知识管理体系。
> 整合 PARA(行动分类)+ Zettelkasten(原子写作)+ MOC(索引地图)+ Johnny.Decimal(编号定位)+ Karpathy 分层(素材/成品分离)。
> 本文件是体系的**唯一规则源**:人和 AI 都按此规则使用本库。

## 一、目录体系(编号即优先级)

```text
0-Note\
├── 00-索引\   索引层   每个专题一张"地图",笔记的入口(不放内容,只放链接)
├── 10-项目\   项目层   有明确目标和截止的学习(如"14天刷完Hot100")
├── 20-领域\   领域层   长期维护的知识田(01-算法/02-编程语言/03-开发工具/04-系统与部署/05-网络与服务器/06-网页开发/07-外语/09-AI智能体)
├── 40-归档\   归档层   完成的项目、过时的知识(只进不出)
├── 50-资源\   资源层   收集的资料/工具/脚本/图片,暂不体系化
├── 90-模板\   模板层   统一笔记骨架(算法/项目/系统/语言)
└── README.md  本文件(总纲)
```

配套仓外目录(可选,**当前未创建**;需要时自行建):

- `F:\0-Note-Data\` — 建议用它放 Anki 牌组、xlsx/csv、处理脚本等原始素材,按 `英语` 等同名对应;本仓库不依赖它

### 00~90 到底什么意思(编号即优先级,也是知识生命周期)

> 目录名里的**数字前缀**两层含义:①大数字 = 越接近仓库边缘(数字小=越核心、越常动);②每层代表知识在其生命周期中的一个**阶段**。**同一个主题的笔记,会随它在生命周期里的位置变化,在不同层之间移动。** 下面用本仓库里真实存在的文件举例,这样你对号入座:

| 目录 | 含义 | 放什么 | 仓库里的**真实例子** |
|------|------|--------|--------------------|
| **00-索引** | 索引层 · 每个专题一张"地图" | 只放链接和路线,不放正文(正文在 20-领域) | `00-索引/算法.md` 里一行 `- [[冒泡算法]] — 交换排序入门 \| 重点 \| done` 就是指向正文的"入口" |
| **10-项目** | 项目层 · 有目标+截止的学习/刷题项目 | 项目文件夹(目标、截止日期、任务清单) | `10-项目/2026-12-掌握SQLite/`(含 `!项目说明.md`:定位/目标/状态/任务清单) |
| **20-领域** | 领域层 · 长期维护的知识田 | **笔记的成品正文**(正文唯一存放处) | `20-领域/01-算法/冒泡算法.md` 整篇笔记 |
| **40-归档** | 归档层 · 完结/过时沉底 | 完成的项目、过时知识(只进不出) | `40-归档/CSDN文章/`;学完的 `10-项目/` 文件夹整体移入 |
| **50-资源** | 资源层 · 暂存的原始资料 | 没提炼的资料、图片、脚本工具,暂不体系化 | `50-资源/图片/`、`50-资源/工具/`、`50-资源/英语/` |
| **90-模板** | 模板层 · 统一笔记骨架 | 写新笔记时复制的模板(不改动) | `90-模板/20-笔记正文模板.md`(冒泡算法笔记就是从它复制改写的) |

**一句话记忆**(按知识流向,不按编号大小):`00 指路 → 10 立项 → 50 暂存原料 → 20 沉淀正文 → 40 封存 → 90 给格式`。

**为什么 50 在 20 后面?** 50-资源 是“还没提炼的原料”,20-领域 是“提炼后的成品”——原料放在编号最靠后的资源层(50,仅次于模板层 90),提炼成知识后向核心(20)**前进**,符合 PAR 的流动方向;编号大只表示“还没消化/偏边缘”,不代表优先级高。

**这一层默认不进远程仓库**:图片、外语素材等大件只留在本机(`.gitignore` 里用 `50-资源/*` 整体忽略、再开白名单),入版的只有巡检器等工具、记录类笔记、被 MOC 引用的讲解。所以新克隆的机器上 `50-资源/图片/`、`50-资源/英语/` 不存在,指向它们的链接只在本机有效。

## 二、五条核心规则

### 1. 流动规则(PARA 灵魂)

信息有生命周期,按方向流动,**禁止只存不动**:

```text
新信息 → 50-资源(暂存) ──提炼──→ 20-领域(沉淀为知识)
                │                          │
                └→ 10-项目(要用时升级) ─┘→ 40-归档(完结/过时沉底)
```

- 新收集的资料先扔 `50-资源`,**不要直接塞 Areas**
- 要系统学一个东西 → 在 `10-项目` 建项目文件夹(含目标+截止+任务清单)
- **10-项目 文件夹命名 = 时间粒度置顶 + 符号置顶 + 索引承载**:命名 `{时间粒度}-{名称}`,`!` 前缀置顶常驻项(每日一练,`!一天一道算法题`)。时间粒度=难度:入门用月(`2026-10-掌握Markdown`)、基础/部署用季度(`2026Q4-掌握Docker`)、进阶用年(`2027-掌握边缘函数原理`);字典序自动排成 月→季→年。`!`(ASCII 最小)替代数字序号实现置顶;组内精确学习顺序由 00-索引「学习路线」索引承载(如先 Docker 后握手协议、代理服务器最后)。
- 学完提炼出的知识 → 写进 `20-领域`;项目完结整个文件夹移入 `40-归档`
- **每季度巡检一次**:Resources 里超过 3 个月没动的,要么提炼进 Areas 要么删

### 2. 写作规则(Zettelkasten 轻量版)

- 一篇笔记只讲一个主题(原子性)
- **必须用自己的话重写**——直接复制粘贴的资料没有价值,那是收藏不是学习
- 代码可以贴,但必须带"为什么这么写"的注释或说明
- 笔记之间用 `[[双链]]` 互连(如 `相关: [[冒泡算法]]`),Obsidian 里可点击,VS Code 里是纯文本不碍事

### 3. 检索规则(MOC)

- **不靠文件夹深挖找东西,靠 MOC 地图**
- 每个专题一张 MOC(如 `00-索引\算法.md`):列出该专题所有笔记 + 推荐学习顺序 + 待补坑
- 笔记写完,记得在对应 MOC 里加一行链接
- 链接双轨制:**正文互连用 `[[双链]]`**(Obsidian 里可点);**MOC / 索引 / README 用相对路径链接**(VS Code / GitHub 可点)。同名文件的双链必须带路径,如 `[[2026-掌握西班牙语B2/!项目说明|项目说明]]`
- MOC 头部统计行(如 `> 条目 49 · 覆盖 ...`)行尾保留 **2 个空格**:那是硬换行,用来把统计行与下方引言块分开;勿被格式化工具删掉

### 4. 元数据规则(frontmatter)

每篇笔记头部带 YAML 元数据,**不超过 8 个字段**:

```yaml
---
type: algorithm    # algorithm | project | system | language | tutorial | log | note | concept
tags: [排序, 数组]
status: learning   # todo | learning | done | review
date: 2026-08-26
difficulty: 2      # 1-5 自评(算法类用)
source: 力扣912
related: "[[冒泡算法]]"
review: 2026-09-26  # 下次复习日期(可选)
---
```

- `type` 另两个容易含混的取值:`note` = 项目内的每日/清单/索引类笔记(如西语每日笔记、词汇表);`concept` = 概念辨析/对比讲解(如 CLI-TUI-GUI、编辑器编译器IDE、测试夹具)
- 项目 `status` 判定口径(巡检器 A7 的依据):项目内除 `!项目说明.md` 外还有任何 `.md`(含 `!实施计划.md`)→ `learning`;只有 `!项目说明.md` → `todo`
- 巡检器跑法(A1~A9;退出码 0 = PASS):`cd 50-资源/工具/vault-check && PYTHONIOENCODING=utf-8 python -B check_vault.py`;看覆盖率用 `--coverage`,看各 MOC 条目数用 `--moc-stats`

### 5. 分层规则(Karpathy)

- 本库(0-Note)只放**文本成品**:md 笔记
- 二进制素材(Anki/xlsx/图片大文件/脚本/docx/pdf)放仓外 `0-Note-Data\` 或 `50-资源\` 各素材子目录:`图片\`(图片)、`工具\`(脚本)、`英语\`(外语配套附件,与 20-领域 同名对应)。注意:`*.sh` / `*.docx` / `*.xlsx` / `*.pptx` / `*.pdf` 已被 `.gitignore` 忽略,这些文件只留在本机、**不入库**
- **`50-资源` 整体不入库**(2026-09-23 起):`.gitignore` 用 `50-资源/*` 忽略全部,只白名单保留 `工具/vault-check/`(巡检器)、`记录/`、`Zephyr/`、`工具/Markdown资料收集.md`。图片与外语素材只在本机、不进远程,也不进历史
- 知识"编译"一次:Raw 素材 → 提炼 → Areas 成品,之后持续更新成品而非重读素材

## 三、笔记怎么写(四类骨架)

写新笔记时,从 `90-模板\` 复制对应骨架:

| 场景 | 模板 | 核心段落 |
|------|------|---------|
| 学/刷一道算法题 | `20-笔记正文模板.md` | 题意→直觉与试错→核心思路→代码→复杂度→同类题→复习记录 |
| 学一个开源项目/做项目 | `20-笔记正文模板.md` | 解决什么→架构→跑起来→核心机制→**决策与权衡**→我能复用什么→复盘 |
| 学一个系统/中间件 | `20-笔记正文模板.md` | 一句话本质→解决什么→核心概念→架构→**权衡取舍**→瓶颈→面试问法 |
| 学一门语言/技术 | `20-笔记正文模板.md` | 定位→环境速查→核心心智模型→语法差异表→坑与最佳实践→实战片段 |

> 想理解 **00~90 每层的模板 + 一个项目如何走完完整生命周期** → 看 [`90-模板/90-模板总览与生命周期.md`](<90-模板/90-模板总览与生命周期.md>),各层模板都放在 `90-模板\`(00-索引模板 / 10-项目立项模板 / 20-笔记正文模板 / 40-归档封存模板 / 50-资源暂存模板),每个都带一个「学习 Markdown(基于菜鸟教程)」的填充示例。

## 四、命名规范

- 笔记文件:`主题名.md`(中文可,简短可检索,如 `冒泡算法.md`、`docker.md`)
- 项目文件夹:`{时间粒度}-{名称}`(如 `2026-10-刷完Hot100/`);常驻项加 `!` 前缀置顶,如 `!一天一道算法题/`
- MOC 文件:`专题名.md`(如 `算法.md`、`系统.md`、`外语.md`、`编程语言.md` 等)
- 语言类拆两个 MOC:自然(人类)语言(英语/西语)归 `外语.md`;**编程/标记语言**(Python/Markdown…)归 `编程语言.md`
- 不用日期前缀命名知识笔记(检索靠 MOC 和 tags,不靠时间)

## 五、记录与笔记的区分

本库正文只放两类东西,写入前先分清:**笔记**是提炼的知识(原理/方法/权衡),**记录**是事件流水(某天发生了什么、怎么处理、要留意什么)。

| 类别 | 定义 | 文件名 | 归属 | frontmatter type |
|---|---|---|---|---|
| **笔记** | 提炼后的知识:原理/方法/权衡取舍 | `主题.md`,无日期前缀 | `20-领域` 对应分类 | `algorithm` / `system` / `language` / `tutorial` / `note` / `concept` |
| **记录** | 事件流水/日志/提醒:发生了什么 + 处理 + 留意点 | `记录-事件名.md` | `50-资源/记录/` | `log` |

- 事件里若沉淀出可复用方法 → 方法提炼成笔记进 20-领域,记录里留 `related` 链接指向它
- 记录归资源层:随季度清理规则处置(3 个月无引用即归档/删除),不占领域层

## 六、AI 协作规则(给 AI 助手看)

- 本库结构见本文件;新笔记按 `90-模板` 骨架生成,带 frontmatter
- 帮我写笔记时:提炼进 `20-领域` 对应分类;素材性内容进 `50-资源`
- 每次大改动后更新相关 MOC 的链接列表
- 遵守流动规则:不要把资料原样堆进 Areas

## 七、一个完整实例:一篇笔记如何在系统里流动

> 以本仓库已有的 **《冒泡算法》**(`20-领域/01-算法/冒泡算法.md`)为线索,看它怎么生、怎么被索引、怎么用、最后怎么封存。**左边 0x 目录 = 它当前所处的阶段,右边路径 = 它实际存在的位置。**

### 第 0 步:你有个灵感 / 收集到一份原料 → 50-资源

- 你看到一段 C 语言冒泡代码、一份别人写的题解 PDF、或一个排序动画 → 这是**原始素材**,先扔 `50-资源/`(可加 `图片/` 存图、`工具/` 存脚本)。
- 这一步只"收藏",**不整理内容**——收藏不等于学习,后面必须提炼。

### 第 1 步:决定真正学它 → 拿模板建正文,写进 20-领域

- 从 `90-模板/20-笔记正文模板.md` **复制一份,改名**为 `20-领域/01-算法/冒泡算法.md`(模板本身在 90 层,永远不改,只复制)。
- 按模板骨架填:**题意(用自己的话)→ 直觉与试错 → 核心思路 → 代码 → 复杂度 → 同类题**。
- 头部写 frontmatter(≤8 字段)。本仓库里这份的真实 frontmatter 长这样:

  ```yaml
  ---
  type: algorithm
  tags: [排序, 数组, 交换排序]
  status: done
  date: 2026-08-26
  difficulty: 1
  source: 经典入门
  related: "[[快速排序]]"
  review: 2026-09-26
  ---
  ```

- 正文只放**成品**:用自己的话重写 + 带"为什么这么写"的注释。写完,原来的原始素材(第 0 步那份)要么删、要么扔回 `50-资源/`。

### 第 2 步:在 00-索引 登记入口(否则这篇笔记"不可见")

- 打开 `00-索引/算法.md`,在"笔记索引"下加一行链接:`- [[冒泡算法]] — 交换排序入门 | 重点 | done`。
- **规则:正文放 20-领域,MOC 只放一行链接。** 以后你想找所有排序题,不用翻文件夹,直接看 `00-索引/算法.md` 这张地图。

### 第 3 步:要系统学(带目标+截止)→ 建 10-项目 立项

- 如果这不是零散记一笔,而是"我要开始系统刷算法" → 建 `10-项目/2026-10-刷完Hot100/`,里面写:目标(刷完 Hot100)、截止日期、任务清单。(命名见上方规则:时间粒度置顶)
- 清单里把《冒泡算法》作为第一题,**在笔记里用 `related: [[..]]` 双向链接**、在项目文件夹里链接回这篇笔记。这样"项目层"和"领域层"互相钩住。

### 第 4 步:学完/项目完结 → 移入 40-归档 封存

- 一个项目刷完、目录过时 → 整个 `10-项目/2026-10-刷完Hot100/` 移入 `40-归档/`。**只进不出**,即使以后不用也不轻易删,留作历史。
- 如果只是单篇知识过时(比如某个库被淘汰),把对应笔记移到 `40-归档/`,并在 MOC 里把它标成过时或去掉链接。

### 全程回顾(一眼看懂数字的含义)

```text
灵感/素材 → 50-资源(暂存)────┐
                                  ├─→ 20-领域(沉淀成品) ──→ 40-归档(封存)
模板 90-模板 ◄─复制─ 写正文 ──┤      ▲                      │
                                  └─→ 00-索引(索引入口)          └← 学完移动
```

`00` 索引、`10` 立项、`20` 正文、`40` 封存、`50` 原料、`90` 模板——**同一份知识,随着它"越学越透",在 50→20→40 之间(原料 → 正文 → 沉底)前进/沉底;00 永远指着它在哪,90 永远教你写**。
