
# [Windows] docs | 开机软件 0 延后启动设置

> 通过在注册表 `Explorer` 下新建 `Serialize` 项、把两个 DWORD 值设为 `0`,禁用 Windows 11 引入的"动态延迟启动"机制,让所有开机自启动软件在登录后立即加载,告别开机后干等 1~2 分钟才看到托盘程序出现的尴尬。
> [Microsoft Learn 问答 · win11 25H2 启动项启动很慢](https://learn.microsoft.com/zh-cn/answers/questions/5602231/win11-25h2)

@[toc]

## 背景

### 开机后软件"迟到"

开机登录后,自启动常驻程序迟迟不出现,干等 1~2 分钟才一个个冒出来,而这期间桌面壁纸还是默认的、任务栏还是没透明的。点开"启动"设置一看,这些程序明明都是"已启用"状态,可就是慢半拍。

### Windows 11 的动态延迟启动

自 Windows 11 **23H2** 版本起(24H2、25H2 同样存在),微软引入了一套**动态延迟启动机制**:系统在用户登录后,会优先把资源让给 Explorer(桌面 / 任务栏)进程,确保"桌面先亮起来"的观感;至于其他自启动软件,则被刻意"压一压",等到系统相对空闲时再分批加载。于是出现了上面"桌面出来了、软件没出来"的割裂体验。

> 本文的方案不是"加速开机",而是**关掉系统强加给启动项的延迟**。

## 核心概念

### 什么是"启动延迟"?

启动延迟不是软件本身的慢,而是**系统层面的"排队机制"**:登录后,系统不立刻把启动项一股脑全拉起来,而是先稳住 Explorer,再按自己的节奏逐步放行其他自启动程序。这个"逐步放行"的节奏,由注册表里两个键值控制。

### 两个关键注册表值

要关掉这个延迟,只需要在注册表里新建一个 `Serialize` 项,并在其下设置两个 **DWORD(32 位)** 值:

| 值名称 | 类型 | 作用 | 设为 0 的含义 |
| :--- | :--- | :--- | :--- |
| `WaitForIdleState` | DWORD(32 位) | 是否等待系统进入"空闲状态"再放行启动项 | **0 = 跳过等待**,登录后立即放行,不等系统空闲 |
| `StartupDelayInMSec` | DWORD(32 位) | 启动项的延迟时间(毫秒) | **0 = 延迟为 0**,启动项不再被"压"住 |

这两个值一唱一和:`WaitForIdleState` 管的是"要不要等",`StartupDelayInMSec` 管的是"等多久"。两个都设成 `0`,等于既不等、也不延迟——启动项在登录瞬间就开跑。

## 手动改注册表

### 第 1 步:打开注册表编辑器

按 `Win + R` 调出运行窗口,输入 `regedit`,回车。弹出用户账户控制(UAC)提示时点"是"。

### 第 2 步:导航到目标路径

在注册表编辑器左侧树状目录里依次展开,或直接把下面这行粘贴到顶部地址栏回车:

```text
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Explorer
```

### 第 3 步:新建 Serialize 项

在左侧选中 `Explorer` 项,然后:

- 右键 `Explorer` -> `新建` -> `项`
- 把新建的项重命名为 `Serialize`

> 注意:是**右键 Explorer 新建子项**,不是在 Explorer 里新建值。`Serialize` 必须作为 `Explorer` 的**子项**存在,两个 DWORD 值要建在 `Serialize` 里面,而不是直接建在 `Explorer` 里。位置建错 = 无效。

### 第 4 步:在 Serialize 下新建两个 DWORD 值

选中刚建好的 `Serialize` 项,在右侧空白处:

- 右键 -> `新建` -> `DWORD(32 位)值`
- 命名为 `WaitForIdleState`,双击它,把"数值数据"改为 `0`,确定
- 再重复一次,新建 `DWORD(32 位)值`,命名为 `StartupDelayInMSec`,数值数据同样改 `0`

两个值的最终状态应该长这样:

```text
Explorer
└── Serialize
    ├── WaitForIdleState      = 0x00000000 (0)
    └── StartupDelayInMSec    = 0x00000000 (0)
```

### 第 5 步:重启生效

注册表修改即时写入,但启动延迟机制只在**登录时**触发,所以必须**重启电脑**(或注销再登录)才能看到效果。重启后留意任务栏右下角,你会发现那些常驻软件几乎是跟着桌面一起冒出来的。
## 这个方案不适合谁?

**配置低的电脑不推荐**
## 注意

这个注册表方案改的是**全局**延迟策略,作用于**所有**走注册表启动项通道的程序,无法单独针对某一个软件做"延迟 / 不延迟"的差异化设置。
